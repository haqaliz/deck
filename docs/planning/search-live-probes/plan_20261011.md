## Phase 1 — Harness + auth gate (P0)

**Goal:** obtain the app's *exact* request strings from its own builders, and
prove both tokens authenticate, before measuring anything.

**Files touched:** `docs/planning/search-live-probes/probe.md` (created);
a **temporary** `native/SharedTests/ProbeBuilderDumpTests.swift` (never
committed).

**Steps:**
1. Create `probe.md` with a header (date, tokens by account id only — never the
   secret), an "auth gate" section, and empty A/B/C sections.
2. Add `ProbeBuilderDumpTests.swift` that `print`s, each on one line with a
   stable prefix (`PROBE-URL`, `PROBE-BODY`):
   - `WiqlClause.query(for: "[System.Title] CONTAINS 'login' OR [System.Tags] CONTAINS 'login'")`
   - `WiqlResponse.url(target: AzureTarget.normalise(organization: "ForesightAnalytics", project: "ForesightManifold"), top: 26)` (adjust to the real `normalise` signature)
   - `HostAzureDevOpsLoader.batchFields` joined, and the `workitemsbatch` URL
   - `GitHubPRSearch.query(tokens: ["login"], scope: "")` and `.url(query:perPage: 25)`
   - `AzurePRSearch.listURL(target:)` and `.byIDURL(target:id: 1)`
3. `xcodegen generate --spec native/project.yml` (a new test file is silently
   not compiled otherwise — CLAUDE.md).
4. `xcodebuild test -scheme DeckSharedTests -derivedDataPath native/build.noindex CODE_SIGNING_ALLOWED=NO -only-testing:DeckSharedTests/ProbeBuilderDumpTests 2>&1 | rg PROBE-`
   → paste the `PROBE-` lines into `probe.md`.
5. Auth gate with the keychain tokens (`security find-generic-password -s
   com.deck.app -a account.<id>.token -w` into a shell var):
   - `curl -s -o /dev/null -w '%{http_code}' -H "Authorization: Bearer $GH" https://api.github.com/user`
   - `curl -s -o /dev/null -w '%{http_code}' -H "Authorization: Basic $(printf ':%s' "$PAT" | base64)" 'https://dev.azure.com/ForesightAnalytics/_apis/connectionData?api-version=7.1-preview'`
6. Delete `ProbeBuilderDumpTests.swift`; `xcodegen generate` again.

**Verification:** both auth calls answer `200`; every `PROBE-` line present in
`probe.md` matches what §3 of the PRD names. If either auth call is not 200,
**stop** — a dead token is not a code contradiction (PRD §3 P0).

**Dependencies:** none.

## Phase 2 — Work-item probes (A1–A9)

**Goal:** replace every guess in `TaskSearch.condition` with a measurement.

**Files touched:** `probe.md` only.

**Steps** (each uses Phase 1's `PROBE-` output verbatim, `Authorization: Basic
…`, 10s timeout):
1. A1 — `CONTAINS 'login'`: sample a real project; record whether a partial word
   (`relogin`) and case variants match; log a title that does and one that does
   not.
2. A2 — `[System.Tags] CONTAINS`: find an item with a tag (`$top` batch already
   returns `System.Tags`); test whole-tag vs partial-tag (`tag` inside
   `mytag`) vs delimiter substring.
3. A3 — `[System.Id] = <a real id from A1>`: returns that item.
4. A4 — same query with no state filter: confirm a Closed/Done item returns.
5. A5 — a broad term (e.g. `a`): `%{time_total}` and `%{size_download}` at
   `$top=26`; recorded as indicative, not a benchmark (PRD §12).
6. A6 — text containing `'`, `)`, `[`, `]`, `%`: send the quote-doubled literal
   the builder produces; record status. Then send one deliberately *un*doubled
   value to confirm the 400 shape (must not be committed as a code path).
7. A7 — for each of the five categories, run
   `… AND [System.WorkItemType] IN GROUP 'Microsoft.XCategory'`; record status.
   Then one bogus category to capture the 400 `message`.
8. A8 — run per project (`ForesightManifold`, `MachineLearning`), count requests
   (expect N+1), confirm each returned row's `System.TeamProject` matches the
   project queried.
9. A9 — the bare-number path: `[System.Id] = N` + batch; record the produced
   work-item URL and `curl -o /dev/null -w '%{http_code}'` it (expect 200).

**Verification:** `probe.md` A-section has, per row, the request, the status,
and the observed behaviour. No claim is written that a raw response does not
show.

**Dependencies:** Phase 1.

## Phase 3 — Pull-request probes (B1–B5, C1–C4)

**Goal:** measure both PR providers, GitHub caveat included.

**Files touched:** `probe.md` only.

**Steps:**
1. B1 — `GitHubPRSearch.query(tokens:["login"], scope:"")` verbatim; record
   `total_count`, `items` length, and *whether this fine-grained token returns
   anything*. Then repeat with a query inside the token's two repos
   (`repo:haqaliz/deck is:pr`) to separate "token sees nothing" from "query
   wrong".
2. B2 — a two-word query (`fix flaky`): confirm both words must appear and order
   does not matter, from the titles returned.
3. B3 — pick a real PR number older than the first page of the recent query;
   run the number path (`is:pr <scope>` + `sort=updated&per_page=100`) and record
   whether the pool contains it.
4. B4 — confirm `is:pr` drops issues (an issue of the same title absent).
5. B5 — count requests one search makes (words + optional number) against the
   30/min budget.
6. C1 — `byIDURL` for (a) a real id in a configured project, (b) a
   well-formed unknown id (expect 404). Record `restrict` behaviour for an id in
   a non-configured project.
7. C2 — `listURL` per project: record a row's `repository.project.name`,
   `status`, and that `parseList` yields the shown number; map completed/abandoned.
8. C3 — whether the 100-of-all-status pool contains an item findable by a rare
   token; note the pool's usefulness (PRD §5 C3).
9. C4 — `curl -o /dev/null -w '%{http_code}'` the built `…/_git/{repo}/pullrequest/{id}`.
10. If both the words and the number path are empty-on-this-token (expected per
    PRD §10), record the exact query + `total_count: 0` and mark B/GitHub
    **token-limited**, not verified.

**Verification:** `probe.md` B/C sections complete; the GitHub token limitation,
if hit, is stated with evidence rather than glossed.

**Dependencies:** Phase 1; C1 may reuse an id from Phase 2 A8.
