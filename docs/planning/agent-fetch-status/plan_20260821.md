## Phase 1 — Status core in Shared (TDD)

**Goal:** a pure, tested vocabulary for "why did the last fetch fail", plus the
store, with no caller wired up yet.

**Files**
- `native/Shared/FetchStatus.swift` (new)
- `native/SharedTests/FetchStatusTests.swift` (new)

**Steps**

1. **RED** — `FetchOutcome` classification of `HostGitHubLoader.GitHubError`:
   `invalidRepo` → `authOrTarget`; `serverError(401|403|404)` → `authOrTarget`;
   `serverError(429|500|502|503)` → `unreachable`; `serverError(418)` →
   `badResponse`; `transport` → `unreachable`; `invalidPayload` → `badResponse`.
2. **RED** — same for `HostWeatherLoader.WeatherError` (`invalidLocation` →
   `authOrTarget`) and `RemoteOpenCodeLoader.RemoteError` (`invalidURL` →
   `authOrTarget`, `unauthorized` → `authOrTarget`).
3. **RED** — copy table (PRD §2.3): `FetchStatusCopy.line(source:outcome:)`
   returns the expected string for every source × outcome; `ok` returns `nil`;
   `weather` + `notConfigured` returns `nil` (empty location is valid).
4. **RED** — chip resolution `FetchChip.text(source:status:dataWrittenAt:now:)`,
   the single place the face logic lives:
   - failed status, recent attempt → the §2.3 line;
   - `ok` status → `nil`;
   - newest of (`dataWrittenAt`, `status.attemptedAt`) older than 30 min →
     `"Agent hasn't run"` (PRD §2.4 dead-agent rule), including the
     no-status-at-all and no-data-at-all cases;
   - boundary: exactly 30 min → not yet dead (`>`, not `>=`).
5. **RED** — `FetchStatus` Codable round-trip; an unrecognised outcome raw value
   decodes to `.ok`; `FetchStatusStore.load(from:)` returns `nil` for a missing
   file and for a corrupt file; `save(_:to:)` → `load(from:)` round-trips
   (temp-dir URL injection, mirroring `ProcessSnapshotStoreTests.swift:31-33`).
6. **GREEN** — implement `FetchStatus.swift`: `FetchSource` (`shipbox`,
   `weather`, `opencodeRemote`), `FetchOutcome` (`ok`, `notConfigured`,
   `authOrTarget`, `unreachable`, `badResponse`), `FetchStatus`
   (source + outcome + attemptedAt), `FetchStatusStore` with
   `fileURL(for:)` = `fetch-{source}.json` in `DeckSettings.containerDirectory`
   and `save(_:to:)` / `load(from:)` defaulting to it, writing via `AtomicFile`.
7. `xcodegen generate --spec native/project.yml` — **required**: sources are
   enumerated at generation time, so a new test file is otherwise silently not
   compiled and the suite still reports success (CLAUDE.md).

**Verification**
`xcodebuild test -project native/Deck.xcodeproj -scheme DeckSharedTests` — new
tests fail before step 6, all green after. No other target touched.

**Dependencies** — none.

## Phase 2 — Record from the agent

**Goal:** every fetch branch in `DeckAgent` writes an outcome, including the
skips.

**Files** — `native/DeckAgent/main.swift`

**Steps**

1. Add a small local helper that saves a `FetchStatus` and returns the outcome
   for logging (keeps each call site one line).
2. **opencode** (`main.swift:46-66`): remote branch `try?` → `do/catch` →
   classify; `token.isEmpty` branch → `notConfigured`; **local** branch success
   → `ok` (PRD §2.3 C2 guard: the file must never hold a stale remote failure);
   local failure writes nothing (local mode is a non-goal, PRD §5).
3. **weather** (`:103`): `try?` → `do/catch` → classify; success → `ok`.
4. **shipbox** (`:113-128`): `try?` → `do/catch` → classify; success → `ok`;
   the not-configured skip branch at `:127` → `notConfigured`.
5. Extend each existing OSLog line with the outcome (`failed shipbox snapshot
   (authOrTarget)`) — outcome names only, never URLs/tokens/repos/paths, per the
   agent's logging contract (`main.swift:15-17`).

**Verification**
Release build green. Run the built agent once
(`native/build.noindex/Build/Products/Release/DeckAgent`) and confirm
`~/Library/Containers/com.deck.app.widgets/Data/Library/Application Support/Deck/fetch-*.json`
appear with plausible outcomes; `log show --predicate 'subsystem == "com.deck.agent"' --last 2m`

## Phase 4 — ShipBox face

**Goal:** ShipBox stops blanking, and says why.

**Files** — `native/DeckWidgets/ShipBoxWidget.swift`

**Steps**

1. `ShipBoxEntry` gains `writtenAt: Date?` and `chip: String?`; `available`
   now means "a snapshot exists" (drop the `age <= 30*60` cutoff at `:65`).
   `stale` keeps its 5-minute meaning.
2. Provider `makeEntry()` loads the status
   (`FetchStatusStore.load(.shipbox)`) and resolves the chip through
   `FetchChip.text(...)` — no face logic in the widget.
3. Header (`:171-190`): render `entry.chip` in the existing 10pt `.tertiary`
   slot next to the time hint; on `.systemSmall` the chip **replaces** the
   totals line (PRD §2.1/C6) so the repo name is not squeezed.
4. Unavailable view (`:123`): second line = the chip when present, else today's
   "Paste a repo + token in Deck settings."
5. Drop the header's second `ShipBoxSnapshotStore.load()` (`:184`) now that the
   provider carries `writtenAt` — one file read per timeline instead of two,
   offsetting the new status read.

**Verification**
Build + `cp -R` to `/Applications` + re-add ShipBox from the gallery at
small/medium/large. Matrix: good token → no chip; wrong token → "Check repo +
token" **with the runs still on screen**; empty repo → "Add a repo + token in
settings"; wifi off → "Can't reach GitHub"; `launchctl bootout` the agent and
wait 30 min (or hand-write an old `writtenAt`) → "Agent hasn't run", data still
rendered.

**Dependencies** — Phases 1–3.
