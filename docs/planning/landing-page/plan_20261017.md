# Plan — landing-page (2026-10-17)

From `docs/planning/landing-page/prd.md`. Five phases, each ending green and
independently verifiable. This is a static page + a CI deploy; "green" means the
staged page renders and the string checks pass — there is no `swift build` or
XCTest here, by design (no `native/` code is touched).

Outcome: `https://haqaliz.github.io/deck` serves the page, `docs/planning/`
stays unpublished.

---

## Phase 1 — Site source + staging script

**Goal:** the full page renders locally, with assets, from a single staging
directory.

**Files:**
- `site/index.html` (new)
- `site/styles.css` (new)
- `scripts/stage-site.sh` (new)
- `.gitignore` (add `.site-build/`)

**Steps:**
1. `site/index.html` — six sections from PRD §2, **relative asset URLs only**
   (`assets/deck.svg`, `assets/A1.png`, …):
   - hero: mark, "Deck", the README one-liner, two CTAs
     (**Download — latest release** → `https://github.com/haqaliz/deck/releases/latest`;
     **Homebrew** → a `<code>brew install --cask haqaliz/deck/deck</code>` block
     that is always present, plus a copy button);
   - screenshots (`A1`, `A3`, `A5`);
   - widget grid: all fourteen cards, one-liners from PRD §2;
   - Search block (`⌥Space`; `pr `, `mkt `, `cal ` examples);
   - install block, **in order**: DMG/Homebrew → `xattr -dr
     com.apple.quarantine /Applications/Deck.app` → "run this **before** the
     first launch" warning → "right-click the desktop → Edit Widgets…"; no
     `--no-quarantine` anywhere;
   - footer: Apache-2.0, the repo link, the not-notarized note.
2. `site/styles.css` — light/dark via `prefers-color-scheme`, responsive down to
   phone width, mac-native feel (system font stack, rounded cards).
3. `scripts/stage-site.sh` — dependency-free (`rm -rf` + `mkdir` + `cp`): copy
   `site/` into `.site-build/`, then copy `docs/deck.svg` and the three used
   screenshots into `.site-build/assets/`. Accept an optional output dir
   (default `.site-build`). No JS/npm.
4. `.gitignore`: add `.site-build/`.

**Verification:**
- `scripts/stage-site.sh && ls -R .site-build` shows `index.html`, `styles.css`,
  `assets/{deck.svg,A1.png,A3.png,A5.png}`.
- `python3 -m http.server -d .site-build 8000` then open
  `http://localhost:8000/` — all sections render, **no 404s in the network
  panel**, both appearances (toggle the OS appearance), and at ~390 px wide.

**Dependencies:** none.

## Phase 2 — Consistency check script

**Goal:** a committed check that fails if the install copy drifts.

**Files:** `scripts/check-site.sh` (new)

**Steps:**
1. Takes the staging dir (default `.site-build`) and asserts, on the built
   `index.html`:
   - **present:** the `xattr -dr com.apple.quarantine /Applications/Deck.app`
     line; the before-first-launch warning wording; `brew install --cask
     haqaliz/deck/deck`; the `releases/latest` link; **all fourteen widget
     names** (LiveBox … MarketBox);
   - **absent:** `--no-quarantine`;
   - order: the `xattr` line appears **after** the install command in the file.
2. Exit non-zero with a clear message on the first failure.

**Verification:**
- `scripts/check-site.sh` → exit 0 on the Phase 1 output.
- Negative test: temporarily delete the warning sentence from
  `.site-build/index.html`, run again → **non-zero**; restore and re-run →
  green. (Recorded in the plan, not committed as a test.)

**Dependencies:** Phase 1.

## Phase 3 — Pages deploy workflow

**Goal:** pushing site changes deploys to GitHub Pages, gated by the checks.

**Files:** `.github/workflows/pages.yml` (new)

**Steps:**
1. Triggers: `push` to `master` changing `site/**`, `scripts/stage-site.sh`,
   `scripts/check-site.sh`, `docs/screenshots/**`, `docs/deck.svg`, or the
   workflow itself; plus `workflow_dispatch`.
2. `permissions: { contents: read, pages: write, id-token: write }`;
   `concurrency` on `pages` with `cancel-in-progress`.
3. Job `deploy` (environment `github-pages`): checkout → run
   `scripts/stage-site.sh` → run `scripts/check-site.sh` →
   `actions/configure-pages` → `actions/upload-pages-artifact` (path
   `.site-build`) → `actions/deploy-pages`.
4. Keep the workflow independent of `deck.yml` (which builds the app) so a docs
   change never triggers a macOS build.

**Verification:**
- YAML parses: `python3 -c "import yaml,sys;yaml.safe_load(open('.github/workflows/pages.yml'))"`.
- If `actionlint` is present, run it; otherwise skip.
- Local dry run: run `scripts/stage-site.sh && scripts/check-site.sh` exactly as
  the workflow does → green. (The live deploy is Phase 4.)

**Dependencies:** Phases 1–2.

## Notes / risks carried from the PRD critique

- **Pages-Source is the one manual gate** (Phase 4 step 1). Nothing in code can
  set it; the workflow's first run otherwise fails at `deploy-pages`.
- **The check proves presence, not parity** (PRD §9.4). The grep is a floor; a
  release that changes the install steps must update all **four** copies
  (`README.md`, `homebrew/deck.rb`, `deck.yml` notes, `site/index.html`). The
  install section will carry a one-line comment saying so.
- **Asset drift**: screenshots are staged at deploy, not duplicated in git, so a
  replaced `docs/screenshots/A1.png` flows to the site on the next deploy.
- **No test suite change**: nothing in `native/` or `DeckSharedTests` is
  touched; CI for the app (`deck.yml`) is unaffected.
- **Commit per task** on `feat/landing-page/aliz`; the branch's PR is opened by
  deck-end.
