# Plan: spotlight-shell

Source: `prd.md` (approved 2026-10-10). Adapted to this repo: xcodegen +
xcodebuild, not SwiftPM. Pure logic lives in `native/Shared/` and is tested in
`DeckSharedTests` (`native/SharedTests/`); UI/lifecycle is verified on a signed
build installed from `/Applications`.

**Standing rules for every phase**
- Every new `.swift` file (source or test) needs `xcodegen generate --spec
  native/project.yml`, or it is silently not compiled and the suite still
  passes. Check the executed-test count rises.
- Test command: `xcodebuild test -project native/Deck.xcodeproj -scheme
  DeckSharedTests -derivedDataPath native/build.noindex CODE_SIGNING_ALLOWED=NO`
  must show `Test Suite 'All tests' passed` and a non-zero executed count.
- Build only into `native/build.noindex`; run `scripts/lsclean.sh` after every
  release build.
- Quit a running Deck (`pgrep -lf "MacOS/Deck$"`) before testing anything that
  reads or writes `settings.json`.
- Commit per step on `feat/spotlight-shell/aliz`.

## Phase 0 — Gating probe (red in the PRD)

**Goal:** prove the hotkey, panel and tray work under hardened runtime with no
entitlement and no new permission prompt, before any design depends on them.

**Files:** `docs/planning/spotlight-shell/probe/main.swift` (throwaway, kept as
evidence), `docs/planning/spotlight-shell/probe.md` (results).

**Steps**
1. Write a ~80-line AppKit program: `NSStatusItem`, Carbon
   `RegisterEventHotKey` for ⌥Space, a borderless non-activating `NSPanel`
   (`.nonactivatingPanel`, `.floating`, `canBecomeKey` true) with an
   `NSTextField` that receives typing, Esc/click-away dismiss.
2. Compile with `swiftc`, sign with the Apple Development identity and
   `-o runtime`, **no entitlements file**.
3. Measure and record in `probe.md`: registration return code; panel appears
   over a full-screen app and on the active Space; typing reaches the field
   without activating the app (previous app keeps focus afterwards); no TCC
   prompt; `codesign -d --entitlements -` shows none; ⌥Space already taken ->
   what the failure code looks like.
4. Positive control: also register a key another app owns and confirm the
   failure is detectable, so a silent success means something.

**Verification:** `probe.md` states each item pass/fail with the command run.
**Stop condition:** any fail -> stop, revise the PRD (likely `NSEvent` global
monitor + Accessibility) before Phase 1.

**Dependencies:** none.

## Phase 1 — Pure search core (TDD)

**Goal:** query parsing, matching, ranking and the four providers as pure
functions over decoded snapshots, plus the settings struct.

**Files**
- `native/Shared/SpotlightCore.swift` — `SearchResult`, `SearchSection`,
  `SearchProviderID` (`clip/port/time/oc`), `SpotlightQuery.parse` (prefix
  scoping, trimming), `SpotlightMatcher` (case/diacritic-insensitive,
  prefix-of-word beats substring, stable ordering), section grouping and caps.
- `native/Shared/SpotlightProviders.swift` — `ClipSearch`, `DevSearch`,
  `ClockSearch`, `OpenCodeSearch`: `(query, snapshot, now) -> [SearchResult]`;
  each result carries a primary `SpotlightAction` (`.copy(String)` only in this
  slice). A nil snapshot yields no results.
- `native/Shared/DeckSettings.swift` — `SpotlightSettings` (shortcut
  keyCode/modifiers default ⌥Space, `keepInTrayOnly=false`,
  `openAtLogin=false`, per-provider enabled flags: clip off, others on), wired
  into `DeckSettings` + `CodingKeys` with `decodeIfPresent`.
- `native/SharedTests/SpotlightCoreTests.swift`,
  `SpotlightProvidersTests.swift`, `SpotlightSettingsTests.swift`.

**Steps (each RED -> GREEN)**
1. Query parsing: `clip foo`, `PORT 8080`, unknown prefix stays free text,
   prefix alone yields empty query, whitespace trimming.
2. Matcher + ranking incl. diacritics and tie-break stability.
3. Each provider against fixture snapshots: ClipBox (text, file path, image
   items have no content), DevBox (port number exact, command, container),
   ClockBox (city name -> time/offset/relative day via `ClockBoxCore`), OpenBox
   (titles). Missing snapshot -> `[]`.
4. Disabled provider is skipped; per-section result cap.
5. `SpotlightSettings` round trip, and **an old `settings.json` with no
   `spotlight` key keeps every other setting** (the regression CLAUDE.md
   records); a hand-edited shortcut with out-of-range values falls back to the
   default.

**Verification:** `xcodegen generate`, then the test command; executed count
rises by the new tests; suite green.

**Dependencies:** none (Phase 0 only gates continuing).

## Phase 2 — Lifecycle policy (TDD)

**Goal:** every quit/activation decision in the PRD as a pure, tested policy
so the delegate only applies it.

**Files:** `native/Shared/TrayLifecyclePolicy.swift`,
`native/SharedTests/TrayLifecyclePolicyTests.swift`.

**Steps**
1. `shouldTerminate(reason:keepInTrayOnly:)` — reasons: `.trayQuit`,
   `.settingsCmdQ`, `.dockQuit`, `.lastWindowClosed`, `.system` (logout/restart
   must always terminate). Tray-only: window close does not terminate.
2. `activationPolicy(trayReady:keepInTrayOnly:settingsWindowOpen:)` — accessory
   only when the status item exists; regular while the window is open.
3. `canEnableTrayOnly(trayReady:)`.
4. `urlLaunch(alreadyRunning:)` — a cold URL-only launch still quits; an
   already-running Deck stays (PRD decision).
5. Shortcut-conflict message copy (registration failure code -> sentence).

**Verification:** test command green, count up. **Dependencies:** Phase 1 only
for the settings type.

## Phase 3 — Shell (tray, hotkey, panel)

**Goal:** the visible feature, wired through the delegate, with no dependency
on `ContentView`.

**Files**
- `native/DeckApp/SpotlightHotKey.swift` — Carbon wrapper (register,
  unregister, re-register on change, returns the status for the settings UI).
- `native/DeckApp/SpotlightPanel.swift` — `NSPanel` subclass + SwiftUI content
  (field, grouped results, arrow/Enter/Esc, "No results" state).
- `native/DeckApp/SpotlightController.swift` — owns the panel, loads settings
  and snapshots **itself at query time** (no shared state with `ContentView`),
  runs the providers on a background queue, applies the primary action
  (copy to `NSPasteboard`, then dismiss).
- `native/DeckApp/TrayController.swift` — `NSStatusItem` + menu (Search,
  Settings, Quit).
- `native/DeckApp/DeckApp.swift` — delegate owns the controllers; apply
  `TrayLifecyclePolicy` in `applicationShouldTerminate`, window close handling
  and `applicationDidFinishLaunching` (keep the existing URL-launch behaviour,
  extended per Phase 2 step 4). Do not call `legacyCleanup()` from anywhere new.

**Steps**
1. Tray icon + menu (Settings opens the existing window; Quit terminates).
2. Hotkey -> toggles panel; re-registers when settings change.
3. Panel renders providers' results from a real container; Enter copies and
   dismisses; Esc/click-away dismisses; previous app keeps focus.
4. Tray-only mode: window close keeps the process; Dock icon hidden only after
   the status item exists; reopening Settings from the tray shows the Dock icon
   again while it is open.

**Verification:** release build -> `scripts/lsclean.sh` -> install per
CLAUDE.md -> manual matrix: hotkey from another app and over a full-screen
app; clip copy-back; tray Quit exits; Dock Quit and Cmd-Q behave per the
policy; widget URL click with Deck running keeps it, with Deck not running
quits after forwarding. Confirm `pgrep` shows the process after window close
in tray-only mode.

**Dependencies:** Phases 0-2.

## Phase 4 — Settings tab and login item

**Goal:** the new "Spotlight" sidebar item beside General.

**Files:** `native/DeckApp/DeckApp.swift` (`DeckWidget.spotlight` case, title,
icon, `SpotlightSettingsView`), `native/DeckApp/ShortcutRecorder.swift`,
`native/DeckApp/MainAppLoginItem.swift`.

**Steps**
1. Shortcut recorder control (requires a modifier; Esc cancels; shows the
   conflict sentence from Phase 2 when registration fails).
2. "Keep Deck in the tray only" toggle, disabled until the tray exists.
3. Per-provider toggles with the ClipBox privacy copy and the OpenBox "recent
   sessions only" copy.
4. "Open Deck at login": `SMAppService.mainApp` register/unregister; read
   status as the source of truth and show `.requiresApproval` as "turned off in
   Login Items" (not as unregistered). Do not touch the two agent
   registrations.

**Verification:** settings persist across relaunch; editing the shortcut takes
effect without relaunch; after replacing the bundle, re-check login-item state
(the veto resets — install first, then toggle, then relaunch).

**Dependencies:** Phase 3.
