# Implementation plan — `agent-heartbeat`

**PRD:** [`prd.md`](prd.md) · **Critique:** [`critique.md`](critique.md)
**Branch:** `feat/agent-heartbeat/aliz` · **Date:** 2026-08-30

Five phases, shell-and-data first, each ending green. Every pure decision is
TDD'd with the code, not after it — the two policies this touches are already
table-tested and the tables get extended rather than replaced.


## Phase 1 — The evidence type and the heartbeat store

**Goal.** A witness file the 60s agent can write, and a reader that tells
"absent" apart from "unreadable".

**Files**
- `native/Shared/AgentHeartbeat.swift` *(new)*
- `native/Shared/RefreshPolicies.swift` — `AgentEvidence` beside `AgentLiveness`
- `native/Shared/ProcessSnapshot.swift` — an `evidence` accessor
- `native/SharedTests/AgentHeartbeatTests.swift` *(new)*

**Steps**
1. **RED.** Tests for `AgentEvidence`: a missing path is `.never`; a path holding
   non-JSON bytes is `.unreadable`; a valid file is `.ran(at:)` with the exact
   date. Then the same three against `ProcessSnapshotStore` — today it answers
   `nil` for the first two alike (`ProcessSnapshot.swift:31-34`), which is the
   conflation being fixed.
2. **GREEN.** Add `enum AgentEvidence { case ran(at: Date); case never; case unreadable }`
   to `RefreshPolicies.swift` (policy vocabulary, next to the type that consumes
   it). Add one shared reader that checks existence first and decodes second, so
   both stores answer the same way.
3. `AgentHeartbeat { var writtenAt: Date }` + `AgentHeartbeatStore` over
   `AtomicFile`, file `agent-heartbeat.json` in `DeckSettings.containerDirectory`
   — the `ProcessSnapshotStore` shape exactly.
4. Round-trip test, **including a literal pin that `JSONEncoder` writes `Date` as
   seconds since the 2001 reference date**. Harmless and confusing; the last
   cycle pinned it for `agentsRegisteredAt` after it misled a reader of
   `settings.json`, and the same reader will meet this file.
5. `xcodegen generate`, then the unit gate.

**Verification.** `DeckSharedTests` green, including the three evidence shapes
for both stores.

**Dependencies.** None. Everything else builds on this.

## Phase 2 — Two witnesses, and the clock that protects the upgrade

**Goal.** The policy judges each agent separately and says which one stopped —
without accusing anybody on the release that introduces it.

**Files**
- `native/Shared/RefreshPolicies.swift`
- `native/SharedTests/RefreshPoliciesTests.swift`

**Steps**
1. **RED — the shape.** `AgentLiveness.down(lastRefresh: Date?)` becomes
   `.down(Down)` carrying `scope` (`.both` / `.data` / `.processes`) and both
   evidences. Existing `.down` assertions are rewritten to the new shape in the
   same commit; the *inputs* of the existing table are untouched, so a
   regression in fast-agent behaviour still fails.
2. **GREEN — the per-witness ladder.** Extract today's five steps into
   `verdict(evidence:limit:registeredAt:now:) -> .healthy / .unknown / .down`.
   Unchanged in substance: recent evidence wins **before** the grace window (so a
   working repair clears the notice at the next tick), and a future timestamp is
   a bad clock rather than a dead agent.
3. **The thresholds.** `dataAgentInterval = 60` as a **named constant**, with the
   limit derived as `4 * dataAgentInterval`; the process witness keeps
   `max(4 * processRefreshInterval, 120)` byte for byte. Test that the process
   verdicts are unchanged across the whole existing table.
4. **GREEN — the combine rule.** Global guards first and still structural
   (`intent == false`, `state != .enabled` → `.unknown`, before any witness is
   read, so a Login Items veto cannot raise a second notice about its own cause).
   Then: any `down` → `.down` scoped to which; else all `unknown` → `.unknown`;
   else `.healthy`.
5. **RED/GREEN — C4's total order.** Which evidence the both-down case reports:
   a timestamp outranks both non-dates, `.unreadable` outranks `.never`. Pin all
   six pairs.
6. **RED/GREEN — C2, the third trigger.** `AgentRegistrationClock.stamp` gains
   "restamp when the heartbeat is absent while the process witness is healthy".
   Tests for all four combinations, and specifically: **an upgraded install
   (`stored` days old, both `.enabled`, no heartbeat, fast agent healthy) must
   NOT report `.down`** — that is the whole point of the trigger. Plus the
   negative: a real both-down fault (no healthy witness) is unaffected and still
   accuses.

**Verification.** Unit gate green. The pre-existing `AgentLivenessPolicyTests`
cases still assert the same verdicts for the process witness.

**Dependencies.** Phase 1 (`AgentEvidence`).

## Phase 3 — The agent writes it, and only the agent

**Goal.** The witness exists at runtime, and the property that makes it a witness
is enforced by the suite rather than by a comment.

**Files**
- `native/DeckAgent/main.swift`
- `native/SharedTests/AgentHeartbeatTests.swift`
- `native/SharedTests/DeckBundleTests.swift` (or a sibling, same `#filePath` idiom)

**Steps**
1. Write the heartbeat at the **start** of the full-refresh path — immediately
   after `let start = Date()` and the "full refresh started" log, **before any
   fetch** (C1). One OSLog line, no payload. It witnesses *launched and started
   work*, never *finished*; the comment says so, because the difference is the
   whole reason it is not at the bottom of the function.
2. Confirm by placement that the fast role cannot reach it: `main.swift:54`
   already returns before this point.
3. **The single-writer test.** Read `DeckApp/` and `DeckWidgets/` sources through
   `#filePath` and assert no write to `AgentHeartbeatStore` appears in either —
   the idiom `DeckBundleTests` uses to pin `DeckBundle` against `project.yml`.
   The comment states plainly that it is a substring search: it catches the
   realistic regression (a heartbeat write copy-pasted into a host refresh path,
   which is exactly how the ten snapshots lost the property) and would not catch
   a wrapper or a rename (C5).
4. **The cadence pin (C3).** Assert `dataAgentInterval` equals `StartInterval` in
   `DeckApp/LaunchAgents/com.deck.agent.plist`. Swift never reads that plist at
   runtime, so without this a retuned agent leaves a threshold that fires on
   every healthy tick with nothing failing.
5. `xcodegen generate`; unit gate; build gate.

**Verification.** Both gates green. Then drive the agent by hand — **with Deck
quit**, because a running Deck overwrites snapshots with its own copy
(CLAUDE.md): `pgrep -lf "MacOS/Deck$"` must be empty, then
`/Applications/Deck.app/Contents/MacOS/DeckAgent` and confirm
`agent-heartbeat.json` appears and its mtime advances on a second run.
*(Ordinary caveat: the dev build's agent is the one in the bundle you installed,
so this reads the installed copy until Phase 5 replaces it.)*

**Dependencies.** Phase 1.

## Phase 4 — The notice names the half that stopped

**Goal.** The one user-visible surface.

**Files**
- `native/DeckApp/DeckApp.swift` — `evaluateLiveness()` (:537),
  `stampAgentsRegisteredAt()` (:517), `GeneralSettingsView.livenessNotice` (:832),
  the `.down` match (:864)

**Steps**
1. **Read both evidences once, at the top of the reconcile pass**, then stamp,
   then evaluate. **The existing order is load-bearing and must survive**
   (`DeckApp.swift:500-511`): the stamp is written before liveness is judged, or
   the bundle rename becomes this check's first false positive. C2's new trigger
   needs the process verdict as an *input* to the stamp, so evidence-reading
   moves ahead of both — it depends on neither.
2. `livenessNotice` takes the `Down` value and words three scopes (PRD §4):
   both (today's sentence, unchanged), data-only ("…LiveBox is still updating."),
   processes-only ("…Other widget data is still updating."). Never a launchd
   label — "Deck's data agent", not `com.deck.agent`.
3. The evidence sentence gains its third case: a file that will not decode reads
   "The last refresh could not be read.", not "No refresh has been recorded" —
   something wrote it, and claiming otherwise is the false statement D3 removes.
4. One notice, one **Restart agents** button, unchanged behaviour.

**Verification.** Build gate. Then force each scope by hand on the installed copy
(Phase 5) — a unit test cannot reach `GeneralSettingsView`, so the wording is
verified by eye, which is also the only way to catch it reading badly.

**Dependencies.** Phases 1–3.

## Phase 5 — Live verification on the installed copy

**Goal.** Prove it against a real launchd, since SMAppService cannot register
from `build.noindex` and every previous agent finding in this repo came from the
installed copy or was wrong.

**Steps**
1. Build Release, `scripts/lsclean.sh`, replace **only** the app bundle
   (`rm -rf /Applications/Deck.app && cp -R …`) — never touch the container
   (CLAUDE.md: the SIP-protected metadata plist survives deletion and every
   widget then renders blank forever).
2. **The upgrade check first, because it is the one that can discredit the
   feature (C2).** Install over the configured v1.36 with the agents running and
   open Deck: the General tab must be **silent**. A false accusation here is the
   failure this whole design guards against.
3. Healthy steady state: `agent-heartbeat.json` advances every 60s;
   `processes.json` on its own cadence; no notice.
4. **The real fault.** `launchctl bootout gui/$(id -u)/com.deck.agent` — the fast
   agent keeps writing and LiveBox keeps visibly updating, the heartbeat stops,
   and within 240s the tab must name **the data agent**. `evaluateLiveness()`
   runs on a 60s timer while the window is open (`DeckApp.swift:219`), so this is
   watchable without relaunching.
5. The mirror: bootout `com.deck.agent.processes` instead and confirm the
   processes-only wording. Then both, and confirm the original wording returns.
6. **Restart agents** repairs it; expect the notice to go quiet for one grace
   window and to be able to return naming a *narrower* scope if only one agent
   comes back (C6) — designed, not a bug.
7. Corrupt the process snapshot (`echo "{" > processes.json`, Deck quit) and
   confirm the wording is "could not be read", not "No refresh has been
   recorded".
8. Re-add each widget from the gallery — the standing rule that widgets must not
   regress between builds.

**Verification.** Record the run in
`docs/planning/agent-heartbeat/verification.md` with what was measured, and
**correct the PRD wherever the machine disagrees with it** — every agent
document in this repo earned its accuracy that way.

**Dependencies.** Phases 1–4.

## Risks

| Risk | Mitigation |
|---|---|
| A slow tick reads as a dead agent | Start-of-tick write (C1), pinned by placement in Phase 3 |
| The release accuses every upgrading user | Third clock trigger (C2), pinned by the Phase 2 upgrade test *and* the Phase 5 upgrade check |
| A future refresh path writes the heartbeat and silently kills the witness | Single-writer test (Phase 3), with its limits stated |
| Agent cadence retuned, threshold left behind | Plist pin (Phase 3) |
| A new file silently not compiled | `xcodegen generate` after every file addition, in each phase's steps |
