# Implementation plan — livebox-thermal-state (2026-08-20)

Source: `docs/planning/livebox-thermal-state/prd.md` (approved).

## Command deviation (read first)

The `deck-plan` skill template still names SwiftPM verification (`swift test`,
`swift run <Widget> --debug-flip`). This repo is an **xcodegen** project with no
`Package.swift` and no debug-flip harness — those commands do not exist here.
The real commands, matching CLAUDE.md and `.github/workflows/deck.yml:59`:

```bash
# tests (pure logic)
xcodebuild test -project native/Deck.xcodeproj -scheme DeckSharedTests \
  -derivedDataPath native/build.noindex CODE_SIGNING_ALLOWED=NO

# build (shell/UI)
xcodegen generate --spec native/project.yml
xcodebuild -project native/Deck.xcodeproj -scheme DeckApp -configuration Release \
  -derivedDataPath native/build.noindex -allowProvisioningUpdates \
  -allowProvisioningDeviceRegistration build
```

**`xcodegen generate` is required after adding ANY new source file.** The
original claim here — that files in already-globbed dirs are picked up
automatically — is wrong, and wrong in a dangerous way: xcodegen enumerates
files into the `.pbxproj` at generation time, so a new test file is simply not
compiled. Observed during Phase 1: the suite reported **"Test Suite 'All tests'
passed"** while the new tests did not exist in the target. That is exactly the
silent-pass failure mode CI guards against (`deck.yml:65`). Always regenerate,
and always check the executed-test count moved.

## Phase 1 — Pure core (TDD, RED → GREEN)

**Goal:** a tested level → label/tier mapping in `Shared/`, with no widget code.

**Files touched**
- `native/SharedTests/LiveBoxThermalTests.swift` (new, written FIRST)
- `native/Shared/LiveBoxThermalCore.swift` (new)

**Steps**
1. **RED** — write `LiveBoxThermalTests.swift` covering the §7 criteria:
   - `level(rawValue:)` maps 0→`.nominal`, 1→`.fair`, 2→`.serious`, 3→`.critical`
   - clamps: `-1`→`.nominal`, `4`→`.critical` (a state beyond critical must not
     silently degrade to untinted)
   - `label`: `"NOMINAL"`, `"FAIR"`, `"SERIOUS"`, `"CRITICAL"`
   - `tier`: nominal→`.normal`, fair→`.normal`, serious→`.warn`, critical→`.alarm`
   - a round-trip guard: `level(rawValue: ProcessInfo.ThermalState.fair.rawValue) == .fair`
     (pins our Int contract to Foundation's actual raw values)
   Run the suite; confirm it **fails to compile / fails**.
2. **GREEN** — add `LiveBoxThermalCore.swift` with `ThermalLevel: Int` and the
   three static functions exactly as in prd.md §4.
3. Re-run; suite green.

**Verification:** `xcodebuild test … -scheme DeckSharedTests`, and confirm the
run reports `Executed N tests` with N above the previous count (CI asserts this
too — `deck.yml:65` — because a misconfigured target passes silently).

**Dependencies:** none. This phase is mergeable on its own.

## Phase 2 — Setting (TDD)

**Goal:** `showThermal` persists, defaults off, and old `settings.json` files

**Files touched**
- `native/SharedTests/DecodeTests.swift` (extend `LiveBoxSettingsDecodeTests`)
- `native/Shared/DeckSettings.swift` (`LiveBoxSettings`, three places)

**Steps**
1. **RED** — add decode cases: `{}` → `showThermal == false`;
   `{"showThermal":true}` → `true`; encode round-trip preserves it; and the
   existing `{}`-equals-defaults test still passes (it compares whole structs,
   so a wrong default breaks it loudly).
2. **GREEN** — add to `LiveBoxSettings` (DeckSettings.swift:75):
   - `var showThermal = false` (field, after `showPerVolumeDisk`)
   - `case showThermal` in `CodingKeys` (:106)
   - `showThermal = try c.decodeIfPresent(Bool.self, forKey: .showThermal) ?? false`
     in `init(from:)` (:115)
   - `try c.encode(showThermal, forKey: .showThermal)` in `encode(to:)` (:147)
   All four are required — the type has a hand-written decoder AND encoder, so
   missing either one silently drops the setting.
3. Re-run; suite green.

**Verification:** `xcodebuild test … -scheme DeckSharedTests`.

**Dependencies:** independent of Phase 1, but commit after it so the branch

## Phase 3 — Front face

**Goal:** the `● THRM  FAIR` row renders last on all three sizes when enabled,
and nothing changes when disabled.

**Files touched**
- `native/DeckWidgets/LiveBoxWidget.swift`

**Steps**
1. Add `LiveBoxSampler.thermal() -> ThermalLevel` returning
   `LiveBoxThermalCore.level(rawValue: ProcessInfo.processInfo.thermalState.rawValue)`.
   **Do not** add it to `sample()`'s tuple — that flows into
   `history(appending:)`/`Sample` and would change `history.json` (prd §5).
2. Thread a `thermal: ThermalLevel` property into `LiveBoxFace` and pass it from
   `LiveBoxWidgetEntryView` (:196-210), inside the existing `TimelineView` tick.
3. Add a private `thermalRow` view — **not** a `metricRow` call, which is
   percent-typed (`%3.0f%%`, :463). Shape: `Circle()` 7×7 filled with
   `thermalTint ?? .secondary`, `Text("THRM").foregroundStyle(.secondary)`,
   `Text(label).foregroundStyle(thermalTint ?? .primary)` with `.lineLimit(1)`
   and `.minimumScaleFactor(0.75)` **on that Text only** (prd §4 — on the shared
   HStack it would shrink the CPU/MEM/DISK digits too).
4. Add `thermalTint` — nil unless `settings.showThresholdColors`, then
   `.normal`→nil, `.warn`→`ThresholdTier.warnColor.color`,
   `.alarm`→`.alarmColor.color`. Mirrors `tierColor()` (:471) but sources its
   tier from `LiveBoxThermalCore.tier`.
5. Render `if settings.showThermal { thermalRow }` last in `smallView` (:244),
   and last before `Spacer()` in the `mediumView` (:262) and `largeView` (:285)
   header `HStack`s.
6. Make the header spacing conditional in both medium and large:
   `HStack(spacing: settings.showThermal ? 10 : 14)` — so "off is
   byte-identical" holds on both faces.

**Verification**
- `xcodebuild … -scheme DeckApp … build` succeeds.
- Install (`cp -R` to `/Applications`, `open`), re-add LiveBox from the gallery,
  check small/medium/large with the toggle **off** → identical to before.
- Toggle on → row present at all three sizes; small shows four rows unclipped.
- **Forced-state check (the PRD's 🔴 fix):** temporarily hardcode
  `LiveBoxSampler.thermal()` to `.serious`, rebuild, confirm amber; then
  `.critical`, confirm red **and that the medium header does not truncate with
  the 8-character `CRITICAL`**; then **revert the hardcode**. macOS exposes no
  supported way to force a thermal state (`pmset -h` has no thermal option;
  `pmset -g therm` records nothing even while `ProcessInfo` reports `.fair`).
- Confirm the revert: `git diff` shows no hardcoded level before committing.

**Dependencies:** Phases 1 and 2.

## Risks carried into implementation

- **Untestable-in-anger tint path.** Serious/critical cannot be triggered on
  demand; coverage is unit tests plus a forced-render eyeball. If the hardcode
  is left in by accident the widget lies permanently — hence the explicit
  `git diff` revert check in Phase 3.
- **Medium-face width.** `CRITICAL` is the widest value the row can hold. If
  spacing 10 + scale 0.75 still clips, fall back to shortening the label rather
  than shrinking the shared digits (record the deviation in this file).
- **Quiet feature.** The row will read `FAIR` almost always; that is expected,
  not a bug.
