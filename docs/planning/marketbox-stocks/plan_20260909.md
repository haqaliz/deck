```
P1 (ticker model + catalog) ─┬─> P3 (builder .stock + collapse) ─> P5 (face)
P2 (Yahoo parser) ───────────┴─> P4 (loader: spaced serial fetch) ─> P5 ─> P6 (picker) ─> P7 (release)
```

## Phase 1 — `MarketTicker.stockSymbol` + the curated stock catalog

**Goal.** A ticker can be a stock: identity is a Yahoo symbol (`^GSPC`) separate
from the display symbol (`SPX`), `kind` derives `.stock`, and no existing user
loses a row. Pure, TDD.

**Files.** `native/Shared/MarketBoxCore.swift`, `native/Shared/DeckSettings.swift`,
`native/SharedTests/MarketTickerTests.swift`, `native/SharedTests/DecodeTests.swift`.

**Steps.**
1. **RED** — `MarketTickerTests`:
   - a ticker with `stockSymbol` set derives `.stock`; `coinID` non-empty wins
     over `stockSymbol` (defensive — a stock can never price as crypto);
   - display `symbol` ("SPX") is preserved while the fetch identity is
     `stockSymbol` ("^GSPC");
   - crypto/fiat/gold tickers behave exactly as before;
   - **round-trip: `stockSymbol` actually encodes** (the hand-written
     `CodingKeys` trap — a forgotten case compiles, decodes as absent and never
     encodes).
2. Add `stockSymbol: String = ""` to `MarketTicker` (`MarketBoxCore.swift`),
   the `CodingKeys` case, and the tolerant `init(from:)` decode. Add the
   `kind` derivation: `coinID` → `.crypto`; else `stockSymbol` → `.stock`;
   else the existing gold/fiat by symbol.
3. Add `MarketSymbolResolver.stockCatalog` — display symbol, friendly name,
   Yahoo symbol — plus the `stock(for:)` accessor. Contents (~20 entries):
   - **Stocks:** AAPL Apple, MSFT Microsoft, GOOGL Alphabet, AMZN Amazon,
     NVDA NVIDIA, META Meta, TSLA Tesla, NFLX Netflix, AMD AMD, INTC Intel,
     JPM JPMorgan, V Visa, BRK.B Berkshire, DIS Disney, COST Costco, WMT Walmart.
   - **Indices:** SPX S&P 500 (`^GSPC`), IXIC Nasdaq Composite (`^IXIC`),
     DJI Dow Jones (`^DJI`), RUT Russell 2000 (`^RUT`), VIX CBOE Volatility
     Index (`^VIX`).
   - A test asserts the catalog has **no duplicate display symbols** and no
     display symbol collides with the curated crypto migration table (a
     collision would be refused out loud at add time, which is right, but the
     catalog should not invite it).
4. `MarketBoxSettings`: no new key is needed for stocks to *encode* (`tickerList`
   is already the array) — the `stockSymbol` field rides on `MarketTicker`. The
   existing tolerant decode already covers old files (empty `stockSymbol`).
5. **GREEN**, then extend `DecodeTests`: a settings fixture with a stock ticker
   (`symbol: "SPX", stockSymbol: "^GSPC"`) round-trips; a file without the key
   decodes with `stockSymbol == ""` and kind `nil`/existing behavior unchanged.

**Verification.** `xcodegen generate` (test edits, no new files) then the suite.

## Phase 4 — `HostMarketLoader`: spaced serial stock fetch

**Goal.** The agent prices stock rows in one per-tick pass that stays under
Yahoo's burst limit and never spends the tick on a doomed pass.

**Files.** `native/Shared/MarketBoxSnapshot.swift`, `native/SharedTests/MarketBoxSnapshotTests.swift`.

**Steps.**
1. `needsStocks = tickers.contains { $0.kind == .stock }` in `fetch(settings:)`,
   mirroring `needsCrypto`/`needsGold`/`needsFiat`.
2. `fetchStocks(symbols:)` → `StockFetchResult` (quotes by Yahoo symbol +
   `noData` symbols). **Serial, one v8 call per symbol, `~0.75s` spacing**
   (`MarketFetchPlan.stockSpacing`, a single pinned constant). Per call:
   - `.quote` → record;
   - `.noData` → record into `noData` and continue (**not** a source failure);
   - `.malformed` / transport / non-200 → **abort the pass** and return what was
     priced so far — a rate-limited or dead first call means the rest are doomed
     too, so do not burn the tick on them.
3. `fetch` passes the result into `MarketBuilder.build` as the stock arm; the
   stock result is `nil` when `!needsStocks` (the three-state convention:
   nil = not asked / failed, per the existing `quotesByID` rule).
4. Tests (no network — the loader's policy is pinned through the pure parts):
   - `MarketFetchPlan.stockSymbols(for:)` dedupes by Yahoo symbol, drops blanks;
   - `MarketFetchPlan.stockSpacing` is `> 0` (a knob, not a magic sleep);
   - an all-stock-fail fetch still *builds* rows for the other kinds and the
     whole fetch only throws when **no** row at all priced (existing rule).
   - `grep -n "withThrowingTaskGroup" native/Shared/MarketBoxSnapshot.swift`
     returns nothing — the fan-out "fix" must not be applied to Yahoo.

**Verification.** Suite. One manual agent run (after the release build in P5)
prices a real AAPL/SPX pair into `marketbox.json`; see P5.

**Depends on.** P1, P2.

## What could still go wrong

1. **Yahoo's burst limit during manual verification.** Testing the agent or the
   picker burns the same quota the loader uses; if stock rows go stale mid-test,
   that is the 429 path working as designed. Wait ~60s between manual runs, and
   never loop the loader.
2. **A fixture that drifts.** The AAPL/GSPC prices are a point-in-time snapshot;
   the tests assert structure and the *captured* values, never that AAPL is
   still $316.22. The parser ignores everything it does not read, so a trimmed
   fixture is a fair contract.
3. **The 12-row cap hides a stock.** `tickerCount` and the list cap already
   cover stocks — a user with 12 crypto rows cannot add a stock until they
   remove one. Expected, not a bug; the add-sheet already refuses with "12 is
   the maximum".
4. **Weekend verification.** On a closed market Yahoo serves the last close with
   a ~0.0 change; the widget renders it. The P5 verification must not demand a
   non-zero change if the test lands on a weekend.
