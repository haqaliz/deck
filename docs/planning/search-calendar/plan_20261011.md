# Plan — search-calendar (2026-10-11)

From `docs/planning/search-calendar/prd.md`. Type: `task`. Nothing new is built;
the work is (a) move the calendar-access prompt into the Settings toggle, and
(b) earn the live-read claim with a recorded run.

Note on tooling: this repo is xcodegen + xcodebuild, not SPM. "Build" below means
`xcodegen generate` (after any new file) then `xcodebuild`; "test" means the
`DeckSharedTests` scheme. The panel steps need a human at the screen (no
computer-use tooling here) and are marked **[human]**.

## Phase 1 — The pure decision, TDD

**Goal:** name and pin the two decisions the prompt move rests on, so the view
and the loader are thin call sites over tested policy.

**Files touched:**
- `native/Shared/EventSearch.swift`
- `native/SharedTests/EventSearchTests.swift`
- `native/Shared/CalBoxSnapshot.swift` (a status accessor only)

**Steps:**
1. **RED.** In `EventSearchTests`, add a suite for two pure functions:
   - `CalendarSearchAccess.shouldRequestOnEnable(rawStatus:)` → `true` **only**
     for `0` (never asked); `false` for `1,2,3,4,99`.
   - `CalendarSearchAccess.panelCanRead(rawStatus:)` → `true` **only** for `3`.
   Run and watch them fail to compile/fail.
2. **GREEN.** Add `enum CalendarSearchAccess` in `EventSearch.swift`, delegating
   to the existing `CalendarAccess.canRead` / `.shouldPrompt` (keep that enum;
   its raw-value pin test is the reason both exist).
3. Replace the prompt branch in `HostEventSearch.events` (`EventSearch.swift:101-108`)
   with a single guard: read the live status via
   `HostCalendarLoader.authorizationStatus` and
   `guard CalendarSearchAccess.panelCanRead(...) else { throw
   SearchSourceFailure(.calendarAccess) }`. Delete the `requestAccess` call here
   — **the panel no longer prompts**. Update the stale comment.
4. Add `HostCalendarLoader.authorizationStatus: Int` in `CalBoxSnapshot.swift`
   (`EKEventStore.authorizationStatus(for: .event).rawValue`), so no EventKit
   import is needed in the settings view.
5. **REFACTOR.** Confirm `CalendarAccess.shouldPrompt` now has exactly one caller
   (the Settings side, Phase 2) and is not dead.

**Verification:**
- `xcodegen generate --spec native/project.yml` (no new file, but the new test
  file requires it) then
  `xcodebuild test -project native/Deck.xcodeproj -scheme DeckSharedTests
  -derivedDataPath native/build.noindex CODE_SIGNING_ALLOWED=NO` → the new
  assertions pass, the whole suite stays green (baseline 1673).

**Dependencies:** none.

## Phase 2 — Prompt in context, on the toggle

**Goal:** enabling Calendar events in Settings asks macOS for access there and
then, once; visiting the tab does not.

**Files touched:**
- `native/DeckApp/SpotlightSettingsView.swift`

**Steps:**
1. In `binding(for:)` (`:102-115`), give `.event` a custom `Binding`:
   `get` returns `settings.eventEnabled`; `set(on)` records `let wasOff = !settings.eventEnabled`,
   assigns the value, and — **only on the off→on transition and only when
   `CalendarSearchAccess.shouldRequestOnEnable(rawStatus: HostCalendarLoader.authorizationStatus)`**
   — fires `Task { _ = await HostCalendarLoader.requestAccess() }`.
   No request on appear, on re-render, or on off→off.
2. Correct the `.event` note copy (`:132-133`): "macOS asks for calendar access
   **when you turn this on**." (It currently says "the first time", which
   describes the removed panel path.)
3. Leave `exampleSummary`/`examples` alone; the row's static copy is unchanged
   otherwise (decision: no grant-state line).

**Verification:**
- `xcodebuild -project native/Deck.xcodeproj -scheme DeckApp -configuration
  Release -derivedDataPath native/build.noindex -allowProvisioningUpdates
  -allowProvisioningDeviceRegistration build` succeeds.

## Phase 3 — Install and earn the live claim

**Goal:** prove the EventKit read, the meeting link and the failure line against
the real calendar.

**Files touched:** none (build/install + record).

**Steps:**
1. `scripts/lsclean.sh`; replace only the bundle:
   `rm -rf /Applications/Deck.app && cp -R native/build.noindex/Build/Products/Release/Deck.app /Applications/`
   and launch.
2. **[human]** Enable Settings → Search → Calendar events → allow the prompt.
3. **[human]** In the panel (`⌥Space`): `cal <word matching a real event>` →
   the **CALENDAR** section shows real events with the date · calendar subtitle.
4. **[human]** Enter on an event that has a meeting link → the browser opens the
   conferencing URL; Enter on one without → the title is copied. Cmd-Return copies.
5. **[human]** Denied path: revoke Deck's Calendars access in System Settings,
   reopen the panel, search again → the section shows the one-line reason and
   **no prompt appears**.
6. **Measure** the broadcast-query read cost (time from send to results for a
   broad term) — the prefix-free decision turns on this number.
7. **Invariant:** `grep -rn "HostEventSearch" native/DeckAgent native/DeckWidgets`
   is empty.

**Verification:** `docs/planning/search-calendar/verification.md` records each
step's observed result, and states plainly what was not observed.

**Dependencies:** Phase 2 installed.
