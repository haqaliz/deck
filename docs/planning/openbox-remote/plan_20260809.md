## Phase 3 — Remote aggregation, pure (TDD)

- **Goal**: client-side aggregation of `session` + `message` JSON into
  `OpenCodeMetrics`, no I/O.
- **Files touched**: `Sources/OpenBoxCore/RemoteMetrics.swift`,
  `Tests/OpenBoxCoreTests/RemoteMetricsTests.swift`.
- **Steps**:
  1. Codable models mirroring the server shapes: `SessionJSON`
     (`id`, `time.updated`), `MessageJSON` (`role`, `time.created`,
     `cost`, `tokens{input,output,cache{read,write}}`, `modelID`,
     `providerID`).
  2. `RemoteMetrics.aggregate(sessions:messages:now:)`:
     - keep sessions with `time.updated ≥ now − 14d`;
     - per session fetch is precomputed; aggregate only messages with
       `role == "assistant"` and `time.created ≥ now − 13d` (matches local
       daily query window); "today" = `time.created > now − 24h`;
     - day bucket = UTC day of `time.created` (matches SQL `date()`);
     - model key `providerID/modelID` → `ModelParser.parse`;
     - sums: input, output, cacheRead, cacheWrite, cost; session count;
       models top-3 by cost desc.
  3. Fixture tests (all models `opencode-go/deepseek-v4-flash-max`):
     - fixed `now` + fixed epoch-ms fixtures: today sums, daily buckets
       across days, cache sums, cost rounding;
     - sessions updated < 14d ago are excluded (and their messages don't
       count);
     - old messages (> 13d) excluded from buckets;
     - models sorted by cost, top 3;
     - empty input → zeroed `OpenCodeMetrics`.
- **Verification**: `swift test` — all green.
- **Dependencies**: Phase 2.

## Phase 4 — HTTP transport + remote loader

- **Goal**: async loader doing the fetch fan-out and basic auth, delegating
  to the pure aggregator.
- **Files touched**: `Sources/OpenBox/OpenCodeMetrics.swift`
  (add `RemoteOpenCodeMetricsLoader`), `Sources/OpenBoxCore/RemoteMetrics.swift`
  (expose aggregate), `Tests/OpenBoxCoreTests/RemoteLoaderTests.swift`
  (URLProtocol stub).
- **Steps**:
  1. `RemoteOpenCodeMetricsLoader.load(url:password:) async throws
     -> OpenCodeMetrics` using `URLSession`:
     `GET {url}/session` with `Authorization: Basic base64("opencode:" + password)`,
     then `GET {url}/session/{id}/message` per kept session (sequential,
     first slice).
  2. Error mapping: connection error / non-200 / 401 → thrown
     `RemoteError` with a UI-ready message.
  3. `RemoteLoaderTests` with `MockURLProtocol`: stubbed `/session` and
     `/session/{id}/message` JSON → aggregated metrics; 401 → error message.
- **Verification**: `swift test` — all green; `swift build` green.
- **Dependencies**: Phase 3.

## Phase 5 — Store, settings, UI wiring

- **Goal**: the widget actually uses remote mode; settings expose URL +
  renamed password field; footer label + error copy reflect mode.
- **Files touched**: `Sources/OpenBox/Settings.swift`, `SettingsView.swift`,
  `MetricsStore.swift`, `ContentView.swift`.
- **Steps**:
  1. `Settings`: add `var serverURL: String = ""` (auto mode: non-empty →
     remote). Keep `token` key + `OPENCODE_TOKEN` default.
  2. `MetricsStore.refresh()`: if `serverURL` non-empty →
     `Task` with the async remote loader off-main, hop to `@MainActor`;
     else existing local path. Distinct error copy for remote failures.
  3. `SettingsView`: "Server URL" text field row above the password row;
     rename "Token" label → "Server password", placeholder
     `OPENCODE_SERVER_PASSWORD`.
  4. `ContentView`: footer label "ALL-TIME" (local) vs "14D" (remote);
     store exposes `isRemote` so the view doesn't read settings directly.
- **Verification**: `swift build -c release`; `swift run OpenBox --debug-flip`
  → settings face shows URL row + renamed password; run with no URL →
  local unchanged (window bounds = content height); run with bogus URL in
  settings → remote error line, no crash; `CGWindowList` bounds check.
- **Dependencies**: Phase 4.

## Addendum (2026-08-09, during implementation)

Live verification against `opencode serve` v1.18.15 found that `/session`
returns session-level `cost`, `tokens`, `model{id,providerID,variant}` and
`time.created` — richer than the dev-branch SDK spec. Implemented a session-
level aggregation fast path (single GET, matches local SQL over the `session`
table exactly), with the planned message-level fan-out as the automatic
fallback for older servers. `Task.detached` was dropped: URLSession async
hangs on the detached executor in this environment; the MainActor task works
(verified live: 825K input / $0.41 aggregated from the real server).
