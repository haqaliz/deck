# CalBox — Implementation Plan

Date: 2026-08-22 · Input: `docs/planning/calbox/prd.md`

Seven phases. Phase 1 is a **hard gate**: it proves the one unproven mechanism
the whole widget rests on (PRD §10 C2). Nothing else starts until it is green.

Note on commands: this repo is an xcodegen/xcodebuild project, not the
per-widget SwiftPM layout the `deck-plan` template still describes. There is no
`--debug-flip` and no panel height/flip wiring — the Widget Center is the only
surface (CLAUDE.md, M2). Verification uses `xcodebuild` + a gallery re-add.

---

## Phase 1 — TCC spike (🔴 blocking gate)

**Goal**: prove `DeckAgent`, a `type: tool` target with no Info.plist, can carry
`NSCalendarsFullAccessUsageDescription` and actually receive a calendar grant.

**Files touched**: `native/project.yml`, `native/DeckAgent/Info.plist` (new),
`native/DeckApp/Info.plist`.

**Steps**:
1. `native/DeckAgent/Info.plist` — minimal: `CFBundleIdentifier`
   (`com.deck.agent`), `CFBundleName`, `CFBundleExecutable`,
   `NSCalendarsFullAccessUsageDescription` ("Deck reads your calendar to show
   your next event in the CalBox widget.").
2. `project.yml` → DeckAgent `settings.base`:
   `INFOPLIST_FILE: DeckAgent/Info.plist` and
   `CREATE_INFOPLIST_SECTION_IN_BINARY: YES`.
3. Add the same usage-description key to `native/DeckApp/Info.plist`.
4. `xcodegen generate --spec native/project.yml`, then build DeckApp Release.
5. Temporary `--calendar-probe` flag in `DeckAgent/main.swift`: request access,
   print granted + calendar count, exit. Removed in Phase 4.

**Verification** (all four must pass):
```bash
xcodegen generate --spec native/project.yml
xcodebuild -project native/Deck.xcodeproj -scheme DeckApp -configuration Release \
  -derivedDataPath native/build.noindex -allowProvisioningUpdates build
otool -s __TEXT __info_plist native/build.noindex/Build/Products/Release/DeckAgent \
  | head                                   # section must exist and be non-empty
codesign -dv --entitlements - native/build.noindex/Build/Products/Release/DeckAgent
native/build.noindex/Build/Products/Release/DeckAgent --calendar-probe
#   → prompts once, then "granted: true, calendars: 11"
```

**If it fails**: stop and re-approve plan B (DeckApp performs the read on
launch + settings-window open; the agent does not). Plan B keeps every face and
loses the 60s cadence — a materially worse widget, so it is a decision, not a
fallback to take silently.

**Dependencies**: none. Everything else depends on this.

## Phase 2 — `CalBoxCore` scratch package (TDD)

**Goal**: every pure decision — which event is next, what the countdown says,
which calendars default on, how the timeline is cut — proven by tests before any
app wiring. Precedent: `ShipBoxCore` (`docs/planning/shipbox/plan_20260814.md`).

**Files touched**: `CalBoxCore/` (scratch SwiftPM package at worktree root,
removed in Phase 7).

**Deliberately EventKit-free.** The logic operates on a plain `CalEvent`, so it
is testable without a calendar store; the `EKEvent → CalEvent` mapping is the
only untested part and is covered by the Phase 1 spike + the Phase 4 live run.

**Steps**:
1. `Package.swift` (library + test target, tools 5.10, copied from ShipBoxCore)
   + `Sources/CalBoxCore/CalModels.swift`:
   `CalEvent { id, title, start, end, isAllDay, calendarTitle, color: RGBA }`
   and a snapshot-shaped container `{ writtenAt, events }`.
2. `CalendarDefaults.swift` — `shouldEnableByDefault(allowsContentModifications:)`.
   A one-line rule, but it earns a test: the draft's title-prefix version was
   wrong (PRD §10 C3) and a regression here silently floods the agenda.
3. `EventNormalisation.swift`:
   - `occurrenceID(eventIdentifier:start:)` → `"\(id)@\(start.timeIntervalSince1970)"`
   - `dedupe(_:)` on `(title, start, end, calendarTitle)`, keeping first
   - `dropDeclined(_:)` over an injected `isDeclined` flag on the input row
4. `NextEvent.swift` — `select(events:now:)` per PRD §4: all-day excluded;
   smallest `end > now` wins (in-progress beats not-yet-started); ties broken by
   earlier `start`, then title, so the pick is **stable across ticks**.
5. `Countdown.swift` — `text(start:now:)`: `> 1h` → `in 2h 05m`; `≤ 1h` →
   `in 42m`; `|Δ| ≤ 60s` → `now`; started-not-ended → `12m in`.
6. `Agenda.swift` — `split(events:now:calendar:)` → `(allDay, today, tomorrow)`
   in the current time zone, chronological, finished events dropped.
7. `TimelineBoundaries.swift` — `entries(events:now:calendar:)`: `now` + every
   `start`/`end` in the horizon + next midnight, deduped, sorted, **capped at 24**.
8. Tests (`Tests/CalBoxCoreTests/`), RED → GREEN → REFACTOR:
   - default rule: writable → on, read-only → off
   - occurrence id: two occurrences of one identifier → two distinct ids
     (the exact bug the probe found: 17 events, 10 identifiers)
   - dedupe: the real `Aliz workout time` duplicate collapses to one
   - declined dropped, including when it would otherwise be `next`
   - next-event: all-day never wins; in-progress beats upcoming; empty → nil;
     stability under repeated calls with advancing `now`
   - countdown: each band + both boundaries (60s, 1h) + the started case
   - split: midnight edges, an event spanning midnight, all-day partition
   - boundaries: dedup, sort, the 24 cap, midnight always present

**Verification**: `swift test` in `CalBoxCore/` — all green.

**Dependencies**: Phase 1.

## Phase 3 — Shared data layer

**Goal**: snapshot + store + EventKit loader + settings + failure copy,
compiling in all four targets.

**Files touched**: `native/Shared/CalBoxSnapshot.swift` (new),
`native/Shared/DeckSettings.swift`, `native/Shared/FetchStatus.swift`.

**Steps**:
1. Port CalBoxCore verbatim into `CalBoxSnapshot.swift`; add
   `CalBoxSnapshotStore` (`calbox.json` in `DeckSettings.containerDirectory`,
   load/save copied from `ShipBoxSnapshotStore`).
2. `HostCalendarLoader` (host/agent only) — `requestFullAccessToEvents`,
   `calendars(for: .event)` filtered to the selected identifiers,
   `predicateForEvents(withStart: now, end: endOfDay+2, calendars:)`,
   map `EKEvent → CalEvent` (occurrence id, `calendar.cgColor → RGBA`,
   `attendees.first(where: \.isCurrentUser)?.participantStatus == .declined`),
   normalise, cap at 60. Typed `CalendarError { notConfigured, accessDenied,
   readFailed }`.
3. `CalBoxSettings` — `calendarIDs: [String]`, `hasChosenCalendars: Bool`,
   `showAllDay`, `showAgenda`, `eventCount = 4`, `showTomorrow`,
   `useCalendarColors`, `accentColor` — with the tolerant `init(from:)`
   (pattern: `ShipBoxSettings`, DeckSettings.swift:361-371). Register on
   `DeckSettings`.
4. `FetchStatus.swift`: add `case calbox` to `FetchSource`; extend
   `FetchClassifier.outcome(for:)` with `CalendarError` → `.notConfigured` /
   `.authOrTarget` / `.badResponse`; add CalBox arms to `FetchStatusCopy.line`
   and `.hint` per PRD §6. **No new `FetchOutcome` case** — the enum is on-disk
   schema.

**Verification**: `xcodegen generate` then build DeckApp Release — green.
`FetchSource` is `CaseIterable`, so any missed `switch` arm is a compile error,
not a runtime blank.

**Dependencies**: Phase 2.

## Phase 4 — Agent wiring

**Goal**: the snapshot lands in the container every 60s.

**Files touched**: `native/DeckAgent/main.swift`.

**Steps**:
1. CalBox block after the ShipBox one: empty `calendarIDs` →
   `FetchStatusStore.record(.notConfigured, for: .calbox)` and skip; otherwise
   load, **always save** (PRD §3 — `writtenAt` drives the chip), record `.ok`;
   on throw classify and record.
2. OSLog one line per outcome — **counts only, never event titles** (PRD §3).
3. Remove the Phase 1 `--calendar-probe` flag.

**Verification**:
```bash
native/build.noindex/Build/Products/Release/DeckAgent
python3 -m json.tool ~/Library/Containers/com.deck.app.widgets/Data/Library/\
Application\ Support/Deck/calbox.json | head -30
log show --last 2m --predicate 'subsystem == "com.deck.agent"' | grep -i calbox
```
Snapshot must contain today's real events; the log must not contain any title.
Then re-run with `calendarIDs` emptied and confirm `fetch-calbox.json` records
`notConfigured`.

**Dependencies**: Phase 3.

## Phase 5 — Widget face

**Goal**: three sizes rendering, with a countdown that stays correct while the
agent is dead.

**Files touched**: `native/DeckWidgets/CalBoxWidget.swift` (new),
`native/DeckWidgets/DeckWidgets.swift`.

**Steps**:
1. `CalBoxEntry` + `CalBoxProvider` (pattern: `ShipBoxProvider`), including a
   `placeholder` with plausible fake events — the placeholder is what the
   gallery shows.
2. `getTimeline` emits the **multi-entry** timeline from
   `TimelineBoundaries.entries`, `.after(60s)` as the floor (PRD §5).
3. Countdown block: `Text(start, style: .relative)` for the live tick, plus the
   Phase 2 `Countdown.text` for the non-relative wording; monospaced digits;
   dot in `useCalendarColors ? event.color : accentColor`.
4. Small / medium / large per PRD §2, all-day row suppressed when empty, large
   capped at 8 with `+N more`.
5. Empty + unavailable states, including the **success** empty state ("Nothing
   left today" — no chip), and the `FetchChip.text(source: .calbox, …)` line.
6. Register `CalBoxWidget()` in `DeckWidgets.swift`.

**Verification**: build + install to `/Applications`, `open`,
`pluginkit -m -i com.deck.app.widgets`, then **re-add from the gallery at all
three sizes** (CLAUDE.md: widgets must not regress between builds). Check
against Calendar.app that the next event matches. Confirm the countdown
advances with the agent stopped
(`launchctl bootout gui/$(id -u)/com.deck.agent`), then boot it back in.

**Dependencies**: Phase 4.

## Phase 6 — Settings tab

**Goal**: pick calendars, in the only place Deck has settings.

**Files touched**: `native/DeckApp/DeckApp.swift`.

**Steps**:
1. CalBox tab: enum case + detail switch + view (pattern: the ShipBox tab).
2. Calendar list read via `HostCalendarLoader.calendars()`, grouped by source
   title, checkbox per calendar. First open applies the Phase 2 default rule and
   sets `hasChosenCalendars`, so a later deselection is never re-defaulted on.
3. Toggles right-aligned, stepper, ColorPicker — shell convention.
4. Static note that **both** Deck and DeckAgent need calendar access (PRD §7),
   plus the `FetchStatusCopy.hint` sentence under the calendar list, cleared
   when the selection changes (the `shipbox-fetch-errors` pattern).

**Verification**: open Deck, CalBox tab — all 11 calendars listed and grouped;
the four read-only ones unticked on first open. Tick one, confirm
`settings.json` updates, run the agent, confirm `calbox.json` changes and the
widget follows. Deny calendar access in System Settings and confirm the tab
shows the access hint and the face shows "Allow calendar access".

**Dependencies**: Phase 5.

## Phase 7 — Tests, registration, cleanup

**Goal**: the pure logic is covered by the real test target and the widget is
registered everywhere.

**Files touched**: `native/SharedTests/CalBoxTests.swift` (new),
`native/project.yml` (no change expected — sources are directory-based),
`README.md`, `ROADMAP.md`; delete `CalBoxCore/`.

**Steps**:
1. Port the Phase 2 tests into `DeckSharedTests` as `CalBoxTests.swift`, then
   **`xcodegen generate` again** — xcodegen enumerates files at generation time,

   reports success (CLAUDE.md, Commands). Confirm the new test count.
2. Delete the `CalBoxCore/` scratch package.
3. README.md: CalBox in the widget list, and the calendar-access note.
4. ROADMAP.md: tick CalBox under M5 **and correct the recorded caveat** — the
   "`~/Library/Calendars/` is empty, no account configured" note is wrong; it
   was a TCC denial. Record that routes 2 and 3 were dropped and why, so nobody
   re-litigates the transport later.

**Verification**:
```bash
xcodegen generate --spec native/project.yml
xcodebuild -project native/Deck.xcodeproj -scheme DeckSharedTests \
  -derivedDataPath native/build.noindex test 2>&1 | tail -20
```

confirm nothing regressed.
