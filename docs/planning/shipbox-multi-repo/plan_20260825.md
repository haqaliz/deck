# Implementation plan — ShipBox multi-repo (2026-08-25)

From `prd.md` (approved). Eight phases, each ending green. Pure logic is TDD'd
with `DeckSharedTests`; faces and settings are verified by build + install +
re-add from the gallery.

## Standing rules for every phase

- **`xcodegen generate --spec native/project.yml` before building whenever a
  file is added.** xcodegen enumerates sources at generation time, so a new test
  file is silently left out of the target and the suite still reports success
  (CLAUDE.md). The `Executed [1-9]` gate below is the backstop.
- **Tests:**
  ```bash
  xcodebuild test -project native/Deck.xcodeproj -scheme DeckSharedTests \
    -derivedDataPath native/build.noindex CODE_SIGNING_ALLOWED=NO 2>&1 | tee /tmp/test.log
  grep -q "Test Suite 'All tests' passed" /tmp/test.log   # must pass
  grep -qE "Executed [1-9][0-9]* test" /tmp/test.log      # must have run something
  ```
- **Build:**
  ```bash
  xcodebuild -project native/Deck.xcodeproj -scheme DeckApp -configuration Release \
    -derivedDataPath native/build.noindex -allowProvisioningUpdates \
    -allowProvisioningDeviceRegistration build
  scripts/lsclean.sh        # after EVERY release build, not just broken ones
  ```
- **No Swift Charts** anywhere in the face. **One timeline entry**, 60 s policy.
- Commit per phase, TDD order (RED → GREEN → REFACTOR) for phases 1–4.

## Phase 1 — Settings: mode, repo list, migration

**Goal** `ShipBoxSettings` carries a mode, a repo list and a dynamic cap, and an
existing `settings.json` migrates without losing the user's repo.

**Files** `native/Shared/DeckSettings.swift` ·
`native/SharedTests/DecodeTests.swift` (new cases)

**Steps**

1. RED — tests for: legacy `{"repo": "haqaliz/deck"}` decodes to
   `repos == ["haqaliz/deck"]` **and** `repoMode == .static`; absent keys give
   `repoMode == .dynamic`, `repos == []`, `maxRepoCount == 3`; `repos`
   normalizes (trim, drop empty, dedupe case-insensitively, cap 5); an unknown
   `repoMode` string falls back to `.dynamic`; encode emits only the new shape
   (no `repo` key); the three existing `DeckSettings` regression tests still
   pass (a new section must not reset every other setting).
2. GREEN — add `enum ShipBoxRepoMode: String, Codable { case dynamic, staticList }`
   (raw values `"dynamic"` / `"static"`), `repoMode`, `repos: [String]`,
   `maxRepoCount = 3`, `static let maxRepoCount = 5`, and
   `static func normalized(_:)` — mirroring `MarketBoxSettings`
   (`DeckSettings.swift:770-818`) line for line.
3. Extend the hand-written `init(from:)`: read `repos`, else legacy `repo`
   (non-empty → `[repo]` + `.staticList`), else defaults. `encode(to:)` writes
   only the new keys. `CodingKeys` gains `case legacyRepo = "repo"`.
4. Keep `repo` **out** of the struct entirely — the legacy key is read on
   decode only, exactly as MarketBox retired `symbols`.

**Verification** the test block above. **Depends on** nothing.

## Phase 2 — Snapshot: per-run repo tag, merge, labels, note

**Goal** the pure data layer for many repos — merge order, row labels and the
failure note — all testable without a network.

**Files** `native/Shared/ShipBoxSnapshot.swift` ·
`native/SharedTests/ShipBoxSnapshotTests.swift`

**Steps**

1. RED — tests for:
   - **merge/sort**: runs from three repos interleave by `createdAt` descending;
     ties break stably by repo order.
   - **short-name labels**: `haqaliz/deck` → `deck`; when two configured repos
     share a short name (`a/deck`, `b/deck`) **every** row in the snapshot uses
     `owner/repo` — one rule per snapshot, never per row.
   - **note composition** (the `PRChip.text` rule, `FetchStatus.swift:349`):
     one failure → `"cyclo: check repo + token"`; N failures sharing an outcome
     → `"cyclo + 2 more: check repo + token"`; N with mixed outcomes →
     `"cyclo: check repo + token +2 more"`; zero failures → `nil`.
   - **tolerant decode**: a v1.27 `shipbox.json` (`repo` string, runs with no
     `repo` field) decodes — `repos == [repo]`, each `ShipRun.repo == ""` — so
     the first tick after the upgrade renders instead of blanking to
     "No build data".
2. GREEN — `ShipRun` gains `var repo: String`; `ShipBoxSnapshot` gains
   `repos: [String]` and `note: String?` and loses `repo: String`; both get a
   hand-written tolerant `init(from:)`.
3. Add pure helpers: `ShipBoxMerge.merge(_:)`, `ShipBoxLabels.labels(for:)`,
   `ShipBoxNote.compose(failures:)`. No I/O, no `Date()` inside them (inject).

**Verification** tests. **Depends on** Phase 1 (mode enum for note wording).

## Phase 3 — Loader: concurrent fan-out and two-wave discovery

**Goal** one snapshot from up to five repos, partial failures survived, dynamic
discovery bounded — with the network-free parts under test.

**Files** `native/Shared/ShipBoxSnapshot.swift` (`HostGitHubLoader`) ·
`native/SharedTests/ShipBoxLoaderTests.swift` ·
`native/SharedTests/Fixtures/github_repos.json`

**Steps**

1. Capture the fixture from the live API (trimmed, as `github_prs.json` was):
   `/user/repos?sort=pushed&per_page=100&affiliation=owner` → keep ~6 entries
   and only the fields used (`full_name`, `pushed_at`, `archived`, `fork`).
   **Scrub** anything private; these are public repo names but check.
2. RED — tests for `RepoInventoryParser.parse` (order preserved by `pushed_at`,
   malformed entries skipped, empty array → `[]`, garbage → `nil`) and for a
   **pure** `DynamicRepoSelector.select(inventory:probeResults:maxCount:)`:
   candidates are `min(maxCount + 3, 8)`; winners are the first `maxCount` with
   `total_count > 0`; fewer winners than `maxCount` is fine; a probe error
   counts as "no runs" and does not abort the selection.
3. GREEN — implement the parser and the selector as free functions.
4. Wire the network around them (not unit-tested; verified in Phase 5):
   - `fetch(settings:) async throws -> ShipBoxSnapshot`, replacing
     `fetch(repo:token:)`.
   - Static: the configured repos. Dynamic: inventory → wave 1 probes at
     `per_page=1` → `DynamicRepoSelector` → wave 2.
   - **Both waves use `withTaskGroup`** — the codebase's first concurrent fetch
     (PRD §7 deviation). Each child returns `Result`; no shared mutable state.
   - `per_page = min(max(runCount, 2), 8)` for wave 2.
   - Partial-failure policy exactly as `HostMarketLoader` (`MarketBoxSnapshot.swift:193`):
     keep the first error, build from survivors, **throw only when no repo
     produced any runs and at least one errored**. All-200-with-zero-runs is a
     success with `runs: []`.
   - **C1**: an inventory failure propagates as its own classified error — it is
     never reported as "not configured".

**Verification** tests for steps 2–3; the fan-out itself is proven in Phase 5
against the live API. **Depends on** Phases 1–2.

## Phase 4 — Mode-aware failure copy (C3)

**Goal** dynamic mode never tells the user to check a repo field that its tab
does not have.

**Files** `native/Shared/FetchStatus.swift` ·
`native/SharedTests/FetchStatusTests.swift`

**Steps**

1. RED — `.shipbox` + `.authOrTarget` + `.dynamic` → token-only wording
   ("Check your token"); `+ .staticList` → today's "Check repo + token";
   `.notConfigured` + `.dynamic` → "Add a token in settings"; every other
   source's copy is byte-identical to before (pin it).
2. GREEN — a `ShipBoxCopy.line(outcome:mode:)` shim in front of
   `FetchStatusCopy.line(source:outcome:)`. **Do not add a `FetchSource` case**:
   the file's own comment says per-source keys exist so each *sub-tab* can show
   its own sentence, and here both sub-tabs share one fetch.

**Verification** tests. **Depends on** Phase 1.

## Phase 5 — Agent and host app wiring

**Goal** the two writers use the new loader identically, and it works against
the real API.

**Files** `native/DeckAgent/main.swift` (the block at `:130`) ·
`native/DeckApp/DeckApp.swift` (`refreshShipBox()` at `:303`)

**Steps**

1. Replace the `repo.isEmpty` guard with a resolver: dynamic needs only a token;
   static needs a token **and** ≥1 repo. Neither → `.notConfigured` (unchanged
   meaning).
2. Call `HostGitHubLoader.fetch(settings:)`; on success `save` + record `.ok`
   (a partial failure is still `.ok`, its detail rides in `snapshot.note`); on
   throw record `FetchClassifier.outcome(for:)` and **do not write** the file.
3. Mirror the exact same logic in `refreshShipBox()` — the two have always been
   line-for-line and must stay so.
4. Log the repo count and note presence via `agentLog.info` (`privacy: .public`
   on counts only, never on repo names — they can be private repos).

**Verification**
```bash
# build, install, then watch one real tick
cp -R native/build.noindex/Build/Products/Release/Deck.app /Applications/ && open /Applications/Deck.app
python3 -c "import json;d=json.load(open('$HOME/Library/Containers/com.deck.app.widgets/Data/Library/Application Support/Deck/shipbox.json'));print(d['repos'], len(d['runs']), d.get('note'))"
```
Expect: dynamic mode with an empty config discovers 3 repos with runs;
setting a deliberately bad static repo (`haqaliz/nope`) yields a written
snapshot, `.ok`, and a note naming `nope`; a bad **token** yields no write and
an `authOrTarget` chip. **Depends on** Phases 1–4.

## Phase 6 — Widget face

**Goal** the merged list reads correctly at three sizes, names its repos, links
to runs, and cannot hide a failure on the small face.

**Files** `native/DeckWidgets/ShipBoxWidget.swift`

**Steps**

1. `ShipBoxEntry`: `repo: String` → `repos: [String]`, plus `note: String?`.
   Update `placeholder` to a believable three-repo sample.
2. Header: one repo → its name (identical to today); N → `"N repos"`.
3. Rows: `<label> #<runNumber>` from `ShipBoxLabels`, trailing
   `RunFormatting.detail(for:)` unchanged.
4. **C4** — on `.systemSmall`, when `totals.failure > 0` the totals line wins
   over the chip (invert the current precedence at `:180`). Data that is bad
   news outranks a note about the fetch.
5. Note line under the list (medium/large), `.tertiary`, one line, truncating —
   MarketBox's treatment (`MarketBoxWidget.swift:165`).
6. Deep links: wrap each row in `Link(destination:)` for `run.htmlURL`; small
   face gets `.widgetURL(...)` for the newest run. Guard with the existing
   `DeckLink` http(s)-with-host filter — the URL comes from a snapshot file,
   which is data, not instruction. Skip the link when `htmlURL` is empty.

**Verification** build + install + `scripts/lsclean.sh`, **re-add ShipBox from
the gallery** and check all three sizes; click a row and confirm it opens the
run in the browser (not a new Deck window — the `handlesExternalEvents` trap).
Confirm the timeline archive stays small:
`du -sh ~/Library/Containers/com.deck.app.widgets/Data/SystemData/com.apple.chrono/timelines/`.
**Depends on** Phase 5.

## Phase 7 — Settings sub-tabs

**Goal** dynamic by default with one stepper; static with five pickers fed by
the live inventory; captions that explain every empty state.

**Files** `native/DeckApp/DeckApp.swift` (`ShipBoxSettingsView` at `:1184`)

**Steps**

1. Token field and the shared sections render **above** the sub-tabs (**C6** —
   the picker depends on the token, so the token must be visible first).
2. `Picker`-style sub-tab bound to `settings.repoMode`, PRBox's sub-tab pattern.
3. Dynamic tab: `Stepper("Repos to watch: N", in: 1...5)` + a caption that says
   the set **changes as you push** (**C7**), not merely how it is chosen.
4. Static tab: five `Picker`s over the inventory, `MarketBoxSettingsView`'s
   `tickerBinding(slot:)` pattern (empty pick clears the slot, remaining repos
   close up). A configured repo missing from the inventory stays listed and
   changeable (`configuredSymbolsNotInPicker` rule).
5. Inventory loaded in a `.task` when the tab appears — host app only, never
   persisted, never the agent. Store `[String]` + a load state in `@State`.
   Caption names the reason it is empty: no token / classified fetch failure /
   account has no repos.
6. `FetchStatusCaption(source: .shipbox, clearOn:)` gains the mode and the repo
   list in its key so a fixed setting clears the stale sentence immediately.

**Verification** open Deck → ShipBox tab: pickers populate within ~2 s (measured
1.9 s for 31 repos); switching modes and editing repos pushes a snapshot within
one 60 s tick; clearing the token empties the picker with the caption explaining
why. **Depends on** Phase 5.

## Risks

| Risk | Mitigation |
|---|---|
| `withTaskGroup` is new here and the agent is a short-lived CLI | The task group is awaited to completion inside the existing `do/catch`; the agent already `await`s several loaders before exiting |
| Dynamic discovery picks repos the user doesn't want | `affiliation=owner` only (PRD §9 Q1); static mode is one click away |
| Two waves push a slow tick past 60 s | Measured 1.3 s + 1.7 s concurrent; the 10 s per-request timeout bounds the worst case at 20 s, not 50 s |
| A private repo name reaching the log | Log counts, never names (Phase 5 step 4) |
| The old snapshot fails to decode after upgrade | Tolerant `init(from:)`, pinned by a Phase 2 test with a real v1.27 payload |

## Outcome (2026-08-25)

Shipped in five commits on `feat/shipbox-multi-repo/aliz`. 723 tests pass (+43
over master), both CI gates green.

**Two deviations from the phase order above, both forced by the code:**

- **Phase 4's copy shim landed inside phase 2.** `ShipBoxNote.compose` needs
  mode-aware wording to produce "cyclo: check your token", so `ShipBoxCopy`
  could not wait for its own phase. Phase 4 therefore has no separate commit.
- **Phase 5 landed with phase 3.** Replacing `fetch(repo:token:)` with
  `fetch(settings:)` broke the agent and host app in the same edit, so the
  wiring could not be deferred without leaving the tree red.

Phases 1 and 2 kept the app compiling via interim `repos.first` shims at the
three call sites; phases 5–7 replaced all of them.

**Live verification (the plan's phase 5 gate), against the real API:**

| Case | Result |
|---|---|
| Automatic, `maxRepoCount: 3` | discovered `belay`, `rereflect`, `vocca`; 12 runs, strictly newest-first across repos, `note: nil`, status `ok` |
| Static with a bogus middle repo | 8 runs from the two good repos; `note: "nope-does-not-exist: check repo + token"`; status `ok` |
| Bad token, static | status `authOrTarget`; `shipbox.json` **byte-identical** — last-good data survived |
| Bad token, automatic | status `authOrTarget`, **not** `notConfigured` — C1 holds where it actually matters |
| A real v1.27 `settings.json` | migrated on load to static mode with one repo, and the app correctly did *not* rewrite the file, since nothing changed |

Extension registers at 1.28; `ShipBoxWidget`'s timeline archive is 36 KB
(ClockBox, the largest, is 1.2 MB), so nothing resembling the CalBox
archive-size failure.

**Not verified:** the faces at three sizes. Deck's widgets render behind
windows and the desktop was covered, so no one has actually looked at the
multi-repo face, the note line, the inverted small-face precedence (C4), or a
row click. That check needs a human at the machine.
