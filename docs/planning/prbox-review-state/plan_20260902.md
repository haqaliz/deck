## Phase 1 — Review-state model + pure folding (TDD)

**Goal** the snapshot carries an optional, provider-agnostic review state and
both providers' vote/review payloads fold to it, all unit-pinned.

**Files**
- `native/Shared/PRBoxSnapshot.swift` — `PRReviewState` enum, `PullRequestItem.reviewState`, `GitHubReviewParser` + `GitHubReview` + fold, `GitHubReviewStateCap`.
- `native/Shared/AzureDevOpsLoader.swift` — Azure vote fold (pure, in `AzurePRParser`).
- `native/SharedTests/PRBoxGitHubTests.swift` (or a new `PRBoxReviewStateTests.swift`) — fold + cap tests.
- `native/SharedTests/PRBoxAzureTests.swift` — vote-fold tests.
- `native/SharedTests/PRBoxSnapshotTests.swift` — decode/round-trip tests.
- `native/SharedTests/Fixtures/github_pr_reviews.json` — hand-built on the documented shape (probe §3; the `azure_prs_votes.json` precedent).

**Steps**
1. `enum PRReviewState: String, Codable, Equatable { case approved, changesRequested }` in `PRBoxSnapshot.swift`.
2. `PullRequestItem.reviewState: PRReviewState?` (decoded `decodeIfPresent`, nil default; init param default nil; memberwise call sites untouched). Pin: a row with no key decodes nil; round-trip carries it; a snapshot written before the field decodes whole.
3. `struct GitHubReview { let login: String; let state: String; let submittedAt: Date }` + `GitHubReviewParser.parse(_ data: Data) -> [GitHubReview]?` — top-level array payload; nil on non-array/garbage (per-PR fail → no state, never a tick failure).
4. `PRReviewState.fold(_ reviews: [GitHubReview]) -> PRReviewState?` — latest-per-user among **substantive** states only (APPROVED, CHANGES_REQUESTED; COMMENTED/PENDING/DISMISSED never count); ties on `submittedAt` break by array order; any CHANGES_REQUESTED → `.changesRequested`; else any APPROVED → `.approved`; else nil. Tests pin the whole matrix (PRD §4).
5. `enum GitHubReviewStateCap { static func limit(_ items: [PullRequestItem], to cap: Int) -> [PullRequestItem] }` — newest by `createdAt`, ties by the `PRFormatting.sorted` order, prefix `cap`; the set that gets per-PR fetches.
6. Azure fold: `PRReviewState.fold(azureReviewers: [[String: Any]], excluding me: String) -> PRReviewState?` in `AzureDevOpsLoader.swift` — any negative vote → `.changesRequested`; else any vote ≥ 5 → `.approved`; else nil; the owner's own entry is excluded.
7. `AzurePRParser.item(from:role:me:target:)` stamps `reviewState` from the entry's `reviewers`.

**Verification** `xcodegen generate` (new fixture/test files), `xcodebuild test -scheme DeckSharedTests`: new tests green; the full suite stays green (1117 baseline).

**Dependencies** none.

## Phase 2 — GitHub per-PR fan-out in the loader

**Goal** `HostGitHubPRLoader.fetch` fetches review state for the capped rows, concurrently, fail-open per row, gated by a flag.

**Files**
- `native/Shared/PRBoxSnapshot.swift` — `HostGitHubPRLoader.fetch(token:scope:cap:reviewState:)`.

**Steps**
1. Signature: add `reviewState: Bool` (default `true` so tests/fixtures compile; both call sites pass it in Phase 3).
2. After the two search calls, when `reviewState` is on and items exist: `GitHubReviewStateCap.limit(items, to: cap)` → for each, build `GET /repos/{owner}/{repo}/pulls/{n}/reviews` from the item's `repository_url` tail + `number` (no new identity info needed).
3. Fan out with `withThrowingTaskGroup` (the `HostAzurePRLoader.inParallel` shape): each task returns `(index, Result<PRReviewState?, Error>)`; **a per-PR failure yields `nil` state, never a thrown tick** — the row keeps no glyph and the queue renders (PRD §5).
4. Apply states back onto the capped items by index (set `reviewState`), keep the rest of `fetch` unchanged.
5. Reuse `send(url:token:)` as-is (Bearer, versioned Accept, 10s timeout).

**Verification** pure seams stay pinned (cap + fold from Phase 1); loader behavior verified by the Phase 6 live install; `xcodebuild test` green.

**Dependencies** Phase 1 (types + fold).

**Files**

**Steps**
