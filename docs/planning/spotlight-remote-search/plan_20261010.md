# Plan: spotlight-remote-search

Source: `prd.md` (approved 2026-10-10). Stacked on `feat/spotlight-shell/aliz`.
Same conventions as the shell plan: pure logic in `native/Shared/` tested in
`DeckSharedTests`; run `xcodegen generate --spec native/project.yml` after any
new file and check the executed-test count rises; tests first, run red; build
only into `native/build.noindex`; `scripts/lsclean.sh` after every release
build; quit the installed Deck and restore `settings.json` around any run that
shares its container.

**Decision still open:** the Azure probe (Phase 0) uses the user's PAT and has
**not** been approved. Phases 1-3 need no account and can proceed; Phases 4-5
state which Azure behaviours they assume until Phase 0 has measured them.

## Phase 0 - Azure probe (BLOCKED on the user's go-ahead for their PAT)

**Goal:** measure what Azure does with search text before the query builder
depends on it.

**Files:** `docs/planning/spotlight-remote-search/probe.md`; a throwaway
`probe/` tool (not product code) that reads the TaskBox account's token from
the keychain exactly as `DeckAgent` does and sends read-only requests.

**Steps** (each is one measured line in probe.md; prefer one request each):
1. `[System.Tags] CONTAINS 'x'` on a tag that exists and one that does not;
   is it substring or whole-tag? case sensitivity?
2. `[System.Title] CONTAINS` with a word that is also a prefix of another.
3. `[System.Id] = N` for a known id, and for an id in another project.
4. Escaping: a term containing `'`, `)`, `[`, `]`, `%`, and a very long term
   after doubling quotes. Which are 200, which 400 and with what message?
5. `$top` behaviour for a broad term: latency, response size, and that Azure
   reports no total (so "full answer = at least N").
6. Does the batch return `System.Tags`, and in what shape (`a; b`)?
7. Closed and old items come back with no state filter.
8. Positive control: a query known to return a specific item, so an empty
   result elsewhere means something.

**Verification:** probe.md lists every item pass/fail with the request shape
(token never recorded). **Stop condition:** any surprise that changes the
query shape revises the PRD before Phase 2.

## Phase 1 - Remote-search policy (pure, TDD)

**Goal:** every rule about *when* a remote request may be sent, with no
network and no clock injected into the UI.

**Files:** `native/Shared/RemoteSearchPolicy.swift`,
`native/SharedTests/RemoteSearchPolicyTests.swift`.

**Steps (each RED then GREEN)**
1. `normalise(query)`: trim, collapse whitespace, case-fold for the cache key.
2. `shouldSearch(query:)`: false under 2 characters after the prefix is
   removed; true otherwise.
3. Debounce: `readyAt(typedAt:)` is typedAt + 300 ms; a later keystroke moves
   it. Pure, driven by passed-in timestamps.
4. Per-source floor: `earliestSend(lastSent:)` = lastSent + 500 ms.
5. Cache: get/put keyed `(source, normalisedQuery)`, 60 s TTL, size cap (drop
   oldest), expired entries miss, `invalidate(source:)`.
6. Generation guard: `Generation` increments per query; `accepts(response:
   for:)` is false for anything but the latest.
7. `RemoteSearchState` transitions: idle, searching, results, empty,
   failed(reason); `failed(.rateLimited(retryAfter))` keeps its own timer and
   blocks sends until it passes.
8. Reason mapping from an HTTP status / error to a user sentence: 401/203 ->
   bad token, 429 -> rate limited, transport -> unreachable, no account ->
   choose an account, locked keychain -> cannot read token. Reuse
   `FetchClassifier` where it already answers.

**Verification:** test command green, count up. **Dependencies:** none.

## Phase 2 - Task search query and parsing (pure, TDD)

**Goal:** turn typed text into a safe WIQL condition and Azure rows into
results.

**Files:** `native/Shared/TaskSearch.swift`,
`native/Shared/TaskBoxSnapshot.swift` (add optional `tags`),
`native/Shared/AzureDevOpsLoader.swift` (parser + field list),
`native/SharedTests/TaskSearchTests.swift`.

**Steps (each RED then GREEN)**
1. `TaskSearch.condition(for: text)` -> `String?`: quotes doubled; text capped
   (100 chars); numeric text also adds `OR [System.Id] = N`; control chars and
   newlines stripped; result **must pass `WiqlClause.validate`** (asserted in
   the test for every case).
2. Injection corpus, each asserted to stay inside one literal and keep the
   project clause intact in `WiqlClause.query(for:)`: `') OR ([System.Id] > 0`,
   `' OR 1=1 --`, `]`, `[System.State]`, `)`, `''`, a lone `'`, unicode, 4000
   chars, `ORDER BY`, `SELECT`, `%`.
3. `TaskItem.tags: [String]` (optional, `decodeIfPresent`); a JSON file with no
   `tags` key still decodes; the parser splits `a; b` and trims.
4. Batch `fields` gains `System.Tags`; existing fixtures still parse.
5. `TaskSearch.results(from: [TaskItem], account:)` -> `[SearchResult]`:
   `id = task:{project}:{id}`, title, subtitle `Type - State - Project - #id`
   plus tags, action `.open(url)` with the URL through `DeckLink.webURL`; a row
   whose URL fails the check is **not** offered as openable (copy only).
6. Ranking: exact id first, then title prefix, then the existing matcher.

**Verification:** test command green; injection corpus all pass validate.
**Dependencies:** Phase 0 only for the Azure-behaviour assumptions it states.

## Phase 3 - Model plumbing (pure, TDD)

**Goal:** the shell's types know about a remote source without changing local
behaviour.

**Files:** `native/Shared/SpotlightCore.swift`, `native/Shared/DeckSettings.swift`,
tests alongside.

**Steps (each RED then GREEN)**
1. `SearchProviderID.task` appended after `.oc`; prefix `task`; `isRemote`;
   `settingsTitle`, `exampleQuery` (`task login bug`), `exampleSummary` incl.
   the "what you type is sent to dev.azure.com" sentence. The existing example
   test must cover it.
2. `SpotlightAction.open(URL)`; `copyLink` is derived, not stored.
3. `SpotlightSettings.taskEnabled` (default true), tolerant decode; an old
   settings file keeps everything.
4. `SpotlightEngine.run` unchanged for local sources and ignores remote ones
   (asserted), so local results never wait on the network.
5. `SpotlightQuery.parse("task foo")` scopes to `.task`; `task` alone is free
   text.

**Verification:** test command green, count up; the local engine tests are
untouched. **Dependencies:** none.

## Phase 4 - Host wiring

**Goal:** the panel shows a live Tasks section.

**Files:** `native/Shared/AzureDevOpsLoader.swift` (new
`HostAzureDevOpsLoader.search`), `native/DeckApp/RemoteSearchCoordinator.swift`,
`native/DeckApp/SpotlightPanel.swift`, `native/DeckApp/SpotlightSettingsView.swift`.

**Steps**
1. `HostAzureDevOpsLoader.search(organization:projects:token:text:)`: validate,
   WIQL per project with `$top`, one batch call, `errorPolicy: omit`; throws the
   existing typed errors so `FetchClassifier` words them.
2. `RemoteSearchCoordinator` (main-actor, host-only): owns the policy state,
   the cache and one cancellable `Task`; on each query change it cancels, waits
   out the debounce, resolves credentials once per panel session
   (`DeckSettings.load()` + `hydrateAccountsFromKeychain()` + `gate(.taskbox)`),
   searches, and publishes `[RemoteSearchState]` + results. Never touches the
   agent's snapshots.
3. Panel: local sections render immediately; remote sections render beneath
   with Searching / empty / failed text; Enter opens (`NSWorkspace`), Cmd-Return
   copies the link; selection and keyboard navigation span both groups; the
   panel refits as sections arrive.
4. Settings: Tasks toggle row with example and privacy sentence; with no
   TaskBox account the row says so.
5. Hide/Esc cancels any in-flight request and clears the cache of nothing
   (cache lives for the app session, 60 s TTL).

**Verification:** release build, `lsclean.sh`, install. Without an account:
panel shows "Choose an account for TaskBox in Credentials" for `task x`.
With the account (needs the go-ahead): see Phase 5.

**Dependencies:** Phases 1-3.
