## Phase 1 — LiveBoxCore: per-core sampling + delta math (TDD, scratch SwiftPM package)

**Goal**: pure, tested per-core CPU sampling model — the aggregated
`CpuTicks.sample()` API stays byte-identical for the existing callers.

**Files touched**:
- `Package.swift` — scratch package: library `LiveBoxCore` + test target
  `LiveBoxCoreTests`.
- `Sources/LiveBoxCore/CpuTicks.swift` — `CpuTicks` (`Equatable`) + the
  mach sample (mirror of `SystemMetrics.swift:14-42`, ported): one
  `CpuTicks.sample() -> CpuTicks` (aggregated — used by existing code) and
  `CpuTicks.sampleAll() -> [CpuTicks]` (per-processor, never aggregated).
- `Sources/LiveBoxCore/PerCore.swift` —
  `perCoreUsagePercents(previous: [CpuTicks], current: [CpuTicks]) -> [Double]`
  — per-core `(deltaTotal - deltaIdle) / deltaTotal * 100`, `0` when
  `deltaTotal == 0`, zip-safe on the shared prefix when counts differ.
- `Tests/LiveBoxCoreTests/PerCoreTests.swift`.

**Steps** (TDD: failing test → green):
1. `CpuTicks` + `Equatable`; aggregated `sample()` keeps current behavior
   (port verbatim).
2. `sampleAll()` returns one `CpuTicks` per CPU (same
   `host_processor_info(PROCESSOR_CPU_LOAD_INFO)` call, no summation loop).
3. `perCoreUsagePercents`: mirror `cpuUsagePercent` math per core.
4. Tests: (a) `previous == current` → all 0; (b) idle-only increase → all 0;
   (c) one busy core with known delta → its percent = expected, others 0;
   (d) all-busy → 100s; (e) count mismatch (current has one more core) →
   shared-prefix length, no crash; (f) first call (no previous) → empty-safe
   handling (caller passes `[]` previous → empty result).

**Verification**: `swift test` — all LiveBoxCoreTests green.

**Dependencies**: none.

## Phase 3 — Front face: per-core lines in the chart

**Goal**: medium/large chart draws ≤8 thin per-core lines under the prominent
metric lines; old `history.json` decodes unchanged.

**Files touched**:
- `native/DeckWidgets/LiveBoxWidget.swift`:
  - `Sample` gains `let perCore: [Double]?` (Codable, optional — old history
    decodes, `nil` → no lines).
  - `LiveBoxSampler` keeps a `previousPerCoreTicks: [CpuTicks]?`; `sample()`
    also returns `perCore: [Double]` via `perCoreUsagePercents`.
  - `history(appending:)` stores `perCore` in the appended `Sample`.
  - Chart: when `settings.showCPU && settings.showPerCoreCores`, render
    `prefix(min(perCore.count, 8))` extra `LineMark`s **before** the
    CPU/MEM/DISK marks (draw order = below), series named per index, styled
    `settings.cpuColor.color.opacity(0.4)`, `lineWidth 1.0`, `catmullRom`.

**Steps**:
1. Extend `Sample` + sampler + history.
2. Add the per-core `LineMark`s in `LiveBoxFace.chart`.
3. `xcodebuild` Release; install to `/Applications`; `open /Applications/Deck.app`;
   `pluginkit -m -i com.deck.app.widgets`.

**Verification**: re-add LiveBox from the gallery (CLAUDE.md regression rule);
within ~1 minute thin per-core lines appear under the CPU line on medium/large;
total CPU/MEM/DISK lines unchanged in weight and color; small widget identical;
other five widgets unchanged (re-add one).

**Dependencies**: Phases 1, 2.
