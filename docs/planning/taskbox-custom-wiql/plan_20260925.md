## Phase 1 — `WiqlClause`: validation + composition (pure, TDD)

**Goal:** one pure type decides whether a condition may be sent and composes the full query.

**Files:** `native/Shared/WiqlClause.swift` (new),
`native/SharedTests/WiqlClauseTests.swift` (new), `xcodegen generate`.

**Steps**
1. RED: tests for `WiqlClause.validate(_:) -> WiqlClause.Problem?`:
   - nil for the built-in condition, P13 `CONTAINS 'a)'`, P14 `'it''s'`,
     P15 macros, `CONTAINS 'order'`/`'from'`, `[Custom.FromDate]`
   - `.unbalancedParentheses` for `a) OR (b` (P9: depth < 0 mid-string) and `(a`
   - `.unterminatedLiteral` for `'abc`, `.unterminatedField` for `[System.State`
   - `.reservedKeyword("ORDER BY")` etc. for ORDER BY / ASOF / MODE / SELECT /
     FROM outside literals, case-insensitive, whole word (`[System.Id] > 0 order by x`)
   - `.tooLong` above 4,000 characters
2. RED: `WiqlClause.query(for condition: String) -> String`:
   - whitespace-only / empty yields the built-in condition
   - output is exactly `SELECT [System.Id] FROM WorkItems WHERE [System.TeamProject] = @project AND (<c>) ORDER BY [System.ChangedDate] DESC`
   - `isCustom(_:)`: trimmed non-empty
   - `Problem.message`: the settings caption copy for each case
3. GREEN: single-pass scanner with states normal / inLiteral / inField,
   tracking depth, and a word buffer in normal state for keyword checks.
4. `xcodegen generate`, then run the suite.

**Verification:** the new tests pass and the executed count is higher than 1311.
**Dependencies:** none.

## Phase 2 — Loader: cap, 400 message, error cases (pure parts TDD)

**Goal:** the WIQL call sends the composed query with `$top=201`, reports caps, and turns a 400 into `queryRejected`.

**Files:** `native/Shared/AzureDevOpsLoader.swift`, `native/Shared/FetchStatus.swift`,
`native/SharedTests/AzureDevOpsParserTests.swift`, `native/SharedTests/` fetch-status
tests (existing file for `FetchClassifier`/`FetchStatusCopy`).

**Steps**
1. RED/GREEN `WiqlIdParser`: `static let requestTop = idLimit + 1`. `ParsedWiql`
   gains `capped: Bool` (`ids.count > idLimit`), `total = min(count, idLimit)`.
   Update the existing 260-id test: total is 200 and capped.
2. RED/GREEN `WiqlErrorParser.message(_ data: Data) -> String?`: the `message`
   field, trimmed, first line. Fixtures are the P2 and P3 bodies from the probe;
   non-JSON gives nil.
3. `AzureDevOpsError` gains `invalidQuery(WiqlClause.Problem)` and
   `queryRejected(String?)`.
4. `FetchOutcome.queryRejected`. `FetchClassifier`: both new errors map to
   `.queryRejected`. `FetchStatusCopy.line` gives "Check the query" for
   `.taskbox`, nil elsewhere. `hint` gives the PRD §5.3 sentence. Tests cover
   the mapping, that only taskbox speaks, and the tolerant decode of an unknown
   raw value.
5. `HostAzureDevOpsLoader.fetch(organization:projects:token:condition:)`:
   validate first (throw `invalidQuery`, no request). The WIQL URL gets
   `&%24top=201`. In `workItemIDs`, a `serverError(400)` becomes
   `queryRejected(WiqlErrorParser.message)`. That needs `send` to return the
   body on non-200, so add a thin `sendWiql` rather than changing `send` for
   every caller. Delete `wiqlQuery` and its now-false comment.
6. Snapshot totals: sum of `min` totals, and `totalIsLowerBound` = any capped
   (A2). Snapshot `isCustomQuery = WiqlClause.isCustom(condition)`.
7. Public `HostAzureDevOpsLoader.test(organization:projects:token:condition:) async -> [ProjectTestResult]`
   for the settings Test button: WIQL-only per project (no batch), returns
   count/capped or error per project. It reuses `workItemIDs`.

**Verification:** the suite is green. The TaskBox and `DeckAgent` callers
don't compile until Phase 3, so Phase 2 and 3 land together before the build
check.
**Dependencies:** Phase 1.

## Phase 3 — Snapshot, settings field, callers, face wording

**Goal:** the setting persists and flows through both refresh paths, and the face words custom queries correctly.

**Files:** `native/Shared/TaskBoxSnapshot.swift`, `native/Shared/DeckSettings.swift`,
`native/DeckAgent/main.swift`, `native/DeckApp/DeckApp.swift` (`refreshTaskBox` only),
`native/DeckWidgets/TaskBoxWidget.swift`, `TaskBoxSnapshotTests`, settings decode tests.

**Steps**
1. RED/GREEN `TaskBoxSnapshot` gets `totalIsLowerBound`, `isCustomQuery`
   (tolerant, default false). An old JSON fixture decodes both as false.
2. RED/GREEN `TaskFormatting.totalLine(totalCount:lowerBound:custom:)` covers
   "11 open", "211+ open", "11 items", "211+ items". `emptyLine(custom:)` gives
   "Nothing assigned" or "No matches".
3. RED/GREEN `TaskBoxSettings.query: String = ""`, tolerant decode. Confirm
   TaskBoxSettings has no hand-written `encode(to:)` (verified: synthesized),
   and add a round-trip test anyway.
4. Pass `settings.taskbox.query` from `DeckAgent/main.swift:232` and
   `DeckApp.refreshTaskBox`. The agent log stays outcome-only (A4).
5. Widget: the entry carries `totalIsLowerBound`/`isCustomQuery` from the
   snapshot, the header and empty view use the formatting functions, and the
   placeholder gets defaults.
6. Release build.

**Verification:** the suite is green and the release build succeeds.
**Dependencies:** Phase 2.

## Phase 4 — Settings UI: draft, Apply, Test

**Goal:** the Query section per PRD §3, where only Apply persists (A1).

**Files:** `native/DeckApp/DeckApp.swift` (`TaskBoxSettingsView`, plus passing the resolved credential for Test).

**Steps**
1. `@State draft` is initialised from `settings.query` in `onAppear`. A
   `TextEditor` (monospaced, ~4 lines) with a placeholder overlay showing the
   built-in condition.
2. A live `WiqlClause.validate(draft)` shows a red caption with `Problem.message`.
3. Buttons: **Apply** (disabled if invalid or `draft == settings.query`;
   writes it; the existing settings-save path persists, then `refreshTaskBox`
   is triggered via an `onApply` closure), **Test** (disabled if invalid, no
   account, or running), and **Start from default**. An "Unsaved changes"
   caption shows while they differ.
4. The Test result line shows counts ("11 matches", "ForesightManifold 11 · Ops 0",
   "200+"), Azure's message verbatim, or `FetchStatusCopy.hint`. It clears on
   a draft or account change. It's held in `@State` only (A4).
5. Test needs the token. Use the same `gate(.taskbox)` resolution
   `refreshTaskBox` uses, via a closure passed from the parent view, so the
   view never touches the keychain directly.

**Verification:** release build. Manual check in the running app: typing
doesn't change the widget, Apply does, and Test shows each of the three result
kinds.
**Dependencies:** Phase 3.

**Goal:** prove it on the installed copy and record it.

**Steps**

   `scripts/lsclean.sh`, then open once.
2. Quit Deck (`pgrep -lf "MacOS/Deck$"` shows nothing). Edit `taskbox.query` in
   settings.json per case, and run `/Applications/Deck.app/Contents/MacOS/DeckAgent`:
   - empty: 11-ish items, "N open", the same ids as probe P1
   - `[System.State] = 'Active'`: "N items"
   - P3 clause: `fetch-taskbox.json` says `queryRejected`, and the snapshot
     **mtime is unchanged**
   - P9 clause: `queryRejected` with no request (the local guard)
   - `[System.Id] > 0`: "200+ items", and the tick finishes well under 10s
   - restore empty
3. Settings UI: Test for each case, and Apply behaviour.
4. Re-add TaskBox from the gallery, check small/medium/large. No version bump
   is needed for the gallery (no new widget), but bump for the release as
   usual.
5. Docs: ROADMAP M8 tick with findings (the probe corrected the TaskBox
   non-goal, P9, the `$top` cost). TaskBox PRD non-goal gets a pointer. README
   TaskBox line. CLAUDE.md trap: "WIQL wrapped in parens is not isolation;
   uncapped WIQL can exceed the 10s timeout".

**Dependencies:** Phase 4.
