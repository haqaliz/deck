# BatBox accessories — implementation plan (2026-08-23)

Source: `prd.md` as revised after the spike. Branch `feat/batbox-accessories/aliz`.
Commands are xcodegen/xcodebuild per CLAUDE.md, not the SwiftPM ones in the
deck-plan template.

---

## Phase 0 — Prove the SPI resolves inside the sandboxed extension

**Goal:** retire the one unverified assumption before building on it.

The spike ran in an unsandboxed CLI. `IOPSCopyPowerSourcesByType` is SPI
declared via `@_silgen_name`; if the symbol does not resolve, or the sandbox
denies it, everything downstream is worthless.

**Files:** `native/DeckWidgets/Loaders/BatteryMetrics.swift` (temporary log)

1. Add the declaration and a one-shot `os_log` of the accessory count and first
   name, called from `BatBoxProvider.makeEntry`.
2. Release build, install, add a BatBox widget, read the extension's log.

**Verification:** the extension log names `MX Master 3S`. If it reports zero
while `pmset -g accps` shows the mouse, the sandbox is blocking it and the
whole feature reverts to the agent path — stop and re-plan.
**Blocks:** everything.

## Phase 1 — Accessory model + pure logic (TDD)

**Goal:** everything testable that does not touch IOKit.

**Files:** `native/Shared/AccessoryCore.swift` (new),
`native/SharedTests/AccessoryCoreTests.swift` (new)

1. `BatteryAccessory`: `id`, `name`, `percent`, `lowWarnLevel`, `category`.
2. `AccessoryCore.tier(percent:lowWarnLevel:)` — the device's own
   `Low Warn Level` drives amber; red at half that. No global setting.
3. `AccessoryCore.symbol(for category:)` — SF Symbol per
   `Accessory Category`: Mouse → `magicmouse`, Keyboard → `keyboard`,
   Headphones → `headphones`, unknown → `dot.radiowaves.left.and.right`.
4. `AccessoryCore.sorted(_:)` — lowest battery first, so the one about to die
   is the row that survives the row cap.
5. `AccessoryCore.summary(_:)` — the small face's line: count plus the lowest
   percent, nil when the list is empty.

**Verification:** `xcodegen generate` then the test scheme; record the
before/after test count — a green suite alone is not evidence the new file
compiled (CLAUDE.md).
**Dependencies:** none; runs in parallel with Phase 0.

## Phase 2 — IOKit accessory loader

**Goal:** turn the SPI call into `[BatteryAccessory]`.

**Files:** `native/DeckWidgets/Loaders/BatteryMetrics.swift`

1. Promote the Phase 0 declaration into
   `AccessoryMetricsLoader.snapshot() -> [BatteryAccessory]`.
2. Read type `4`; map `Name`, `Current Capacity`, `Max Capacity`,
   `Low Warn Level`, `Accessory Category`, `Accessory Identifier`.
3. Percent via the existing `BatteryMath.percent(current:maxCapacity:)` rather
   than assuming `Max Capacity == 100`.
4. Identity from `Accessory Identifier`, falling back to `Name`.
5. Every failure path — nil blob, unresolved symbol, missing keys — returns an
   empty array. Never throws, never partially populates.
6. Remove the Phase 0 temporary log.

**Verification:** Release build; the face renders the mouse at its real
percent, cross-checked against `pmset -g accps`.
**Dependencies:** Phases 0, 1.

## Phase 3 — BatBox faces

**Goal:** accessories on all three sizes.

**Files:** `native/DeckWidgets/BatBoxWidget.swift`

1. `BatBoxEntry` gains `accessories: [BatteryAccessory]`.
2. Small: one line from `AccessoryCore.summary`, hidden when empty.
3. Medium/large: an `ACCESSORIES` section — SF Symbol, name, percent, tier
   colour; capped at `accessoryCount`, large showing more.
4. Section hidden entirely when the list is empty — never an empty header.

**Verification:** Release build, install, all three sizes with the mouse
connected and then disconnected — the section must appear and vanish without
a stale percentage.
**Dependencies:** Phase 2.

## Phase 4 — Settings

**Goal:** two controls, no more.

**Files:** `native/Shared/DeckSettings.swift`, `native/DeckApp/DeckApp.swift`,
`native/SharedTests/DecodeTests.swift`

1. `BatBoxSettings`: `showAccessories = true`, `accessoryCount = 4`.
2. Tolerant decode, and extend the container round-trip test — the guard added
   for `calbox` only works if new fields are actually covered.
3. BatBox tab: a toggle and a stepper.

**Verification:** test scheme; change both in the app and confirm the widget
follows within ~60s.
**Dependencies:** Phase 3.

## Phase 5 — Docs + release

**Files:** `README.md`, `ROADMAP.md`, `CLAUDE.md`, `native/project.yml`

1. BatBox roster entries mention accessories.
2. **CLAUDE.md: BatBox is now the counter-example to the two-path split** —
   still self-sampled, but reading a power-source type the public headers do
   not expose. Record that `IOPSCopyPowerSourcesByType` is SPI, that
   `IOPSCopyPowerSourcesList` deliberately omits accessories, and that
   `system_profiler`/IORegistry return nothing for a real device — so nobody
   repeats the two dead ends the spike burned.
3. Version bump 1.18 → 1.19.

**Verification:** `grep -n 'accessor' README.md ROADMAP.md CLAUDE.md`.
**Dependencies:** all.

## Phase 6 — Reinstall

Per the standing instruction, finish with a remove-and-install.

**The container must not be touched.** `rm -rf` on it is what left every widget
blank earlier; the app bundle is the only thing that gets removed. No
`settings.json` backup is needed for the same reason — nothing wipes it.

1. Quit Deck; `rm -rf /Applications/Deck.app`; copy the fresh build in.
2. `scripts/lsclean.sh`, then `scripts/container-repair.sh` as a check.
3. `pluginkit -m -i com.deck.app.widgets` reports 1.19.
4. User re-adds BatBox and confirms the accessory row.

**User steps that cannot be automated:** re-adding widgets, and connecting an
accessory to see a populated section.
