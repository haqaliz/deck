# Implementation plan — `credentials`

**From:** `prd.md` + `critique.md` (all five 🔴 and four 🟡 folded in).
**Branch:** `feat/credentials/aliz` · **Baseline:** `DeckSharedTests` green, 2026-08-26.

## Ground rules for every phase

- **`xcodegen generate --spec native/project.yml` before building whenever a
  source file is added.** xcodegen enumerates files at generation time, so a new
  test file is silently not compiled *and the suite still reports success* —
  the most dangerous failure mode in this repo. Each phase below that adds a file
  says so explicitly.
- Every phase ends green:
  ```bash
  xcodebuild test -project native/Deck.xcodeproj -scheme DeckSharedTests \
    -derivedDataPath native/build.noindex CODE_SIGNING_ALLOWED=NO
  ```
- Pure logic is TDD (RED → GREEN → REFACTOR). UI is verified by a Release build
  plus a manual pass; there is no headless check for a SwiftUI settings tab.
- One commit per phase, on the branch.

## Phase 1 — The account model and its keychain items

**Goal.** A typed, tolerant `CredentialAccount` that can never write its token
into `settings.json`, plus per-account keychain read/write/delete.

**Files**
- `native/Shared/CredentialAccount.swift` *(new)*
- `native/Shared/DeckKeychain.swift` *(extend)*
- `native/SharedTests/CredentialAccountTests.swift` *(new)*
- `native/SharedTests/DeckKeychainTests.swift` *(extend)*

**Steps**
1. `enum CredentialKind: String, Codable, CaseIterable { github, azure, opencode }`
   with `displayName` and `systemImage`. Decoding an **unknown** raw value must
   not throw — an account written by a newer build reads as skipped, not as a
   settings reset.
2. `struct CredentialAccount: Codable, Equatable, Identifiable` per the PRD.
   Tolerant `init(from:)` — every field `decodeIfPresent`.
3. **`encode(to:)` omits `token` outright.** This deviates from the codebase
   convention of keeping `encode` symmetric and scrubbing at the file boundary,
   deliberately: the legacy five are a fixed list a human can audit, N accounts
   are not. The scrub in Phase 2 stays as a second, independent guarantee.
4. `struct CredentialsSettings: Codable, Equatable { var accounts: [CredentialAccount] }`
   — tolerant decode; an entry that fails to decode is **dropped, not thrown**.
5. `enum CredentialSlot: String, CaseIterable` with `kind`, `source: FetchSource`,
   `displayName`. This is the replacement for `DeckSecret` at every consumption
   site; `DeckSecret` itself is untouched in this phase.
6. `DeckKeychain.read/write/delete(accountID:service:)` using item name
   `account.<id>.token`. Same `service` override the existing tests use, so no
   test touches the real login keychain.
7. `DeckKeychain.readAll(accounts:)` → `[String: SecretRead]` keyed by id.

**Verification**
- New tests: unknown kind decodes without throwing; a malformed account in an
  array is dropped and its siblings survive; `encode` output contains no `token`
  key; round-trip equality holds ignoring `token`.
- Keychain tests against an override service: write → read `.found`; delete →
  `.absent`; delete of an absent item is `errSecSuccess`; a second write updates.
- `xcodegen generate` **required** (two new files), then the test command.

**Dependencies** — none.

## Phase 2 — Wire the model into `DeckSettings` (🔴 R3, 🔴 R4, 🔴 R5)

**Goal.** Accounts persist, tokens never do, slots resolve, and a keychain
failure stays distinguishable from "never configured".

**Files**
- `native/Shared/DeckSettings.swift`
- `native/Shared/FetchStatus.swift`
- `native/SharedTests/DecodeTests.swift`, `DeckSettingsSecretsTests.swift`,
  `FetchStatusCredentialsTests.swift` *(extend)*

**Steps**
1. Add `var credentials = CredentialsSettings()` to `DeckSettings`, **and its
   case to the hand-written `CodingKeys`, and its `decodeIfPresent` line to the
   explicit `init(from:)`.** (R3 — omitting the `CodingKeys` case compiles,
   decodes as absent and never encodes, so every account vanishes on the next
   keystroke, because `onChange(of: settings)` saves on every mutation.)
2. Add `accountID: String?` to `OpenBoxSettings`, `ShipBoxSettings`,
   `TaskBoxSettings`, `PRGitHubSettings`, `PRAzureSettings` — each with a
   `decodeIfPresent` line.
   **`ShipBoxSettings` has a hand-written `encode(to:)`** (it drops the legacy
   `repo` key); `accountID` must be added there too or ShipBox's selection never
   persists. Same class of bug as R3, different file.
3. **R4:** `scrubbedOfSecrets()` loops `credentials.accounts` blanking each
   `token`, in addition to the five legacy fields (which stay while the legacy
   fallback lives, Phase 3).
4. **R5:** `hydrateAccounts(from: [String: SecretRead]) -> Set<String>` returning
   the ids that **failed**, with the existing rules unchanged: `.found`
   overwrites, `.absent`/`.failed` leave the decoded value alone.
   `hydrateAccountsFromKeychain()` for host-side callers.
5. `func account(for slot: CredentialSlot) -> CredentialAccount?` — returns `nil`
   when the id is unset, dangling, **or points at an account of the wrong kind**.
6. Move `FetchSource` mapping onto `CredentialSlot.source`. `DeckSecret`'s
   mapping stays for the migration and is commented as migration-only.

**Verification**
- Regression tests in `DecodeTests.swift`: a `settings.json` with **no**
  `credentials` key decodes and leaves all fourteen widget sections intact; a
  settings value with two accounts round-trips; an `accountID` survives a
  ShipBox encode/decode cycle (pins step 2's trap).
- `DeckSettingsSecretsTests.swift`: encode a settings value holding the sentinel
  token `"SENTINEL-TOKEN-VALUE"` in an account and assert the sentinel appears
  **nowhere** in the encoded bytes.
- `account(for:)` table test: unset → nil, dangling → nil, kind mismatch → nil,
  match → the account.
- `FetchStatusCredentialsTests.swift` re-pointed at slots; the
  `credentialsUnavailable` vs `notConfigured` distinction still asserted.

**Dependencies** — Phase 1.

## Phase 3 — Migration and the legacy fallback (🔴 R2)

**Goal.** Upgrading changes nothing the user can see, loses no token, and never
re-enables something they had switched off.

**Files**
- `native/Shared/CredentialsMigration.swift` *(new)*
- `native/SharedTests/CredentialsMigrationTests.swift` *(new)*

**Steps**
1. `CredentialsMigration.migrate(_ settings: inout DeckSettings, write:readBack:delete:)`
   — closures injected exactly as `DeckSecretsMigration` does, so no test
   touches the real keychain.
2. **Skip** when `credentials.accounts` is non-empty **or** any slot already has
   an `accountID`. Idempotent by construction.
3. Build a candidate per non-empty legacy secret, pulling connection fields from
   its widget: opencode ← `openbox.serverURL`; azure ← `taskbox.organization/project`
   and `prbox.azure.organization/project`; github ← nothing.
4. **Dedupe within a kind only when every field matches** (token, org, project,
   serverURL). A GitHub token shared by ShipBox and PRBox collapses to one
   account; two different PATs stay two.
5. Ordering per candidate, and it is the safety property: **write
   `account.<id>.token` → read back and confirm → set the slot `accountID`(s) →
   only then delete the legacy keychain item.** Any failure leaves everything
   untouched, deletes nothing, and retries at the next launch.
6. **R2:** for `prboxGitHub` / `prboxAzure`, set `accountID` **only when that
   provider's `enabled` was true**. A disabled provider still gets its account
   created (never lose a token) but stays on `None`, marked `Unused`.
7. Labels: azure → the organization; opencode → the server host; github →
   `"GitHub"`. On a within-kind collision append the widget: `"acme (PRBox)"`.
8. `legacyToken(for slot:) -> String?` — the one-release fallback used when a
   slot has no `accountID` **and** `credentials.accounts` is empty. Without it,
   a user who upgrades and never opens Deck loses four widgets, because
   `DeckAgent` reads settings and never writes them.

**Verification** — TDD, all with injected IO:
- Five legacy secrets → the expected account set; identical GitHub tokens
  collapse to one, differing ones do not.
- `enabled == false` on a PRBox provider → account created, `accountID == nil`
  (pins R2).
- `write` fails → no account, no `accountID`, **legacy item not deleted**.
- `readBack` returns a different value → same, nothing deleted.
- Second run is a complete no-op.
- Labels and collision suffixes.
- Legacy fallback resolves every slot from an unmigrated settings value.
- `xcodegen generate` **required** (two new files).

**Dependencies** — Phase 2.

## Phase 4 — The two extension reads (🔴 R1)

**Goal.** OpenBox and PRBox keep rendering correctly once their fields move onto
accounts. These break **silently** — no crash, no log, just a wrong face.

**Files**
- `native/DeckWidgets/OpenBoxWidget.swift` (line ~101)
- `native/DeckWidgets/PRBoxWidget.swift` (lines ~79-80)

**Steps**
1. `OpenBoxWidget`: `isRemote = settings.account(for: .openbox)?.serverURL.isEmpty == false`
   instead of `!(openboxSettings.serverURL ?? "").isEmpty`. Accounts minus their
   tokens **are** in `settings.json`, so the sandboxed extension can resolve
   this; nothing here needs keychain access, which the extension does not have.
2. `PRBoxWidget`: `githubEnabled = settings.prbox.github.accountID != nil`,
   `azureEnabled = settings.prbox.azure.accountID != nil`.

**Verification**
```bash
xcodebuild -project native/Deck.xcodeproj -scheme DeckApp -configuration Release \
  -derivedDataPath native/build.noindex -allowProvisioningUpdates \
  -allowProvisioningDeviceRegistration build
scripts/lsclean.sh        # after EVERY release build, not only on breakage
rm -rf /Applications/Deck.app && cp -R native/build.noindex/Build/Products/Release/Deck.app /Applications/
```
Then **re-add OpenBox and PRBox from the gallery** and confirm: OpenBox shows
remote data when its account has a server URL and local data on `None`; PRBox
shows a provider's rows exactly when that provider has an account. Widgets must
not regress between builds — re-adding from the gallery is the only real check.

**Dependencies** — Phase 2 (needs `account(for:)`).

## Phase 5 — Consumers: loaders, agent, host refreshers

**Goal.** Every fetch takes its credential from the resolved account, and the
locked-keychain path still reports `credentialsUnavailable` per slot.

**Files**
- `native/Shared/ShipBoxSnapshot.swift`, `TaskBoxSnapshot.swift`,
  `PRBoxSnapshot.swift`, `RemoteOpenCodeLoader.swift` *(entry points only)*
- `native/DeckAgent/main.swift`
- `native/DeckApp/DeckApp.swift` *(the `refresh*` functions)*

**Steps**
1. Introduce `struct ResolvedCredential { let token, organization, project, serverURL: String }`
   built from a `CredentialAccount`, and change the loader entry points from
   `fetch(settings:)` (which reads `settings.token`) to
   `fetch(settings:credential:)`. Display settings stay where they are — repo
   lists, row counts, colours, PRBox's `scope`.
2. Replace `isUsable` / `isAnyProviderUsable` with functions of *settings +
   resolved credential*. `grep` confirms both are read only in
   `DeckAgent/main.swift`, so this is a contained change.
3. Agent: `hydrateAccountsFromKeychain()`; for each slot, resolve the account,
   and choose between `.ok`, `.notConfigured` (no account, dangling account,
   empty token, azure missing org/project) and `.credentialsUnavailable` (the id
   is in the failed set). Fall back to `legacyToken(for:)` where Phase 3 allows.
4. Host app: the same resolution in the ten `refresh*` functions; replace
   `unavailableSecrets: Set<DeckSecret>` with `Set<String>` of account ids.

**Verification**
- Existing `ShipBox*`, `TaskBox*`, `PRBox*`, `FetchStatus*` suites all still
  green after the signature changes.
- New table test: slot state (no account / dangling / empty token / azure missing
  project / keychain failed / healthy) → expected `FetchOutcome`.
- Run the built agent by hand and read the log: `Deck.app/Contents/MacOS/DeckAgent`,
  then `~/Library/Logs/Deck/agent.log`. It logs snapshot names only — never
  tokens, URLs, repos or paths — and that must stay true.

**Dependencies** — Phases 2, 3.

## Phase 6 — Verify probes (🟡 A4)

**Goal.** A per-account Verify that names who the credential belongs to.

**Files**
- `native/Shared/CredentialVerification.swift` *(new)*
- `native/SharedTests/CredentialVerificationTests.swift` *(new)*
- `native/SharedTests/Fixtures/` *(two new JSON fixtures)*

**Steps**
1. **github** — `GET https://api.github.com/user`, `Authorization: Bearer`.
   Parse `login`; read the granted scopes from the `X-OAuth-Scopes` response
   header. The only genuinely new endpoint in this change.
2. **azure** — reuse `HostAzurePRLoader.requireIdentity` against
   `_apis/connectionData?api-version=7.1-preview`; it already exists precisely
   because Azure answers **200 with every active PR in the project** for an
   identity it cannot parse.
3. **opencode** — `RemoteOpenCodeLoader.load(serverURL:token:)`. Success *is* the
   probe and it yields a session count; no new endpoint knowledge.
4. `VerificationResult { identity, detail, verifiedAt }` / a failure carrying the
   existing `FetchOutcome` classification, so the copy matches the widget chips.
5. Editing a token, organization or server URL **clears** `verifiedIdentity`,
   `azureIdentityID` and `verifiedAt`.
6. **A4: the cached `azureIdentityID` is display-only in this change.**
   `HostAzurePRLoader` keeps resolving identity live per fetch and keeps failing
   closed. A GUID cached against a since-replaced token would render the whole
   team's PRs as the user's own, and nothing in the response would say so.

**Verification**
- Parser tests from fixtures: a real-shaped `/user` body → login; a
  `connectionData` body → display name + GUID; a body missing
  `authenticatedUser.id` → **throws** (never a silent unfiltered query).
- Verify is manual-only: assert no probe is issued from `onAppear` anywhere.
- `xcodegen generate` **required** (new files *and* new fixtures — fixtures are
  a `resources:` entry, so a missing regeneration means the test reads nothing).

**Dependencies** — Phase 1.

## Phase 7 — The Credentials tab (🟡 A1, A3)

**Goal.** The tab itself: list, add, edit, verify, delete.

**Files** — `native/DeckApp/DeckApp.swift`

**Steps**
1. `DeckWidget.credentials` case, title "Credentials", `key.fill`. Render it as
   a second row directly under General, **above** the `Widgets` section, and
   exclude it from that section's `ForEach` the same way `.general` is.
2. `CredentialsSettingsView`: one `Form`, `.formStyle(.grouped)`, a `Section` per
   kind, each account a `DisclosureGroup`. No sheet and no second window — the
   window stays 640×500.
3. Row summary: label, verification caption, and **"Used by: ShipBox, PRBox"**
   (or "Unused"), computed from the five slots.
4. **A3:** every account row and every picker row carries a subtitle — the org
   for azure, the host for opencode, the verified login for github, falling back
   to the first six characters of the id. Duplicate labels stay legal; they just
   stop being ambiguous.
5. Toolbar `+` menu: Add GitHub / Add Azure DevOps / Add opencode.
6. **A1:** generalise `SecretField` to take a `write: (String) -> OSStatus`
   closure (keeping the `DeckSecret` convenience for the legacy fields until they
   go). Commit semantics stay **exactly** as they are — on blur and on submit,
   never per keystroke; settings are written on every change, and a per-keystroke
   keychain write is both wasteful and racy.
7. Verify button per account, wired to Phase 6, with a green/red caption.
8. **D7:** `Delete…` confirms naming the using widgets ("Delete 'work'? ShipBox
   and PRBox use it."), then removes the keychain item and the record. Dangling
   ids resolve to `nil` → `notConfigured`, never an error.

**Verification** — Release build, then a manual pass: add one account of each
kind; rename; verify (expect a real identity, and a real 401 for a bad token);
delete one in use and confirm the dialog names the right widgets; reopen the app
and confirm every account survived (this is the R3 canary).

**Dependencies** — Phases 2, 6.

## Phase 8 — Widget tabs become pickers (🟡 A2)

**Goal.** No token, org, project or server URL field remains on a widget tab.

**Files** — `native/DeckApp/DeckApp.swift`

**Steps**
1. A reusable `AccountPicker(kind:selection:onManage:)`: `None` plus the accounts
   of that kind with their subtitles, and a trailing **"Manage in Credentials…"**
   that switches the sidebar. `ContentView` owns `selection`, so pass a closure
   down. When no account of the kind exists the picker is disabled and reads
   "No accounts — add one in Credentials".
2. OpenBox: remove Token and Server URL; add the picker. Caption states the new
   rule plainly — **`None` = local opencode database; an account with a server
   URL = remote**, which is clearer than the old empty-URL convention.
3. ShipBox: remove Token; add the picker. Repo mode, list, counts, colours stay.
4. TaskBox: remove Organization, Project, Token; add the picker. Legend, count,
   state mapping, colours stay.
5. PRBox: **D6** — remove both Enable toggles and all credential fields; each
   provider sub-tab gets a picker. GitHub keeps `scope` (a query filter, not an
   identity).
6. **A2:** re-key `FetchStatusCaption(clearOn:)` from the token string to the
   account id + the account's non-secret fields + `verifiedAt`. That is exactly
   the set of user actions that could have fixed the failure; leaving it on a
   token string that no longer exists on the tab would freeze the chip forever.

**Verification** — Release build + `scripts/lsclean.sh`, install, then walk all
six tabs: every picker lists the right kind only; switching an account changes
what the widget shows within one 60s tick; `None` reads `Not configured`;
"Manage in Credentials…" lands on the tab.

**Dependencies** — Phases 2, 7.

## Phase 9 — Docs and release

**Goal.** The model is written down where the next agent will read it.

**Files** — `CLAUDE.md`, `README.md`, `ROADMAP.md`, `native/project.yml`,
`homebrew/`

**Steps**
1. `CLAUDE.md`: the accounts model in Architecture (credentials are records,
   widgets reference them by id, keychain item is `account.<id>.token`), plus a
   trap entry for R1 — *two extension reads moved onto accounts and would have
   failed silently*.
2. `README.md`: a Credentials section. **The keychain caveat is reproduced
   unchanged** — confidentiality at rest, not isolation from other local
   processes. Nothing about this change improves that, and the README must not
   imply it does.
3. `ROADMAP.md`: entry under the keychain item, recording D1–D7 and what the
   critique caught.
4. Version bump in `native/project.yml`. No widget is added, so the descriptor
   cache trap does not apply — the bump is for the release, not the gallery.
5. Full green: `DeckSharedTests` + Release build + `scripts/lsclean.sh`.

**Dependencies** — Phases 1-8.

## Risk register

| Risk | Phase | Guard |
|---|---|---|
| New file not compiled, suite still "passes" | all | `xcodegen generate` before every build in a phase that adds a file |
| Accounts vanish on save (missing `CodingKeys` case) | 2 | Round-trip test; the Phase 7 reopen-the-app canary |
| ShipBox selection never persists (hand-written `encode`) | 2 | Dedicated encode/decode test |
| Live token written to `settings.json` | 1, 2 | `encode` omits `token` **and** scrub loops accounts; sentinel-grep test |
| A disabled PRBox provider silently switched on | 3 | `enabled == false` migration test |
| OpenBox stuck local / PRBox stuck off | 4 | Re-add both from the gallery |
| Token lost during migration | 3 | write → readback → set → delete, with failure tests at each step |
| Whole team's Azure PRs shown as the user's | 6 | Cached GUID is display-only; live resolution keeps failing closed |
| Upgraded-but-never-opened Deck loses four widgets | 3, 5 | `legacyToken(for:)` fallback for one release |
