# Plan: shipbox-inventory-pagination

2026-09-13. PRD: `docs/planning/shipbox-inventory-pagination/prd.md` (approved).
Type: loader + policy feature. No UI. TDD throughout; every phase ends green.

Conventions honoured: pure logic gets its tests with the code; the loader owns
nothing but the fetch; the store owns persistence; `xcodegen generate` after
ANY new source file (a new test file silently drops out of the suite
otherwise — the trap in CLAUDE.md).

## Phase 1 — Link header parser + pagination driver (pure, RED first)

**Goal:** a same-origin, capped page walker for the picker's inventory.

**Files:** `native/Shared/ShipBoxSnapshot.swift` (new `LinkHeaderParser`,
`InventoryPaginator` enums) · `native/SharedTests/ShipBoxInventoryTests.swift`
(new) · `native/SharedTests/Fixtures/` (Link header fixture strings, inline).

**Steps**

1. RED — `ShipBoxInventoryTests`:
   - `LinkHeaderParser.next(from:)`: parses `rel="next"` from a single-link
     header; from a multi-link header (`next` in the middle); `nil` when
     absent; `nil` when only `rel="last"`; `nil` on malformed input (no angle
     brackets, empty); `nil` when the link host is not `api.github.com`
     (a hostile header must never carry the token elsewhere — the
     `DeckURLForwarding` host-filter precedent).
   - `InventoryPaginator.allPages(maxPages:fetchPage:)`: one page; three
     pages in order (page 1's repos stay ahead of page 2's); stops at the cap
     (5); propagates a throwing page.
2. GREEN — implement both enums. `LinkHeaderParser` splits on commas, finds
   the `rel="next"` parameter, and validates the URL: absolute, host
   `api.github.com` (the exact host `get` already targets). `InventoryPaginator`
   is a plain loop — serial by definition, you cannot know the next URL before
   the current response.
3. REFACTOR — keep both pure; no loader changes yet.

**Verification:** `xcodegen generate` (new test file), then
`xcodebuild test -project native/Deck.xcodeproj -scheme DeckSharedTests
-derivedDataPath native/build.noindex` — the new suite green.

**Dependencies:** none.

## Phase 2 — Cache record, policy, store (pure, RED first)

**Goal:** the cross-tick state: versioned record, freshness/identity policy,
atomic store.

**Files:** `native/Shared/ShipBoxSnapshot.swift` (new `ShipBoxInventoryCache`
record, `InventoryCachePolicy`, `InventoryCacheStore`) ·
`native/SharedTests/ShipBoxInventoryTests.swift` (extend).

**Steps**

1. RED — tests first:
   - `InventoryCachePolicy.decision(age:accountMatches:affiliationMatches:)`:
     fresh (age 0…599s) + matches → `.useCache`; 600s → `.refresh`; 601s →
     `.refresh`; **negative age (fetchedAt in the future) → `.refresh`**
     (PRD C4); account mismatch → `.refresh`; affiliation mismatch →
     `.refresh` (PRD C4/C3 — a picker-written default-affiliation record
     must never feed dynamic discovery).
   - `ShipBoxInventoryCache` Codable round-trip (JSONEncoder → JSONDecoder
     → equal fields; `fetchedAt` survives as a `Date`).
   - `InventoryCacheStore.load(from:)`: nil for a missing file; nil for
     corrupt JSON; nil for a future `version`; the record for a valid file.
     `save(_:to:)` writes and `load` reads it back. Temp-dir style of
     `AtomicFileTests`.
2. GREEN — implement. `InventoryCachePolicy.refreshInterval` is the 600 s
   constant (the interview decision). `InventoryCacheStore` mirrors
   `OpenCodeSyncStore` (`RemoteOpenCodeSync.swift:169-184`): default
   `fileURL = DeckSettings.containerDirectory.appendingPathComponent("shipbox-inventory.json")`,
   but `load(from:)` / `save(_:to:)` take the URL as a parameter so the tests
   drive a temp directory (the `AtomicFileTests` seam — the container
   directory is not writable by the test bundle).
3. REFACTOR — version bump rule: any future schema change raises
   `ShipBoxInventoryCache.currentVersion` and old files read as absent
   (self-healing, the `OpenCodeSyncStore` precedent).

**Verification:** test suite green (same command as Phase 1).

**Dependencies:** none.

## Phase 3 — Loader wiring: paginated picker + cache-aware discovery (RED, then integration)

**Goal:** `repoInventory` walks pages and warms the cache; dynamic discovery
reads the cache and never misreports a dead token; both call sites pass the
account id.

**Files:** `native/Shared/ShipBoxSnapshot.swift` (loader) ·
`native/SharedTests/ShipBoxDiscoveryTests.swift` (extend) ·
`native/DeckAgent/main.swift:205` · `native/DeckApp/DeckApp.swift:410,2291`.

**Steps**

1. RED — extend `ShipBoxDiscoveryTests` with the C1 regression:
   `DynamicRepoSelector.allProbesFailed([.failure × n])` is true; false when
   any probe succeeded (even with zero runs); false on an empty probe list.
   The rule: **candidates non-empty AND every probe failed → throw the first
   probe error** (PRD §3.3 — a revoked token with a fresh cache must be
   `.authOrTarget`, never `.notConfigured`).
2. GREEN — loader changes, bottom up:
   - `get` gains a `getResponse` sibling returning `(Data, HTTPURLResponse)`
     (the Link header lives in response headers, which `get` discards); `get`
     delegates. `PRBoxSnapshot.swift` has its own private copy of the request
     shape — untouched.
   - `repoInventory(token:accountID:)`: paginated via `InventoryPaginator`
     (max 5 pages, `per_page=100`, default affiliation — unchanged scope),
     then `InventoryCacheStore.save` a default-affiliation record (best
     effort — a failed write degrades to "no cache").
   - `fetch(settings:token:accountID:)`: dynamic mode passes the account id
     to `discover`.
   - `discover(maxCount:token:accountID:)`: load the cache; ask the policy;
     `.useCache` → zero inventory requests; `.refresh` → live page 1
     (`affiliation=owner`), **save the cache record on success**, throw on
     failure (today's behavior — PRD §3.2); then candidates → probes → the
     C1 rule (throw the first error when every probe failed) → `select`.
     `DynamicRepoSelector.candidates`/`select` keep their signatures.
3. Call sites:
   - `DeckAgent/main.swift:205` — `fetch(settings: shipbox, token: credential.token, accountID: credential.id)`.
   - `DeckApp/DeckApp.swift:410` — same.
   - `DeckApp/DeckApp.swift:2291` — `repoInventory(token: token, accountID: accountID ?? "")`
     (`ShipBoxSettingsView` already carries both, `DeckApp.swift:2143-2148`).
4. REFACTOR — the private one-page `inventory(token:)` becomes the refresh
   step inside `discover`; the public `repoInventory` no longer shares it.

**Verification:** full test suite green; `xcodebuild` Release build of
`DeckApp` succeeds. Live check (installed copy — the only place SMAppService
registers): run `/Applications/Deck.app/Contents/MacOS/DeckAgent` with the
settings in dynamic mode and observe, in the container dir, that
`shipbox-inventory.json` appears with the owner affiliation and
`shipbox.json` keeps advancing every tick. **Confirm zero extra requests on
a warm-cache tick** via the cache file's mtime (must not advance between two
ticks ≤ 10 min apart) — this account's 31 repos have no `Link` header, so
pagination is provable only by the unit tests (PRD §7).

**Dependencies:** Phases 1–2.

## Risks

| Risk | Mitigation |
|---|---|
| Pagination unverifiable live (31 repos, no `Link` header) | Unit tests are the verification; the live check observes the *absence* of extra requests |
| C1 regression (dead token → `.notConfigured`) | The all-probes-failed rule is extracted pure and unit-pinned in Phase 3 step 1, before the loader changes |
| Picker cache poisoning dynamic mode | Affiliation is part of the cache identity (PRD C4, Phase 2 test) |
| Two writers race on the cache | `AtomicFile` whole-file writes; last writer wins; every read validates version + account + affiliation |
| Store I/O untestable (container dir) | `load(from:)`/`save(_:to:)` take the URL; tests use a temp dir (`AtomicFileTests` style) |
