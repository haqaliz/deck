**Steps (TDD):**

## Phase 3 — Provider applies the pin

**Goal:** Widget shows only the pinned interface (totals, chart history,
list, small-face ACTIVE row); falls back to auto when the pin vanishes.

**Files touched:**
- `native/DeckWidgets/NetBoxWidget.swift` (`NetBoxProvider.makeEntry`)

**Steps:**
1. Load settings first: move `DeckSettings.load()` to the top of `makeEntry`.
2. After computing `rates`, apply
   `let filtered = NetBoxPinnedInterface.select(pinned: settings.pinnedInterface, interfaces: rates)`.
3. Compute `totalUp`/`totalDown`, history sample, and the sorted/truncated
   list from `filtered` instead of `rates`.
4. `entry.settings` reuses the already-loaded settings.

**Verification:** build passes; DeckSharedTests green (logic covered by Phase 1);
manual: install build, pin `en0`, confirm small ACTIVE + totals + list show only
`en0`; turn Wi-Fi off → auto fallback; back on → pin re-engages.

**Dependencies:** Phase 2.

real interfaces, pin one, reopen → still pinned; picker shows stored value even

## Risks / notes

- Moving `NetworkMetricsLoader` touches the widget + test targets only;
  `DeckAgent` does not use it — no agent impact (PRD non-goal respected).
- `select()` fallback is silent by design: the stored pin is never rewritten,
  so the pin re-engages when the interface returns (PRD acceptance).
- Real-machine `sample()` intentionally not unit-tested (interface names vary);
  the option-list filter (`rx+tx > 0`) is exercised manually in Phase 4.
