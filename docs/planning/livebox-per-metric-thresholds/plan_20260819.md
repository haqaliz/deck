## Phase 1 — Settings keys + migration decode

**Goal:** `LiveBoxSettings` carries six per-metric threshold keys with a
legacy-fallback tolerant decode.

**Files:** `native/Shared/DeckSettings.swift`, `native/SharedTests/DecodeTests.swift`

**Steps:**

1. In `LiveBoxSettings` (DeckSettings.swift:75-117), replace the stored
   `warnThreshold` / `alarmThreshold` properties with six: `cpuWarnThreshold`,
   `cpuAlarmThreshold`, `memWarnThreshold`, `memAlarmThreshold`,
   `diskWarnThreshold`, `diskAlarmThreshold` — all `Int`, defaults 80/90.
2. Keep the legacy `warnThreshold` / `alarmThreshold` cases in `CodingKeys`
   (decode-only). In `init(from:)`, decode each new key with the fallback chain
   `decodeIfPresent(newKey) ?? decodeIfPresent(legacyKey) ?? default` — e.g.
   `cpuWarnThreshold = try c.decodeIfPresent(Int, .cpuWarnThreshold) ??
   c.decodeIfPresent(Int, .warnThreshold) ?? 80`. Legacy keys are read from the
   container only; they are NOT stored, so the synthesized `encode` writes only
   the six per-metric keys.
3. Keep the existing unrelated keys/decodes untouched (showChart, showCPU, …,
   colors, per-volume, process cadence).

**Verification (TDD — write tests first):** in `DecodeTests.swift`, extend the
LiveBox suite:

- Old file with only legacy keys (`{"warnThreshold":85,"alarmThreshold":92}`) →
  all three metrics inherit 85/92.
- No threshold keys → 80/90 defaults for all six; other keys still load.
- New-format file with per-metric keys → round-trips exactly.
- Mixed file (one per-metric key present, others absent) → present kept, absent
  fall back to legacy/default.
- Encoded output omits legacy keys (encode → JSON string has no
  `"warnThreshold"` / `"alarmThreshold"`).
- Existing keys (e.g. `showPerCoreCores`, `processRefreshInterval`) still decode
  and encode.

`xcodebuild test … DeckSharedTests` green.

## Phase 2 — Pure metric-tier resolver (Shared)

**Goal:** a testable resolver that maps a metric + value + settings to a
`ThresholdTier`.

**Files:** `native/Shared/LiveBoxCore.swift`, new
`native/SharedTests/LiveBoxThresholdTests.swift`

**Steps:**

1. Add to `LiveBoxCore.swift`:
   `enum LiveBoxMetric { case cpu, mem, disk }` and
   `enum LiveBoxThresholdTier { static func tier(metric:value:settings:) ->
   ThresholdTier }` returning `ThresholdTier.tier(value:value, warn:Double(pair.warn),
   alarm:Double(pair.alarm))` using the metric's own pair. Shape mirrors
   `NetBoxThresholdTier` (NetBoxCore.swift:85-92); do NOT modify `ThresholdTier`.
2. No `warn > alarm` special-casing here — `ThresholdTier` already defines alarm
   wins (LiveBoxCore.swift:16).

**Verification (TDD):** new `LiveBoxThresholdTests.swift`:

- Each metric resolves from its own pair (cpu/mem/disk values at the same number
  tier differently when pairs differ).
- Boundary per metric: below-warn normal, at-warn warn, at-alarm alarm.
- Alarm wins when a metric's warn > alarm.
- Default settings (80/90) behave like today's single pair.

`xcodebuild test … DeckSharedTests` green. Regenerate the project first
(`xcodegen generate`) so the new test file is picked up.
