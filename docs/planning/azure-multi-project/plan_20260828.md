# Implementation plan — azure-multi-project

From `prd.md` (approved 2026-08-28). Branch `feat/azure-multi-project/aliz`,
worktree `.claude/worktrees/feat-azure-multi-project`.

## Conventions for every phase

This is an **xcodegen** project, not SwiftPM — the `swift build` / `swift run`
verbs in the generic skill template do not apply here.

```bash
# after adding ANY new source or test file (xcodegen enumerates at generation
# time, so a new test file is otherwise silently not compiled and the suite
# still reports success):
xcodegen generate --spec native/project.yml

# the per-phase gate:
xcodebuild -project native/Deck.xcodeproj -scheme DeckSharedTests \
  -configuration Debug -derivedDataPath native/build.noindex test
```

Every phase ends with that suite green and one commit. TDD throughout: the
tests in each phase's step 1 are written and **failing** before its
implementation steps.

Baseline confirmed green on this worktree before phase 1.

## Phase 1 — Probe `_apis/projects` (the PRD's one accepted risk)

**Goal.** Replace the documented-shape assumption with a captured payload
before anything is built on top of it.

**Files touched.** None (throwaway script in the scratchpad;
`docs/planning/azure-multi-project/probe.md` records the result).

**Steps.**
1. Read the existing TaskBox PAT from the login keychain the same way Deck
   does (`DeckKeychain`, service `com.deck.app`, item `account.<id>.token`) —
   no new credential is requested from the user.
2. `GET https://dev.azure.com/ForesightAnalytics/_apis/projects?api-version=7.1&$top=200`
   with Basic auth; capture status, `count`, and the key set of `value[0]`.
3. Answer three questions in `probe.md`: does a Work Items (Read) PAT get a
   200 here at all; is the display name at `value[].name`; how many projects
   does this org actually have (it sizes the cap-5 decision).

**Verification.** A captured payload pasted into `probe.md`, and a fixture file
derived from it for the phase 7 parser tests.

**Dependencies.** None. **Blocks phase 7** only — phases 2–6 do not depend on
it, so a 403 here does not stall the work; it just makes the free-text fallback
the primary path instead of the corner case.

## Phase 2 — `projects` on the account, and the Verify fingerprint

**Goal.** One account carries up to five projects, on disk and in memory,
without stranding an existing single-project account.

**Files touched.**
`native/Shared/CredentialAccount.swift`,
`native/Shared/CredentialVerification.swift`,
`native/SharedTests/CredentialAccountTests.swift` (new or extended).

**Steps.**
1. **Tests first.** `AzureAccountProjects.normalise`: trims, drops empties,
   de-duplicates case-insensitively keeping the first spelling, caps at 5,
   preserves order. Account decode: `{"projects": [...]}` round-trips;
   `{"project": "X"}` (legacy) yields `["X"]`; `{"project": ""}` yields `[]`;
   neither key yields `[]`. Account encode: writes `projects` and **does not**
   write `project` (CLAUDE.md — a moved field must clear the old copy).
   Fingerprint: differs when a project is added or removed, and is **equal**
   when the same projects are re-ordered.
2. Add `enum AzureAccountProjects { static let maxProjects = 5; static func normalise(_:) }`.
3. `var project: String` → `var projects: [String]`; hand-written `init(from:)`
   gains the legacy fallback, `encode(to:)` writes only `projects`.
4. `CredentialIdentity` fingerprint joins the normalised list, sorted+lowercased
   for hashing only (PRD C1).
5. `CredentialVerification.azure` passes `projects.first ?? "_"` (PRD C2).

**Verification.** The suite. Compile errors elsewhere are expected at this point
and are the map for phases 3–6 — do not paper over them with a computed
`project` shim, which would keep the single-project path alive behind the new
one.

**Dependencies.** None.

## Phase 3 — `ResolvedCredential` and the gate go plural

**Goal.** The one decision table answers for N projects without changing what
`off` / `notConfigured` / `unavailable` mean.

**Files touched.** `native/Shared/CredentialsMigration.swift`,
`native/SharedTests/CredentialGateTests.swift`.

**Steps.**
1. **Tests first.** Azure slot with org + 2 projects → `.fetch` carrying both;
   org + zero usable projects → `.notConfigured`; empty org → `.notConfigured`;
   unavailable account id → `.unavailable` (unchanged); nothing selected and no
   legacy token → `.off` (unchanged); legacy `taskbox.project = "X"` with no
   account → `.fetch(["X"])`; six projects → capped to five.
2. `ResolvedCredential.project: String` → `projects: [String]`.
3. `legacyCredential(for:)` wraps the pre-accounts string in a one-element list
   for `.taskbox` and `.prboxAzure`.
4. The Azure branch of `gate` normalises through `AzureAccountProjects` and
   requires org + at least one project.

**Verification.** The suite. **Dependencies.** Phase 2.

## Phase 4 — TaskBox loader

**Goal.** N projects, 1 + N requests, correct per-row links, honest partial
failure.

**Files touched.** `native/Shared/AzureDevOpsLoader.swift`,
`native/Shared/TaskBoxSnapshot.swift`,
`native/SharedTests/AzureDevOpsLoaderTests.swift`,
`native/SharedTests/TaskBoxSnapshotTests.swift`.

**Steps.**
1. **Tests first.**
   - `AzureTargets.normalise(organization:projects:)` → one target per project,
     each percent-encoded; empty list throws `invalidTarget`.
   - Round-robin interleave: `[[1,2,3,4],[5],[6,7]]` → `[1,5,6,2,7,3,4]`;
     truncation at 200 takes from every project, not the first (feed 3×150 ids
     and assert every project is represented in the 200).
   - `WorkItemParser` reads `System.TeamProject` into `TaskItem.project` and
     builds `url` from **that** project, not from the passed target; a row with
     the field absent falls back to the target and `project == nil`.
   - `TaskItem` / `TaskBoxSnapshot` decode without `project` / `note` (older
     agent) and round-trip with them.
   - Scope/sprint rules: 1 project → today's `AzureTarget.scope` and a sprint;
     2 projects → org name and `sprint == nil`.
   - Partial failure: 1 of 3 projects failing yields the other two's rows plus
     a `note` naming the failure; **all** failing throws.
2. `TaskItem.project: String?`, `TaskBoxSnapshot.note: String?`, both
   `decodeIfPresent`.
3. Add `System.TeamProject` to the batch `fields` list; keep `errorPolicy: omit`.
4. `HostAzureDevOpsLoader.fetch(organization:projects:token:)`: concurrent
   per-project WIQL via `withThrowingTaskGroup` (follow
   `HostGitHubLoader.inParallel`), sprint only when exactly one target,
   interleave → cap 200 → one org-scoped batch, `totalCount` summed.
   The `[System.TeamProject] = @project` clause **stays** in the WIQL.

**Verification.** The suite, plus a live run in phase 10.
**Dependencies.** Phase 3.

## Phase 5 — PRBox loader

**Goal.** N projects behind one identity call, with row ids that cannot collide.

**Files touched.** `native/Shared/AzureDevOpsLoader.swift`,
`native/Shared/PRBoxSnapshot.swift`,
`native/SharedTests/PRBoxSnapshotTests.swift`, `.../AzureDevOpsLoaderTests.swift`.

**Steps.**
1. **Tests first.** Two projects each with a repo named `api` and a PR #12
   produce **two distinct ids** (this is the 🔴 regression test — assert on a
   `Set(ids).count`, which is what a duplicate `ForEach` key would collapse);
   `PullRequestItem.project` populated; `webURL` built from the item's own
   project; `vote == 0` filtering and `$top` ceiling unchanged; totals sum per
   role and capped flags OR; all-projects-fail throws, some-fail notes.
2. `PullRequestItem.project: String?` (`decodeIfPresent`).
3. `id` becomes `"azureDevOps:\(project)/\(repo)#\(number)"`.
4. `HostAzurePRLoader.fetch(organization:projects:token:cap:)`: one
   `connectionData` call, `requireIdentity` **unchanged and still without a
   fallback**, then 2N concurrent role queries each parsed against its own
   target.

**Verification.** The suite. **Dependencies.** Phase 3 (independent of 4).

**Steps.**

## Phase 8 — Settings UI

**Goal.** Five project slots that degrade gracefully.

**Files touched.** `native/DeckApp/DeckApp.swift` (account editor ~`:1253`,
TaskBox tab, PRBox Azure sub-tab, copy at ~`:2034`),
`native/Shared/DeckSettings.swift` (`showProject` on TaskBox + PRBox Azure).

**Steps.**
1. `showProject: Bool = false` on `TaskBoxSettings` and `PRBoxSettings.azure`,
   with tolerant decode and a decode test (the CLAUDE.md rule that adding a
   section must not reset the file).
2. Account editor: the `Project` field becomes five slots — a picker over the
   discovered list when discovery has succeeded, a text field pre-filled from
   the stored value otherwise. Discovery runs on demand, never on the agent tick.
3. `Show project on rows` toggles, pinned right, default off, on both tabs.
4. Reword `:2034` ("in that account's project only").

**Verification.** Release build + install + open Deck; add a second project,
confirm `settings.json` carries `projects` and no `project`, and that an
existing account is unchanged until edited.
**Dependencies.** Phases 6, 7.

## Phase 10 — Live verification

**Goal.** Prove it against the real org, and prove the single-project path did
not move.

**Steps.**
1. Configure `ForesightAnalytics` with `ForesightManifold` + `Manifold`.
2. TaskBox: per-project counts add up to the org total the PRD expects (the
   probe measured 67 across three projects vs 25 in one); every row's link
   opens its **own** project; header shows the org and no sprint.
3. PRBox: no duplicate/missing rows; each row's link resolves; a same-named repo
   in both projects renders twice, distinctly.
4. Remove one project → face returns to the single-project layout, sprint chip
   back, and the Verify badge invalidates (C1).
5. Break one project name deliberately → the other project still renders, with
   a note naming the broken one; break both → the fetch chip reports the failure.
6. Watch the timeline archive size under
   `~/Library/Containers/com.deck.app.widgets/Data/SystemData/com.apple.chrono/timelines/`
   (the CalBox blank-widget tell).

**Dependencies.** Phase 9.
