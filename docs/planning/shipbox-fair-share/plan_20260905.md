## Phase 1 — Pure rule: `ShipBoxMerge.fairMerge` (TDD)

**Goal:** the round-robin interleave, pure and unit-pinned, with today's
merge untouched.

**Files touched:**

- `native/Shared/ShipBoxSnapshot.swift` — new sibling `ShipBoxMerge.fairMerge`
  beside `ShipBoxMerge.merge` (line 160-176). Same signature

- `native/SharedTests/ShipBoxMergeTests.swift` — new test cases (existing
  tests untouched; `merge` behavior is pinned as-is).

**Steps** (RED → GREEN per test, then refactor):

1. Write the tests first, all against the not-yet-existing `fairMerge`:
   - **Fairness:** 3 repos with 1+ runs each → every repo's newest run sits
     in the first 3 positions of the merged list.
   - **Newest first:** `fairMerge(...).first` is the globally newest run
     (mixed timestamps across repos).
   - **Round-robin:** repo A runs at t=100, t=99; repo B at t=98 →
     order is A(100), B(98), A(99) — B's newest outranks A's history.
   - **Intra-repo order:** a repo's own runs stay newest-first.
   - **Degradation:** one repo → identical to `merge`; empty input → `[]`;
     repos with fewer runs than the level depth are skipped, not padded.
   - **Stability:** two runs at the same `createdAt` from different repos
     keep fetch order (repo order) across repeated calls.
   - **Level consumption:** with `k` repos and total runs `n`, no repo
     contributes more than `ceil(n / k)` runs before every other repo's
     runs are exhausted — the property that makes today's
     `per_page = max(runCount, 2)` provably sufficient (PRD §3, critique
     amber 2).
2. Implement `fairMerge`: level-by-level (`enumerated()` over the longest
   repo list), each level = every repo's run at that index, sorted by
   `createdAt` descending with ties broken by repo fetch order — mirroring
   `merge`'s stability rule.
3. Refactor only if the two functions share a comparator worth extracting;
   do not change `merge`.
