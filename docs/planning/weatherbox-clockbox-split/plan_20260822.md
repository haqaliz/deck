## Build & test commands (this repo is xcodegen, NOT SwiftPM)

The `deck-plan` skill's template refers to `Sources/`, `Package.swift` and
`swift run <Widget> --debug-flip` — all from the retired floating-panel
architecture. CLAUDE.md is authoritative. The real commands:

```bash
xcodegen generate --spec native/project.yml          # after ANY new source file
xcodebuild -project native/Deck.xcodeproj -scheme DeckSharedTests \
  -destination 'platform=macOS' test                 # unit tests
xcodebuild -project native/Deck.xcodeproj -scheme DeckApp -configuration Release \
  -derivedDataPath native/build.noindex -allowProvisioningUpdates build
./scripts/lsclean.sh                                 # after EVERY release build
```

`xcodegen generate` is not optional after adding a file: xcodegen enumerates
sources at generation time, so a new test file that skips it is **silently not
compiled and the suite still reports success** (critique A4).

## Phase 0 — Spike: does `Text(_:style:)` honour `\.timeZone` in a widget?

**Goal:** resolve critique R1 before any layout depends on it.

Throwaway. Add a temporary second face to an existing widget rendering
`Text(Date(), style: .time).environment(\.timeZone, TimeZone(identifier: "Asia/Tehran")!)`

**Verification:** visual, against `TZ=Asia/Tehran date +%H:%M`.

## Phase 2 — ClockBox pure core (TDD, no UI)

**Goal:** all clock logic as pure functions, fully tested, before any view.

**Files:** `native/Shared/ClockBoxCore.swift` (new),
`native/SharedTests/ClockBoxTests.swift` (new),
`native/SharedTests/HomeBoxSnapshotTests.swift` (remove `ZoneRowsTests`)

1. `ClockCity` — display name + IANA id; `ClockBoxCities.curated` static table
   of major cities ("Toronto, Canada" -> `America/Toronto`).
2. `ClockBoxCore.resolve(id:)` — maps an id to a `TimeZone`, special-casing the
   `"local"` sentinel to `TimeZone.current` labelled with its own city name
   (critique A1). Invalid ids return nil and are dropped.
3. `ClockBoxCore.offsetLabel(zone:relativeTo:at:)` — uses
   `secondsFromGMT(for: date)` on **both** zones and subtracts, so DST is
   correct year-round and the two zones may shift on different dates
   (critique A2). Formats `±H:MM` with exact minutes; renders `+0HRS` at zero.
   Tests must cover Kathmandu `+5:45` and a DST boundary date.
4. `ClockBoxCore.relativeDay(zone:relativeTo:at:)` — `Yesterday`/`Today`/
   `Tomorrow` by comparing calendar dates in each zone.
5. `ClockBoxCore.rows(ids:at:)` — resolves, drops invalid, caps at 4.
6. `ClockBoxCore.smallCity(ids:)` — first **non-local** city, falling back to
   local only when it is the sole entry (critique A3).
7. Move the 7 `ZoneRowsTests` assertions into `ClockBoxTests` against the new
   API; delete `ZoneRows`/`ZoneRow` from `HomeBoxSnapshot.swift`.

**Verification:** `xcodegen generate` **then** the test scheme. Record the
before/after test count — a rising count is the proof the new file is actually
compiled (critique A4). Green is not sufficient evidence on its own.
**Dependencies:** none (parallel with Phase 1).

## Phase 3 — Settings schema: rename + new section

**Goal:** `homebox` -> `weatherbox`, add `clockbox`, migrate zones to cities,
without resetting anyone's settings.

**Files:** `native/Shared/DeckSettings.swift`,
`native/SharedTests/DecodeTests.swift`

1. `HomeBoxSettings` -> `WeatherBoxSettings`; drop `timezoneIDs` and
   `showZones`.
2. New `ClockBoxSettings`: `cityIDs: [String] = ["local", "UTC"]`,
   `showRelativeDay = true`, `showOffset = true`, `timeColor`. Tolerant
   `init(from:)` like every other section.
3. Explicit `CodingKeys` on `DeckSettings` for the current schema, plus
   `private enum LegacyCodingKeys` used for a **second** keyed container that
   reads the old `homebox` blob — this is the only shape that both compiles and
   keeps the encoder correct (critique R2).
4. Migration on decode: absent `weatherbox` + present `homebox` -> carry
   `location`/`unitsFahrenheit`/`showForecast` across, and carry
   `homebox.timezoneIDs` into `clockbox.cityIDs` (old cap 3 < new cap 4, so
   nothing truncates).
5. Extend the Phase 1 round-trip test to the two new sections.
6. New test: decode a real pre-rename `settings.json` fixture, assert location,
   units and zones all survive.

**Verification:** test scheme, plus a manual decode of a copy of the live
`settings.json`.
**Dependencies:** Phase 1 (shares the initializer).

## Phase 4 — ClockBox widget face

**Goal:** the widget renders at all three families.

**Files:** `native/DeckWidgets/ClockBoxWidget.swift` (new),
`native/DeckWidgets/DeckWidgets.swift`, `native/project.yml`

1. `ClockBoxWidget` with `kind = "ClockBoxWidget"`, three families.
2. Face per Phase 0's outcome: self-updating `Text` if the spike passed,
   otherwise minute-boundary entries.
3. Small = `smallCity`; medium/large = up to 4 columns (name, time, day,
   offset). Shell conventions: rounded system fonts, monospaced digits,
   section titles tracked 1pt, `containerBackground { Color.clear }`.
4. Empty state when no cities are selected — never a blank widget.
5. Register in the bundle; **bump `CFBundleShortVersionString` 1.15 -> 1.16 and
   `CFBundleVersion` 15 -> 16 in all three places** in `project.yml`. Without
   this the widget never appears in the gallery, while everything else looks
   healthy.

**Verification:** `xcodegen`, Release build, install, `./scripts/lsclean.sh`,
`pluginkit -m -i com.deck.app.widgets`, then
`log show --last 2m --info --debug --predicate 'process == "chronod"' | grep -c ClockBoxWidget`
— zero means the descriptors are stale despite the bump. Add at all 3 sizes.
**Dependencies:** Phases 0, 2, 3.

## Phase 8 — Full uninstall / reinstall verification

Per the user's standing instruction, verification is a complete removal and
reinstall, not an in-place upgrade. Back up `settings.json` to
`~/Deck-settings-backup-<date>.json` first — it carries three live tokens, and
this is a git worktree, so the backup must NOT land in the repo.

Sequence, removal artifacts confirmed present on this machine:
`launchctl bootout gui/502/com.deck.agent`; remove
`~/Library/LaunchAgents/com.deck.agent.plist`, `/Applications/Deck.app`, and
the containers `com.deck.app`, `com.deck.app.widgets`, `com.deck.widgets` (the
third is a stale older bundle id); `lsregister -u` every Deck bundle while the
app is absent; `rm -rf native/build.noindex`. Then rebuild, install, launch,
`lsclean.sh`, restore settings, re-add all 12 widgets.

Expect: empty LiveBox/NetBox/BatBox charts (history files are gone) and a
re-prompt for calendar + "data from other apps" access.

**User steps that cannot be automated:** removing widgets from the desktop
beforehand, re-adding them afterwards, clicking Allow on both prompts.
