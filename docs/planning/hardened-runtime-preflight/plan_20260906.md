# Implementation plan — hardened-runtime pre-flight (2026-09-06)

From `prd.md` + its self-critique (2 red, 6 amber; every fix is a numbered step
below). Five phases. Phases 1–3 are code and end green; phase 4 is the
measurement the whole slice exists for; phase 5 writes down what was learned.

**Commands are this repo's, not SwiftPM's.** `deck-plan`'s template assumes
`swift build` / `swift run --debug-flip`; Deck is an xcodegen project, so
verification uses `xcodebuild` and the install ritual from CLAUDE.md.

**Rollback, available from the first commit:** `$SCRATCH/baseline-Deck.app`
(v1.40, `flags=0x0(none)`, `CDHash=155a9e3e…`), built and preserved before any
change. Reverting is `rm -rf /Applications/Deck.app && cp -R` that, then
`scripts/lsclean.sh` and a launch. The container is never touched.

## Phase 1 — The drift guard, failing first (RED)

**Goal.** A test that fails on today's tree and names all three offending
targets, so the fix in phase 2 is proven rather than asserted.

**Files touched**
- `native/Shared/HardenedRuntimeAudit.swift` *(new — pure)*
- `native/SharedTests/HardenedRuntimeTests.swift` *(new)*

**Steps**

1. Write `HardenedRuntimeAudit`: a pure function over the **text** of
   `project.yml` returning, per target, one of `.enabled` / `.disabled` /
   `.absent`. It enumerates the targets it finds under `targets:` rather than
   taking a list — critique A2: a hardcoded triple cannot catch the fourth
   target somebody adds next year.
2. `audit(yml:).offenders(exempting: ["DeckSharedTests"])` returns every target
   that is not `.enabled`. `DeckSharedTests` is the **only** exemption and is
   named in the call, not hidden in the parser: a test bundle is not notarized,
   and that fact should be visible at the call site.
3. Unit-test the pure function against four inline YAML fixtures — all enabled;
   one `NO`; one with the key absent; a fourth target added with no key — so all
   three broken shapes are demonstrated without mutating the real file.
4. One test applies it to the real `native/project.yml`, reached through
   `#filePath` exactly as `DeckBundleTests` reaches it (the DeckSharedTests
   scheme builds only its own target, so the product directory has no `Deck.app`
   to read).
5. `xcodegen generate --spec native/project.yml` — **required**: xcodegen
   enumerates sources at generation time, so a new test file is otherwise
   silently not compiled and the suite still reports success (CLAUDE.md).

**Verification**

```bash
xcodegen generate --spec native/project.yml
xcodebuild test -project native/Deck.xcodeproj -scheme DeckSharedTests \
  -derivedDataPath native/build.noindex CODE_SIGNING_ALLOWED=NO
```

RED, and the failure message must name **DeckApp (NO), DeckWidgets (NO),
DeckAgent (absent)** — three targets, two different shapes. A failure naming
only one is a guard that would have passed the bug that shipped.

**Dependencies.** None. Commit before phase 2 so the RED state is in history.

## Phase 2 — Flip the flag and bump the version (GREEN)

**Goal.** Hardened runtime on all three shipping targets, in one commit with the
version bump so a revert takes both (critique A8).

**Files touched**
- `native/project.yml`

**Steps**

1. `ENABLE_HARDENED_RUNTIME: YES` in `settings.base` for **DeckApp** (`:51`,
   was `NO`), **DeckWidgets** (`:88`, was `NO`) and **DeckAgent** (key absent —
   add it beside `CODE_SIGN_IDENTITY`).
2. `settings.base`, not `configs: Release:` — Debug and Release alike. Per
   critique A6 the justification stated in the file is that developers should run
   what users get; the *measured* claim in this work is confined to Release.
3. Leave `CODE_SIGN_INJECT_BASE_ENTITLEMENTS: NO` under `configs: Release:`
   untouched, and add **no** entitlements file for DeckApp or DeckAgent. Deck
   takes hardened runtime in its strictest form; an exception entitlement is a
   phase-4 finding, never a phase-2 convenience.
4. `DeckSharedTests` unchanged.
5. Version 1.40 → **1.41**, `CFBundleVersion` 40 → 41, in all three targets
   (critique R1: WidgetKit caches the descriptor set per extension version).
6. `xcodegen generate --spec native/project.yml`.

**Verification**

```bash
xcodebuild test -project native/Deck.xcodeproj -scheme DeckSharedTests \
  -derivedDataPath native/build.noindex CODE_SIGNING_ALLOWED=NO   # GREEN, guard included

xcodebuild -project native/Deck.xcodeproj -scheme DeckApp -configuration Release \
  -derivedDataPath native/build.noindex -allowProvisioningUpdates \
  -allowProvisioningDeviceRegistration build

R=native/build.noindex/Build/Products/Release
for b in "$R/Deck.app" "$R/Deck.app/Contents/PlugIns/DeckWidgets.appex" \
         "$R/Deck.app/Contents/MacOS/DeckAgent"; do
  codesign -dvvv "$b" 2>&1 | grep -E "flags=" ; done
bash scripts/lsclean.sh        # after EVERY release build (CLAUDE.md)
```

Three lines, each `flags=0x10000(runtime)`. Two of three is a failure. Also
confirm the app still carries no entitlements and the appex still carries only
`app-sandbox` — hardened runtime must not have dragged anything in.

**Dependencies.** Phase 1 committed.

## Phase 3 — A CI gate, proven by failing on the baseline

**Goal.** The release job cannot publish an unhardened binary (critique A5 —
the same lesson as the HFS+ DMG that went out green).

**Files touched**
- `.github/workflows/deck.yml`

**Steps**

1. After "Build (signed, auto-provisioned)" and before "Package Deck.app (DMG)",
   add a step that reads `codesign -dvvv` for the app, the appex and the agent
   and exits non-zero unless all three report `runtime`. It runs only when
   signing secrets are present (an unsigned compile-check has no signature to
   read).
2. Word the failure so it names the target that lacks the flag, matching the
   guard's message — the same fault has one vocabulary in both places.
3. **Do not touch** `-allowProvisioningDeviceRegistration` (user decision, PRD
   "What does not change"): under automatic Apple Development signing it is what
   lets a fresh runner mint a profile, and the runbook drops it *with* the
   identity switch.

**Verification.** Run the step's own shell against both builds locally:

```bash
# must PASS on the hardened build from phase 2
# must FAIL on $SCRATCH/baseline-Deck.app (v1.40, flags=0x0)
```

A gate that has never been seen to fail is not known to be a gate.

**Dependencies.** Phase 2.

## Phase 4 — Install, and measure the things that could actually break

**Goal.** The evidence. Everything here happens against `/Applications`, never
`build.noindex` — a dev build cannot register with SMAppService.

**Files touched**
- `docs/planning/hardened-runtime-preflight/verification.md` *(new)*

**Steps, in this order** (the order is the critique's: R1 gates everything, A3
before any face)

1. `pgrep -lf "MacOS/Deck$"` → quit Deck. A running Deck rewrites snapshots and
   settings from its own memory (CLAUDE.md).
2. Record pre-install mtimes of `processes.json` and `agent-heartbeat.json`.
3. `rm -rf /Applications/Deck.app && cp -R $R/Deck.app /Applications/` —
   **the bundle only**. Never the container.
4. `bash scripts/lsclean.sh`, then launch, then quit and relaunch once:
   replacing the bundle takes the running jobs down without reloading them.
5. **Gate (R1).** `codesign -dvvv` on the three *installed* binaries → all
   `runtime`; `defaults read /Applications/Deck.app/Contents/Info
   CFBundleShortVersionString` → `1.41`. If either is wrong, stop: nothing after
   this means anything.
6. `pluginkit -m -i com.deck.app.widgets` → registered, version 1.41.
7. **Witnesses (A3).** Both mtimes advance past step 2 within ~2 tick lengths
   (the fast agent at its interval; the 60s agent's real tick is ~68s). No face
   is read as evidence until they have.
8. **The gallery enumerates fourteen widgets.** This is the single check that
   covers the ten not re-added, and it is the exact symptom the Charts trap
   produced when it failed.
9. **Five faces re-added, one per risk surface** (A1) — user action:
   **BatBox** (SPI in the sandbox), **DevBox** (`docker` + ports), **CalBox**
   (TCC), **LiveBox** (self-sampled mach, renders with no agent at all),
   **GitBox** (agent-pumped snapshot). One of them at large, to catch a
   size-specific crash.
10. **SPI:** BatBox's accessory section vs `pmset -g accps` — same accessories,
    same levels. The CLI is ground truth; the extension is what is on trial.
11. **Subprocesses:** DevBox lists listening ports and Docker containers; GitBox
    shows today's commits. That is `ps`, `docker` and `git` all spawned by a
    hardened agent.
12. **TCC:** CalBox renders events and **no new permission prompt appears** —
    the highest-value measurement here, because the notarization release *will*
    reset these grants and this separates the two causes.
13. **AMFI, as supporting evidence only (R2):** `log stream --predicate 'sender
    == "AMFI"'` across a full tick, admissible only if a positive control in the
    same window produces output (`subsystem == "com.deck.agent"` must print
    something while the agent ticks). If the log is dead, say so and rely on
    behaviour.
14. Write `verification.md`: what was run, what came back, timestamps, and every
    negative result kept rather than tidied.

**Failure policy.** A failure is recorded before it is fixed. An exception
entitlement is a last resort and a reportable finding; reverting the flag and
shipping without it is a legitimate outcome — the deliverable is the answer.

**Dependencies.** Phase 2 (phase 3 may land in parallel).

## Phase 5 — Write it down where the next reader will be

**Goal.** The paid day starts at Step 1 with one fewer unknown.

**Files touched**
- `docs/planning/notarization/runbook.md`
- `ROADMAP.md`
- `CLAUDE.md` *(only if phase 4 found something)*
- `README.md` *(only if a user-facing claim changed — expected: none)*

**Steps**

1. Runbook Step 2 loses `ENABLE_HARDENED_RUNTIME` from its instruction block and
   gains one line saying it is already live since v1.41, pointing here. Its gate
   keeps grepping for both `Authority=Developer ID` **and** `flags=.*runtime` —
   still correct, and removing half a step while leaving its gate is how a
   runbook starts lying (critique A7).
2. The "Hardened runtime: what to watch" list gains the measured answers, so the
   three items stop being predictions.
3. `ROADMAP.md` M7: the notarization entry records the flag as already shipped;
   and the stale Homebrew claim that "`--no-quarantine` is what spares users the
   `xattr` dance" goes — Homebrew removed that flag, `README.md:92` and
   `homebrew/deck.rb:13` already say so, and the ROADMAP is the last copy telling
   a reader to use an uncommand.
4. `CLAUDE.md` gets a trap note **only** if phase 4 measured one. No finding, no
   note.
5. Version/registration housekeeping per the blueprint: v1.41 in README if it
   names a version.

**Dependencies.** Phase 4.
