## Phase 1 — Move per-core CPU math to Shared + tests (closes ROADMAP.md:58)

**Goal:** make `CpuTicks` / `perCoreUsagePercents` / `cpuUsagePercent(previous:current:)`
pure and testable in `DeckSharedTests`, without touching the mach samplers.

**Files touched:**
- `native/Shared/SystemMetricsCore.swift` (new)
- `native/SharedTests/SystemMetricsCoreTests.swift` (new)
- `native/DeckWidgets/Loaders/SystemMetrics.swift`

**Steps (TDD):**
1. Write failing `SystemMetricsCoreTests` in the new Shared core file shape:
   - `CpuTicks.total` sums user+system+idle+nice.
   - `cpuUsagePercent(previous:current:)`: nil previous → 0; zero delta → 0;
     known tick pair → expected percent (e.g. +8 busy / +10 total → 80).
   - `perCoreUsagePercents`: per-core deltas; zero-delta core → 0; `zip`-safe
     when core counts differ (shared prefix only).
2. Create `Shared/SystemMetricsCore.swift` with `CpuTicks` (struct + `total` +
   `sample()/sampleAll()` stubs REMOVED — only the pure bits) and the two pure
   percent functions, copied verbatim from SystemMetrics.swift:77-94.
3. Update `DeckWidgets/Loaders/SystemMetrics.swift` to `remove` the moved
   definitions and keep only the Darwin samplers (`sample`, `sampleAll`,
   `memoryUsagePercent`, `diskUsagePercent`, `diskVolumeSamples`), referencing
   the Shared core. The `previous/current` overload of `cpuUsagePercent`
   (L98-101, seeds via `CpuTicks.sample()`) stays in the loader file.
4. `xcodegen generate` (new Shared files), run DeckSharedTests → green.
5. Full Release build → green.

**Verification:** `DeckSharedTests` passes (new suite); `DeckApp` Release build
succeeds. LiveBox widget still compiles against the moved types.

**Dependencies:** none — first.
