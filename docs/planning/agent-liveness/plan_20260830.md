## Phase 1 — `AgentLivenessPolicy`, pure and unit-pinned

**Goal.** The whole decision, as a function, before anything can call it.

**Files touched**
- `native/Shared/RefreshPolicies.swift` (extend — it already holds
  `ProcessRefreshPolicy` and `AgentReconcilePolicy`)
- `native/SharedTests/RefreshPoliciesTests.swift` (extend)

**Steps**

1. **RED.** Write `AgentLivenessPolicyTests` against the not-yet-existing API,
   one test per row of PRD §11. Confirm it fails to compile — that is the red.
2. **GREEN.** Add to `RefreshPolicies.swift`:
   ```swift
   enum AgentLiveness: Equatable {
       case healthy
       case unknown
       case down(lastRefresh: Date?)
   }

   enum AgentLivenessPolicy {
       static func threshold(processRefreshInterval: Int) -> TimeInterval {
           TimeInterval(max(4 * processRefreshInterval, 120))
       }

       static func resolve(
           intent: Bool,
           state: AgentRegistrationState,
           lastRefreshAt: Date?,
           registeredAt: Date?,
           processRefreshInterval: Int,
           now: Date
       ) -> AgentLiveness
   }
   ```
   Resolution order exactly as PRD §5: intent → state → healthy → nil-clock →
   grace → down. **Rule 3 before rule 5** is load-bearing; a comment says why
   (a successful Restart must clear the notice at the next tick, not wait out
   the grace).
3. Document `threshold` with the comparison to
   `ProcessSnapshot.maxAgeSeconds(for:)` and why this one is more conservative.

**Tests** (all twelve rows of PRD §11), notably:
- `.requiresApproval` + a week-old snapshot → `.unknown`, not `.down`. This is
  the structural precedence that stops the veto case double-reporting.
- fresh write + registration *inside* the grace window → `.healthy` (proves the
  rule-3-before-rule-5 ordering).
- `writtenAt` in the future → `.healthy` (clock skew never accuses).
- boundary at exactly `threshold` — pinned explicitly in whichever direction the
  implementation takes, so a later refactor cannot drift it silently.
- `threshold(5) == 120`, `threshold(15) == 120`, `threshold(60) == 240`.

**Verification.** Test suite green with both CI greps. No UI exists yet.

**Dependencies.** None. Start here.

## Phase 2 — `DeckSettings.agentsRegisteredAt`

**Goal.** The grace-period clock persists, and its absence in an older
`settings.json` disturbs nothing.

**Files touched**
- `native/Shared/DeckSettings.swift`
- `native/SharedTests/DecodeTests.swift`

**Steps**

   intact**; (b) a value round-trips through encode→decode.
2. **GREEN.** Add `var agentsRegisteredAt: Date?` (default `nil`) beside
   `agentAtLogin`, then **all three** of:
   - the `CodingKeys` case,
   - `decodeIfPresent` in `init(from:)`,
   - the line in `encode(to:)`.

   decodes as absent and never encodes** — the credentials work lost every
   account to exactly this and the tests are what caught it (ROADMAP M6). All

   clearing it costs one grace window.

**Verification.** Suite green. Confirm the round-trip test actually fails when
the `encode` line is deleted — a decode-only test passes against the bug.

## Phase 3 — Wire it into `reconcileAgents()`, in the right order

**Goal.** The app computes liveness, and the rename release does not
false-positive (PRD §14 R1).

**Files touched**
- `native/DeckApp/DeckApp.swift` (`ContentView`: state, `reconcileAgents`,
  `registerAgents`, `applyAgent`, the 60s timer)

**Steps**

1. Add `@State private var liveness: AgentLiveness = .unknown` — a value, not a
   pre-rendered string, so the view can draw the button and vary the wording.
2. Add `private func evaluateLiveness()`: reads
   `ProcessSnapshotStore.load()?.writtenAt`, `settings.agentsRegisteredAt`,
   `settings.livebox.processRefreshInterval` and `AgentService.main.state`, and
   assigns `liveness`.
3. Add `private func stampAgentsRegisteredAt()`, guarded so it writes **once**:
   ```
   guard settings.agentsRegisteredAt == nil else { return }
   settings.agentsRegisteredAt = Date(); settings.save()
   ```
   (PRD §14 A2 — otherwise every launch writes settings and reloads all
   timelines.)
4. Restructure `reconcileAgents()` to the fixed order:
   ```
   1. legacyCleanup()
   2. for each agent: resolve + act        (register / adoptIntent / reportBlocked)
   3. stamp agentsRegisteredAt              (on successful register, OR .enabled && nil)
   4. evaluateLiveness()                    ← reads what step 3 wrote
   ```
   **Step 3 before step 4 is the whole of R1.** On the renamed app the new labels
   are `.notFound` → step 2 registers → step 3 stamps `now` → step 4 sees a
   fresh registration inside the grace window → `.unknown`. Without the
   ordering, a migrated days-old timestamp plus an empty new container renders
   "no refresh has been recorded" to every user of the rename release.

   The adopt-on-sight arm (`.enabled && nil`) is the upgrade path: an install
   that already had both agents registered never calls `register()` again, so
   without it the field stays `nil` forever and rule 4 makes the check
   permanently silent.
5. Call `evaluateLiveness()` from the existing 60s `ContentView` timer and from
   `applyAgent()`. No new timer.
6. `registerAgents()` and `removeAgents()` end with `evaluateLiveness()` so the
   toggle result is immediate.

**Verification**
- Build green; `scripts/lsclean.sh` after a release build.
- A comment in `reconcileAgents()` states the ordering constraint and names R1,
  so a future reorder has to argue with it.
- Phase 5 covers the runtime proof.

**Dependencies.** Phases 1 and 2.

## Phase 4 — The notice and the Restart button

**Goal.** The user sees the state and can repair it in one click.

**Files touched**
- `native/DeckApp/DeckApp.swift` (`GeneralSettingsView`, and the handler in
  `ContentView`)

**Steps**

1. `GeneralSettingsView` takes `var liveness: AgentLiveness` and
   `var onRestartAgents: () -> Void`.
2. Render inside the existing **Background refresh** section, below
   `agentNotice`, reusing its `Label` + `exclamationmark.triangle.fill` +
   `.font(.caption)` + `.foregroundStyle(.orange)` treatment. Only `.down`
   renders; `.healthy` and `.unknown` draw nothing — no green "all good" row,
   matching every other notice in this tab.
   - `.down(nil)`: "Background refresh has stopped. Deck's agents are registered
     but macOS is not running them. No refresh has been recorded."
   - `.down(date)`: same first two sentences, then "Last refresh: <relative>."
     via `RelativeDateTimeFormatter`.
   - Trailing `Button("Restart agents", action: onRestartAgents)`, laid out like
     the `renameNotice` row (`HStack` + `Spacer` + `.buttonStyle(.link)`).
3. The handler in `ContentView` — **reusing the existing private functions, not
   `AgentService` directly** (PRD §14 R2):
   ```swift
   private func restartAgents() {
       removeAgents()                       // unregisterAll + legacyCleanup
       settings.agentsRegisteredAt = nil    // so the stamp below takes
       registerAgents()                     // legacyCleanup(waitUntilExit) + registerAll + agentError
       stampAgentsRegisteredAt()            // grace restarts; no immediate re-fire
       evaluateLiveness()
   }
   ```
   Calling `AgentService` directly would skip `legacyCleanup()`'s
   `waitUntilExit` — the comment there is explicit that a fire-and-forget
   bootout races the registration and the label collision rejects the new job —
   and would skip the `agentError` assignment and the `.requiresApproval`
   re-check.
4. A `register()` failure surfaces through the existing `agentError` slot, which
   `registerAgents()` already sets. Do not swallow it.

**Verification**
- Release build green, `scripts/lsclean.sh`.
- Open the installed Deck → General: with healthy agents the section looks
  exactly as it does today (nothing added).
- Wording review: the notice must not name a specific agent (PRD §4).

**Dependencies.** Phase 3.

## Phase 5 — The hand-driven pass, on the installed copy

**Goal.** Prove the two things no unit test can reach: that the notice fires on
the real fault, and that the button actually repairs it.

**A `build.noindex` build cannot register with SMAppService at all** — approved
location only. Everything here runs against `/Applications/Deck.app`.

**Steps**

1. `rm -rf /Applications/Deck.app && cp -R native/build.noindex/Build/Products/Release/Deck.app /Applications/`
   (replace the bundle only — never touch the container, CLAUDE.md), launch,
   `scripts/lsclean.sh`.
2. **Baseline.** General shows no liveness notice.
   `stat -f %m ~/Library/Containers/com.deck.app.widgets/Data/Library/Application\ Support/Deck/processes.json`
   advances on the configured interval. Confirm `agentsRegisteredAt` now exists
   in `settings.json`.
3. **Induce the fault.** Quit Deck (`pgrep -lf "MacOS/Deck$"` empty — a running
   Deck overwrites the file you are inspecting), then
   `launchctl bootout gui/$(id -u)/com.deck.agent.processes`.
4. Wait past `threshold` (120s at the default interval). Confirm the
   `processes.json` mtime is **unchanged** — an unchanged mtime is the tell that
   the file was genuinely left alone, not that its content matched.
5. **Observe.** Launch Deck → the notice must appear, with a plausible relative
   "Last refresh" age, and the toggle must still read on.
6. **Repair.** Press **Restart agents** → within one interval the notice clears
   and `processes.json` starts advancing again.
7. **A2 check.** Relaunch Deck twice; `agentsRegisteredAt` must not change on a
   launch where nothing was registered.

**The R2/A3 risk lands here.** `AgentService.Agent.register()` returns early when
`status == .enabled`, and whether `unregister()` drops the status synchronously
is undocumented and unmeasured. If step 6 does nothing, the button is a silent
no-op — the worst outcome for a repair button. **Fallback, if that happens:**
report the failure honestly rather than sleeping and retrying; a button that
says "that did not work, log out and back in" beats one that lies. Record the
measurement either way — this is the kind of thing that belongs in CLAUDE.md.

**Cost.** Step 3 is a real outage: a `bootout` of a registered agent leaves the
job down until the next login or a toggle cycle; smd does not reload it
spontaneously (measured 2026-08-27). Step 6 is also the repair.

**Dependencies.** Phase 4, and a Release build.
