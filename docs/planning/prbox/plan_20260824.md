# PRBox — implementation plan (2026-08-24)

From `prd.md` + `prd-critique.md`. §10 open questions resolved with the PRD's
proposed defaults: optional free-text GitHub scope; drafts shown and marked;
small face is counts only.

> **Note on the `deck-plan` template.** Its blueprint still describes the
> pre-WidgetKit shell (`Sources/<Widget>/`, `Package.swift`, `swift build`,
> `--debug-flip`, flip/dynamic-height wiring). None of that exists any more —
> this repo is xcodegen → `Deck.xcodeproj` with three targets plus
> `DeckSharedTests`, and WidgetKit has no flip face. `CLAUDE.md` and the code
> are authoritative; the plan below follows them.

## Commands used throughout

```bash
xcodegen generate --spec native/project.yml            # after ANY new file
xcodebuild -project native/Deck.xcodeproj -scheme DeckSharedTests \
  -destination 'platform=macOS' test                    # unit tests
xcodebuild -project native/Deck.xcodeproj -scheme DeckApp -configuration Release \
  -derivedDataPath native/build.noindex -allowProvisioningUpdates \
  -allowProvisioningDeviceRegistration build            # full build
scripts/lsclean.sh                                      # after every release build
```

⚠️ **xcodegen enumerates files at generation time.** A new test file that is
not regenerated in is silently not compiled *and the suite still reports
success*. Every phase that adds a file regenerates first.

## Phase 1 — Snapshot model, store, and formatting (pure)

**Goal:** the data shape and every decision the widget must not make, with
tests, before a single byte of network code.

**Files:** `native/Shared/PRBoxSnapshot.swift` (new),
`native/SharedTests/PRBoxSnapshotTests.swift` (new).

**Steps**

1. `PRProvider` (`github`, `azureDevOps`, `unknown`) and `PRRole`
   (`authored`, `reviewing`), both `String`-backed and `Codable`.
2. `PullRequestItem` per PRD §4, with a tolerant `init(from:)`: unknown
   `provider` → `.unknown`; `id`/`number`/`title` stay required (an item
   without them is not a PR). Mirror `TaskItem`'s comment style
   (`TaskBoxSnapshot.swift:19`) — say *why* it is tolerant.
3. `PRBoxSnapshot { writtenAt, authoredCount, reviewingCount, authoredCapped,
   reviewingCapped, pullRequests }`. The two `…Capped` flags carry **R1**: the
   header renders `100+` when a role saturated the over-fetch ceiling.
4. `PRFormatting.sorted(_:)` — created-date descending, tie-break
   `(provider.rawValue, repo, number)` so order is stable between ticks.
5. `PRFormatting.deduped(_:)` — key `(provider, repo, number)`, authored wins
   over reviewing (**A5**).
6. `PRFormatting.age(from:to:)` — `2h` / `10d`, suffix-less. **A6:** written
   beside a doc comment naming `OpenBoxCore.relativeTime` and stating why the
   right-aligned column drops the "ago"; both stay tested.
7. `PRBoxSnapshotStore` — `prbox.json`, `AtomicFile.write` (**A7**, the M4
   invariant), same shape as `ShipBoxSnapshotStore`.

**Verification (TDD — tests first, each RED before GREEN)**
- sorted: mixed providers interleave by date; equal dates give a stable order.
- deduped: same PR in both roles → one row, `.authored`.
- tolerant decode: unknown provider → `.unknown`; missing `title` → row
  dropped, list survives.
- age: 90s→`1m`, 3h→`3h`, 10d→`10d`, future date → `0m` not a negative.
- store round-trip through a temp container.

**Dependencies:** none. Everything else builds on this.

## Phase 2 — GitHub loader + parser

**Goal:** two search calls → `[PullRequestItem]`, with the parser injectable.

**Files:** `native/Shared/PRBoxSnapshot.swift` (append `HostGitHubPRLoader`,
`GitHubPRParser`), `native/SharedTests/PRBoxSnapshotTests.swift`,
`native/SharedTests/Fixtures/github_prs.json` (new, trimmed from the live
probe response).

**Steps**

1. `GitHubPRParser.parse(_ data: Data, role: PRRole) -> [PullRequestItem]?`
   — `number`, `title`, `draft`, `created_at` (ISO8601), `html_url`, repo =
   last path component of `repository_url`. A row missing a required field is
   dropped; a payload that is not an object returns `nil` (→ `.badResponse`).
2. `HostGitHubPRLoader.fetch(token:scope:cap:)` — reuses `HostGitHubLoader`'s
   request shape verbatim (Bearer, `application/vnd.github+json`,
   `X-GitHub-Api-Version: 2022-11-28`, 10s timeout) and throws the **existing**
   `HostGitHubLoader.GitHubError`, so `FetchClassifier` needs no new case.
3. Query builder: `is:pr is:open author:@me` / `review-requested:@me`, plus the
   optional trimmed scope string, percent-encoded. `per_page` = row cap + 1.
   `total_count` is the honest count — GitHub gives it independent of
   `per_page`, so no over-fetch is needed on this side (**R1** is Azure-only).

**Verification**
- fixture → 2 items, right repo names, `draft` honored.
- garbage / empty / `{"items": null}` → `nil`, not a crash.
- query builder: empty scope produces no trailing `+`; a scope with a space is
  encoded.
- one **live** call with the real token (manual, not in CI) confirming the
  fixture still matches the API shape.

**Dependencies:** Phase 1.

## Phase 3 — Azure DevOps loader + parser (the risky one)

**Goal:** identity-resolved, correctly-filtered PRs — and a guard that makes
the unfiltered-query failure impossible.

**Files:** `native/Shared/AzureDevOpsLoader.swift` (append
`ConnectionDataParser`, `AzurePRParser`, `HostAzurePRLoader`),
`native/SharedTests/AzureDevOpsParserTests.swift`,
`native/SharedTests/Fixtures/azure_prs.json`,
`native/SharedTests/Fixtures/azure_connectiondata.json` (both new).

**Steps**

1. `ConnectionDataParser.parse(_:) -> String?` — `authenticatedUser.id`;
   returns `nil` when absent or empty.
2. `HostAzurePRLoader.identity(target:auth:)` — calls
   `{org}/_apis/connectionData?api-version=7.1-preview` and **throws
   `AzureDevOpsError.invalidTarget` when the parser returns nil**. This is the
   🔴 guard: an invalid `creatorId` returns 200 with every active PR in the
   project, so there is no safe fallback. The doc comment carries the probe
   numbers (6 / 6 / 0) so nobody "simplifies" it later.
3. `AzurePRParser.parse(_:role:me:)` — `pullRequestId`, `title`, `isDraft`,
   `creationDate` via `AzureDate.parse`, repo = `repository.name`, URL built as
   `https://dev.azure.com/{org}/{project}/_git/{repo}/pullrequest/{id}` (the
   payload has none). For `.reviewing`, **keep only rows where the reviewer
   entry whose `id == me` has `vote == 0`** (A-scope of the PRD §4 rule).
4. `HostAzurePRLoader.fetch(organization:project:token:cap:)` — normalise via
   `AzureTarget`, Basic auth, then created + reviewing with `$top=101`
   (**R1**), count filtered rows locally, set `…Capped` when a role returns
   101, trim to cap.

**Verification**
- connectionData fixture → the GUID; `{}` → nil; **loader turns nil into a
  throw** (the guard, pinned by its own test).
- PR fixture with reviewer votes `10, 0, -5` → exactly the `vote == 0` row.
- `creationDate` with 7 fractional digits parses (the live shape:
  `2026-08-14T09:45:36.1569896Z`).
- 101-row fixture → `authoredCapped == true`, stored rows == cap.
- URL builder produces the `_git/.../pullrequest/<id>` form.
- one **live** call (manual) re-confirming counts against the probe.

**Dependencies:** Phase 1.

## Phase 4 — Settings

**Goal:** `PRBoxSettings` with per-provider sub-structs, registered *and*
decoded at the top level.

**Files:** `native/Shared/DeckSettings.swift`,
`native/SharedTests/DecodeTests.swift`.

**Steps**

1. `PRGitHubSettings { enabled=false, token="", scope="" }` and
   `PRAzureSettings { enabled=false, organization="", project="", token="" }`,
   each with a tolerant `init(from:)`.
2. `PRBoxSettings { github, azure, showList=true, prCount=6, mineColor=.blue,
   reviewColor=.orange }`, tolerant decode. **A1:** `prCount` is documented as
   the *large* row count (3…12); medium renders `min(prCount, 3)`.
3. Register `prbox` on `DeckSettings` — **and add the
   `decodeIfPresent` line in `DeckSettings.init(from:)`** (**R2**).

**Verification**
- **R2 regression test**, the important one: decode a `settings.json` with no
  `prbox` key and assert every *other* section survives with its values (this
  is the bug that once reset everyone's tokens — `ROADMAP.md`, "Fixed in
  passing").
- Round-trip; unknown keys ignored; `prCount` out of range clamps.

**Dependencies:** none (parallel with 2–3).

## Phase 5 — Fetch status: two sources and a composed chip

**Goal:** per-provider status, one honest line on the face.

**Files:** `native/Shared/FetchStatus.swift`,
`native/SharedTests/FetchStatusTests.swift`.

**Steps**

1. `FetchSource` gains `prboxGitHub`, `prboxAzure`. The `reason` and `hint`
   switches (`:156, :165, :192, :204, :212`) are exhaustive — both cases need
   all four strings each, in the established voice ("Check token",
   "GitHub rejected the request: …").
   **A4:** the Azure hint says "a read-only PAT that can see Code" — *not*
   a named scope, which the probe did not verify.
2. `PRFetchChip.text(github:azure:githubEnabled:azureEnabled:dataWrittenAt:now:)
   -> String?` (**A2**), precedence: agent-silent → both-failed → one-failed
   (named) → nil. Same-outcome both-failed reads `"GitHub + Azure: …"`;
   different outcomes name GitHub and append `"+1 more"`.

**Verification**
- totality: every `(source, outcome)` pair returns non-nil where the existing
  tests require it — extend the existing exhaustiveness test rather than
  writing a parallel one.
- chip matrix as a table-driven test: neither enabled, one enabled+ok,
  one enabled+failed, both failed same, both failed different, agent silent.

**Dependencies:** Phase 4 (enabled flags).

## Phase 6 — The widget

**Goal:** PRBox renders at three sizes from the snapshot.

**Files:** `native/DeckWidgets/PRBoxWidget.swift` (new),
`native/DeckWidgets/DeckWidgets.swift`.

**Steps**

1. Copy `ShipBoxWidget.swift`'s skeleton: entry, `TimelineProvider` with one
   entry and `.after(60s)`, placeholder with plausible sample rows, the
   `available` / `stale` / `chip` triple, "a snapshot that exists is always
   rendered".
2. Header: `PRBOX` + counts `● n MINE  ● n REVIEW`, `100+` when capped.
3. Small = counts only. Medium = header + `min(prCount, 3)` rows. Large =
   header + `prCount` rows. Row per PRD §2: role dot, `GH`/`AZ` monospaced
   tag, `repo #number`, title, right-aligned age; drafts secondary + `DRAFT`.
4. Empty states: "Not configured" (nothing enabled/credentialed) vs
   "No open PRs" (configured, genuinely empty) — visually distinct.
5. Register in the bundle.

**Verification**
- `xcodegen generate` + Release build.
- Install, `scripts/lsclean.sh`, add all three sizes from the gallery, check
  against a hand-written `prbox.json` fixture covering: both providers, a
  draft, a long title, a capped count, and the empty list.
- `log show --last 2m --info --debug --predicate 'process == "chronod"' | grep -c PRBoxWidget`
  — zero means stale descriptors, i.e. the version bump did not take.
- Timeline archive size stays small (the CalBox trap):
  `~/Library/Containers/com.deck.app.widgets/Data/SystemData/com.apple.chrono/timelines/`.

**Dependencies:** Phases 1, 4, 5.

## Phase 8 — Agent

**Goal:** the 60s pump.

**Files:** `native/DeckAgent/main.swift`.

**Steps**

1. A fetch block shaped like ShipBox's (`:131`) and TaskBox's (`:157`): skip
   with `.notConfigured` when a provider is disabled or missing credentials,
   `record(.ok)` on success, `FetchClassifier.outcome(for:)` on failure, one
   `agentLog.info` line per provider.
2. Merge both providers → dedupe → sort → cap → one `PRBoxSnapshot`. **A
   provider that fails must not blank the other's rows**: the snapshot is
   written from whatever succeeded, and the chip says which half is missing.

**Verification**
- Run `DeckAgent` from the terminal; inspect `prbox.json` and both
  `fetch-prbox*.json`.
- Break the Azure token → the GitHub half still renders, the chip names Azure.
- `log stream --predicate 'subsystem == "com.deck.agent"'` shows one line per
  provider per tick.

**Dependencies:** Phases 2, 3, 4, 5.

## Risk register

| Risk | Mitigation |
|---|---|
| Azure returns everyone's PRs (invalid identity) | Phase 3 step 2 throws rather than falling back; pinned by its own test |
| Counts saturate silently | `$top=101` + `…Capped` → `100+` (R1) |
| A settings section resets every user's tokens | R2 regression test, Phase 4 |
| Widget never appears in the gallery | Version bump, Phase 9, verified via `chronod` |
| New test file silently not compiled | `xcodegen generate` in every phase that adds a file |
| Search rate limit | 2 calls/tick against 30/min; no per-repo fan-out anywhere |
