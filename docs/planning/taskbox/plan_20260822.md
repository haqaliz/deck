## Phase 0 — Live shape check (blocked on a PAT; deferrable)

**Goal**: replace the PRD's documented-contract guess with the real payload
shape from org `Manifold`, before the parsers harden around the wrong keys.

**Files touched**: none. Nothing is written to the repo by this phase.

**Steps**:
1. Ask for a **read-only Work Items (Read)** PAT. Export it to a shell variable
   for the session only; never write it to a file, never commit it.
2. `curl` all three endpoints (§3 of the PRD): WIQL POST, `workitemsbatch` POST
   with `errorPolicy: "omit"`, `teamsettings/iterations` GET.
3. Record **only these answers**, in prose, into
   `docs/planning/taskbox/shape-notes.md`:
   - which of `Microsoft.VSTS.Scheduling.DueDate` / `.TargetDate` /
     `System.IterationPath` are non-empty, and on which work-item types;
   - the exact date format returned (ISO8601 with or without fractional seconds);
   - whether `fields` omits absent keys or returns them null;
   - whether the iterations endpoint resolves without an explicit team;
   - the HTTP code returned for a deliberately wrong PAT (confirming §9 C2's
     203-not-401 behaviour).
4. **Discard the payloads.** ⛔ Per PRD §9 R1 / critique N1: the responses carry
   real work-item titles, iteration paths and the PAT owner's display name from
   the user's employer's org. They are read and thrown away. Every fixture
   committed in Phase 2 is **synthetic**, hand-written to the shape these notes
   describe.

**Verification**: `shape-notes.md` exists and answers all five questions; no
file in the repo contains a real work-item title or a PAT.

**If no PAT is available**: skip. Phase 2's parsers are defensive by
construction (every field optional, unknown keys ignored, malformed → `nil`), so
they survive a wrong guess; Phase 7's live check with a real PAT in the settings
tab becomes the verification instead, and any shape correction lands as a
follow-up commit. **This is the only phase that may be skipped.**

**Dependencies**: none. Blocks nothing hard; informs Phase 2.

## Phase 1 — Model + due logic (TDD, pure)

**Goal**: `TaskItem`/`TaskBoxSnapshot` and every pure decision the face makes —
due resolution, bucketing, sorting, formatting — proven by test before a byte of
network or UI code exists.

**Files touched**: `native/Shared/TaskBoxSnapshot.swift` (new),
`native/SharedTests/TaskBoxSnapshotTests.swift` (new).

**Steps** (each is RED → GREEN → refactor):
1. **Model.** `TaskProvider: String, Codable` (`azureDevOps`); `DueSource`
   (`explicit/target/iteration/none`); `TaskItem` (id `String`, title, state,
   itemType, url, provider, dueDate `Date?`, dueSource, changedAt `Date?`);
   `TaskBoxSnapshot` (writtenAt, scope, tasks); `TaskBoxSnapshotStore` mirroring
   `ShipBoxSnapshotStore` (`taskbox.json`, `AtomicFile.write`).
   *Tolerant decode*: unknown `provider` / `dueSource` strings decode to a safe
   default rather than throwing away the whole snapshot.
2. **Due resolution.** `TaskFormatting.resolveDue(dueDate:targetDate:
   iterationPath:iterationEnds:) -> (Date?, DueSource)`. Chain
   `DueDate → TargetDate → iterationEnds[path] → nil`, `dueSource` records the
   winner. Tests: each of the four wins in turn; `dueSource` correct in all four.
3. **Buckets.** `DueBucket` (`overdue/today/soon/later/undated`) and
   `TaskFormatting.bucket(due:now:calendar:soonWindowDays:)`. **Day-granular
   via `calendar.startOfDay`** — 23:59 yesterday is `overdue`, 00:01 today is
   `today`. Tests hit every boundary and both sides of `soonWindowDays`
   (day N = `soon`, day N+1 = `later`).
4. **Sort.** `TaskFormatting.sorted(_:)` — due ascending, undated last, ties
   broken by `changedAt` descending. Tests: ordering; undated last; the sort is
   **total** (two runs over the same input give an identical array — a wobbling
   sort would also defeat the agent's write-avoidance and reshuffle the face
   between identical ticks).
5. **Formatting.** `relativeDay` → `"-2d" / "today" / "+3d" / "—"`, clamped at
   `±99d`. `countsLine(tasks:now:calendar:soonWindowDays:)` →
   `"3 overdue · 7 due ≤7d"`, zero parts skipped, **window interpolated from the
   setting** (critique N3), falling back to `"N open"` when every task is
   undated. `counts(...) -> Counts` for the large face's totals row.
6. Tests inject `now` and `Calendar` everywhere; **no test reads the clock**.

**Verification**: `xcodegen generate` then the suite command above. Expect
**325 + N** tests, 0 failures — the increased total is the proof the new file
compiled.

**Dependencies**: none (Phase 0 informs but does not block).

## Phase 2 — Parsers + target normalisation (TDD, pure)

**Goal**: turn three Azure DevOps JSON payloads into `[TaskItem]` defensively,
against synthetic fixtures.

**Files touched**: `native/Shared/AzureDevOpsLoader.swift` (new, parsers half),
`native/SharedTests/AzureDevOpsParserTests.swift` (new).

**Steps**:
1. `AzureTarget.normalise(organization:project:)` — trim both; accept a bare org
   name, a full `https://dev.azure.com/{org}` URL, or a trailing slash and
   resolve all three to one base; **percent-encode both** with `.urlPathAllowed`
   (critique N5 — a project name with a space must not produce a malformed URL
   that surfaces as "unexpected response"); either empty → `.invalidTarget`.
2. `WiqlIdParser.parse(_ data: Data) -> [Int]?` — `workItems[].id`, order
   preserved, capped at **50**. Empty `workItems` → `[]` (not `nil`; "nothing
   assigned" is a success). Malformed → `nil`.
3. `IterationMapParser.parse(_ data: Data) -> [String: Date]` — `value[].path` →
   `attributes.finishDate`. Entries missing `attributes` or with a null
   `finishDate` are **skipped, not fatal**; backslash paths kept verbatim (they
   must match `System.IterationPath` exactly). Malformed → `[:]`, never `nil` —
   this parser's failure mode is "no fallback dates", not "fetch failed".
4. `WorkItemParser.parse(_ data: Data, scope:iterationEnds:orgBase:project:)
   -> [TaskItem]?` — `value[].fields`. A row missing `System.Title` is
   **dropped**, not defaulted. Unknown extra fields ignored. Calls
   `resolveDue` from Phase 1. Builds the **human** URL
   `https://dev.azure.com/{org}/{project}/_workitems/edit/{id}` — the payload's
   own `url` is the API endpoint, not a browsable link. Malformed → `nil`.
5. Date parsing tolerates ISO8601 **with and without** fractional seconds (two
   formatters, tried in order) — Azure DevOps is inconsistent here across fields.
6. **Synthetic fixtures only** (critique N1). Inline fixture strings in the test
   file, in the `ShipBoxSnapshotTests` idiom, with invented titles
   (`"Widget alignment spike"`, not anything from the real org).

**Verification**: suite green; the new test file's cases appear in the count.
Parser cases must include: full payload, missing `fields`, missing title,
absent-vs-null date keys, empty `value`, malformed JSON, and the 50-cap.

**Dependencies**: Phase 1 step 2 (`resolveDue`).

## Phase 3 — Settings + FetchStatus wiring (TDD)

**Goal**: TaskBox becomes a first-class settings citizen and a first-class
fetch-status source, with copy for every failure the user can hit.

**Files touched**: `native/Shared/DeckSettings.swift`,
`native/Shared/FetchStatus.swift`, `native/SharedTests/DecodeTests.swift`,
`native/SharedTests/FetchStatusTests.swift`.

**Steps**:
1. `TaskBoxSettings` per PRD §7 — organization, project, token, showList,
   taskCount 5, soonWindowDays 7, four `RGBA` due colors. Tolerant
   `init(from:)` with `decodeIfPresent ?? default` **per field**, matching every
   other settings struct. Add `var taskbox = TaskBoxSettings()` to `DeckSettings`.
2. Extend `DecodeTests`: `TaskBoxSettings` decodes from `{}`, from partial JSON,
   and from JSON carrying an unknown future field; a full `DeckSettings` written
   by an older build still loads.
3. `FetchSource` gains `case taskbox`. Add arms to **both**
   `FetchStatusCopy.line` and `.hint` for all four non-`ok` outcomes:
   - `.notConfigured` → "Add org, project + PAT in settings"
   - `.authOrTarget` → "Check org, project + PAT"
   - `.unreachable` → "Can't reach Azure DevOps"
   - `.badResponse` → "Unexpected Azure DevOps response"
4. `AzureDevOpsError` (`invalidTarget / serverError(Int) / transport(String) /
   invalidPayload`) + an arm in `FetchClassifier.outcome(for:)`.
   **§9 C2**: map a non-200 **2xx** (notably **203**) to `.authOrTarget` before
   delegating to `outcome(forStatusCode:)`. Azure DevOps answers a bad or
   expired PAT with `203 Non-Authoritative Information` and an HTML sign-in
   page; the shared classifier would call that `.badResponse` and tell the user
   the wrong thing.
5. Extend `FetchStatusTests`: `.taskbox` has copy for every non-`ok` outcome and
   none for `.ok`; `line` and `hint` speak together (the existing invariant);
   203 → `.authOrTarget`; 401/403/404 → `.authOrTarget`; 429/5xx → `.unreachable`.

**Verification**: suite green. The `line`/`hint` parity test already iterates
`FetchSource.allCases`, so a missing arm fails without a new test being written
— confirm it would have caught an omission by deliberately removing one arm
once, watching it go RED, then restoring it.

**Dependencies**: none on Phases 1–2; Phase 4 depends on this (`AzureDevOpsError`).

## Phase 4 — Host loader (network, host/agent only)

**Goal**: the three-call fetch, with the third call best-effort.

**Files touched**: `native/Shared/AzureDevOpsLoader.swift` (loader half).

**Steps**:
1. `HostAzureDevOpsLoader.fetch(organization:project:token:) async throws ->
   TaskBoxSnapshot`. Basic auth header:
   `"Basic " + Data(":\(token)".utf8).base64EncodedString()`.
   `timeoutInterval = 10` per request, matching `HostGitHubLoader`.
2. Call 1 — WIQL POST with the **fixed** query from PRD §3 (not user-editable).
   Non-200 → `serverError(code)`; unparseable → `invalidPayload`.
3. **Short-circuit**: zero ids → return a snapshot with `tasks: []`. Skips calls
   2 and 3 entirely; "nothing assigned" costs one request.
4. Call 2 — `workitemsbatch` POST including **`"errorPolicy": "omit"`**
   (critique N4). Without it the batch fails wholesale when a single id is
   inaccessible or was deleted between calls 1 and 2 — a real race at a 60s
   cadence.
5. Call 3 — iterations GET, **wrapped so any throw yields `[:]`**. A missing
   sprint calendar degrades tasks to undated; it must never fail the tick or
   blank a working list.
6. Assemble: parse → resolve due → `TaskFormatting.sorted` → snapshot with
   `scope` = `project`, or `"{org} / {project}"` when they differ.
   The snapshot ships **pre-sorted** so the widget renders without deciding.

**Verification**: no unit tests (`HostGitHubLoader`'s HTTP isn't tested either —
the parsers it delegates to are, and they were in Phase 2). Proof is
`xcodebuild -scheme DeckApp -configuration Release … build` compiling clean,
plus the live check in Phase 7.

**Dependencies**: Phases 1, 2, 3.

## Phase 5 — Front face

**Goal**: the widget renders at S / M / L, including all three empty states.

**Files touched**: `native/DeckWidgets/TaskBoxWidget.swift` (new),
`native/DeckWidgets/DeckWidgets.swift`.

**Steps**:
1. `TaskBoxEntry` + `TaskBoxProvider` modelled on `ShipBoxProvider`: load
   snapshot, load `DeckSettings().taskbox`, compute `chip` via
   `FetchChip.text(source: .taskbox, …)`, `stale = now − writtenAt > 5min`,
   60s `TimelineReloadPolicy.after`.
2. `placeholder(in:)` with **obviously synthetic** titles (critique N8) — the
   placeholder is what the gallery preview puts on screen.
3. `headerLine`: `entry.scope` (from the **snapshot**, not settings — critique
   N6) `.middle`-truncated; `countsLine` right-aligned; then chip `.tertiary`
   10pt; then `· HH:mm` when stale. On `.systemSmall` **the chip wins and the
   counts line is dropped** (ShipBox precedent: one hint, not two).
4. `taskList(maxCount:)`: `TASKS` title 10pt bold tracked 1pt, then dot +
   title + trailing `relativeDay`. Trailing is `.primary` for overdue/today,
   `.secondary` otherwise (ShipBox's emphasis-on-bad rule). Undated dot is
   `.secondary` — no color picker, mirroring ShipBox's `.neutral`.
5. `totalsRow` on `.systemLarge` only, below a `Divider`, gated on
   `settings.showList` — the ShipBox `statusCount` shape, four buckets.
6. Family split: small = header + 2 rows; medium = header + `taskCount`;
   large = header + divider + totals + `taskCount`.
7. **Three distinct empty faces** (PRD §2): no snapshot → "No task data" + chip
   (or "Add org, project + PAT in Deck settings."); snapshot with `tasks: []` →
   "Nothing assigned"; all-undated → the normal face with `"N open"` and `—`
   rows. The third is the designed answer to §9 R2 and must be reachable.
8. `.containerBackground(for: .widget) { Color.clear }`; register
   `TaskBoxWidget()` in `DeckWidgetsBundle`.

**Verification**: `xcodegen generate`, then
`xcodebuild -project native/Deck.xcodeproj -scheme DeckApp -configuration
Release -derivedDataPath native/build.noindex -allowProvisioningUpdates
-allowProvisioningDeviceRegistration build` succeeds. Face rendering is verified
for real in Phase 7 (WidgetKit has no preview harness in this repo).

**Dependencies**: Phases 1, 3.

## Phase 6 — Back face + agent block

**Goal**: the user can configure TaskBox and the agent keeps it fed.

**Files touched**: `native/DeckApp/DeckApp.swift`,
`native/DeckAgent/main.swift`.

**Steps**:
1. `SettingsTab.taskbox` (after `.shipbox`), title `"TaskBox"`, SF Symbol
   `checklist`; route to `TaskBoxSettingsView(settings: $settings.taskbox)`.
2. `TaskBoxSettingsView` per PRD §2: **Azure DevOps** section (org, project,
   `SecureField` PAT with `.textContentType(.password)`, the caption naming
   *read-only Work Items (Read)* scope and the fact that **`@Me` resolves to the
   PAT's owner** — §9 C1), then `FetchStatusCaption(source: .taskbox,
   clearOn: "org␀project␀token")`; **Tasks** section (toggle, task-count
   stepper 2…8 disabled when the list is off, due-soon stepper 1…30);
   **Due colors** section (four pickers).
3. `refreshTaskBox()` mirroring `refreshShipBox()` at `DeckApp.swift:169`:
   guard on all three fields non-empty → else record `.notConfigured`; on
   success save + record `.ok`; on failure record
   `FetchClassifier.outcome(for:)` and **leave the last-good snapshot alone**.
   Call it from the same two places `refreshShipBox()` is called (window open,
   settings save) so a pasted PAT is verified immediately, not in 60s.
4. `DeckAgent` block after the ShipBox block, same shape: guard on trimmed
   org + project + token; on success **always write** (critique N2 — `writtenAt`
   drives the face's staleness window, so a quiet task list must not read as
   stale) and record `.ok`; on failure record the outcome and keep last-good;
   when unconfigured **record** `.notConfigured`, not just log it.
5. Agent logging stays URL-, token- and name-free: one line,
   `written / failed (<outcome>) / skipped (not configured) taskbox snapshot`.

**Verification**: Release build succeeds; `DeckApp.swift` diff shows the tab in
the enum, the title, the symbol, the view, and both `refreshTaskBox()` call
sites (a tab that exists but is never routed to is the classic miss here).

**Dependencies**: Phases 3, 4, 5.

## Phase 7 — Integration, live check, docs

**Goal**: prove it on the real machine against the real API, and register it.

**Files touched**: `README.md`, `ROADMAP.md`.

**Steps**:
1. Full Release build → `cp -R` to `/Applications/` → `open /Applications/Deck.app`
   → `pluginkit -m -i com.deck.app.widgets` confirms the extension registered.
   Build **only** into `native/build.noindex` (CLAUDE.md: a Spotlight-registered
   dev copy makes WidgetKit resolve the wrong bundle and every widget falls back
   to its placeholder; repair is `scripts/lsclean.sh`).
2. Add TaskBox from the Widget Center at **all three sizes**.
3. **Live check** — paste a real PAT in the settings tab:
   - correct org/project/PAT → tasks render; note whether any date field is
     populated (the §9 R2 answer);
   - deliberately wrong PAT → the caption must read *"Check org, project + PAT"*,
     **not** *"Unexpected Azure DevOps response"* (this is the 203 test, §9 C2,
     proven end-to-end rather than only in a unit test);
   - empty fields → *"Add org, project + PAT in settings"*.
4. **Regression sweep**: re-add all nine existing widgets from the gallery and
   confirm none fell back to a placeholder (CLAUDE.md: widgets must not regress
   between builds).
5. `README.md` — TaskBox entry in the widget list. `ROADMAP.md` — tick the M5
   TaskBox line; record any §9 R2 finding (e.g. "this org populates no
   scheduling field; TaskBox renders as an assigned-work list") so the next
   provider decision has it.
6. Final full suite run; report the test count delta from 325.

**Verification**: all nine prior widgets unregressed, TaskBox renders at S/M/L,
all three error copies observed on screen, suite green.
