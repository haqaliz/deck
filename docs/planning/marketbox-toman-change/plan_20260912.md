## Phase 1 — Builder policy (TDD)

**Goal:** `MarketBuilder` attaches the Toman anchor's 24h change to exactly
the row it describes — the fiat USD row in IRT/IRR displays — and nowhere
else.

**Files:** `native/Shared/MarketBoxCore.swift`, `native/SharedTests/MarketBoxCoreTests.swift`

**Steps:**
1. RED: In `MarketBuilderTests`, update `testBuildsAllKindsInIrt` to pass
   `tmnChange: 2.02` and assert `rows[1].dayChangePct == 2.02` (the USD row);
   add `testUSDRowInIrrCarriesTheSameChange`, `testUSDRowInUsdDisplayIsNil`,
   `testCadRowInIrtStaysPriceOnly`, `testMissingTomanChangeIsNil`. Run — the
   new assertions fail (fiat rows are built with `dayChangePct: nil`).
2. GREEN: Add `tmnChange: Double? = nil` to `MarketBuilder.build`; in the
   `.fiat` case, when `symbol == "USD" && (display == .irt || display == .irr)`,
   build the row with `dayChangePct: tmnChange`. Run — green.
3. REFACTOR: update the stale comments — `MarketRow.dayChangePct` ("crypto
   only" → crypto/stock + the IRT/IRR USD row), `WallexRate.change24h`
   ("unused in v1" → consumed by the builder).

**Verification:** `xcodebuild test -scheme DeckSharedTests` (MarketBoxCoreTests
group) green.

**Dependencies:** none.

## Phase 2 — Loader plumbing

**Goal:** the change survives from the Wallex payload to the builder.

**Files:** `native/Shared/MarketBoxSnapshot.swift`

**Steps:**
1. `fetchToman()` returns `WallexRate` instead of `Double` — still throws
   `invalidPayload` when `tomanPerUSDT` is nil; `change24h` stays optional
   (a rate without `24h_ch` is a valid tick, not a failure).
2. In `HostMarketLoader.fetch`, bind `let wallex = try await fetchToman()`
   and pass `tmn: wallex.tomanPerUSDT, tmnChange: wallex.change24h` to
   `MarketBuilder.build`.

**Verification:** full `DeckSharedTests` green (`WallexParserTests` already
proves `change24h` parses from the fixture); `xcodebuild build` for DeckApp
compiles the changed call sites (DeckAgent/main.swift:342 and
DeckApp/DeckApp.swift:752 call `fetch(settings:)`, whose signature is
unchanged).

**Dependencies:** Phase 1 (the `tmnChange` parameter must exist).
