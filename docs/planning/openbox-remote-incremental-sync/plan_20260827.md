## Phase 1 — `RemoteOpenCodeSync` pure core (TDD)

**Goal:** the state model, the per-session decision, the page merge, eviction
and the sidecar store — all pure, all unit-pinned before any transport changes.

**Files touched:**

- `native/Shared/RemoteOpenCodeSync.swift` (new)
- `native/SharedTests/RemoteOpenCodeSyncTests.swift` (new)
- `native/Deck.xcodeproj` (via xcodegen)

**Steps:**

1. RED: write `RemoteOpenCodeSyncTests` for the state codec — round-trip
   encode/decode, `version != 1` → nil, missing file → nil (via the store),
   corrupt JSON → nil (reads as absent, self-healing).
2. `RemoteOpenCodeSyncState` (Codable, Equatable): `version` (pinned to 1),
   `server`, `mode` (`incremental | fullFetch | singlePage`), `sessions`
   (`[String: SessionCursor { watermark, lastUpdated }]`), `messages`
   (`[RemoteOpenCodeAggregator.RemoteMessage]` — the decoded fields, never
   `parts`). GREEN.
3. RED: `plan(state:sessions:now:) -> [Plan]` — inactive session (updated <
   14d cutoff) → skip; `lastUpdated == updated` → skip; unknown session →
   page; `mode == .fullFetch` → fullFetch. GREEN.
4. RED: `merge(state:sessionID:page:hasNextCursor:) -> (state, needMore)` —
   dedupe by message id; watermark = max `created`; page count > limit (100)
   → flip `mode` to `.fullFetch`; page identical to previous page →
   `.singlePage`; all messages ≤ watermark → no merge, `lastUpdated` still
   advances; `needMore = hasNextCursor && page has created > watermark`
   (false when `.singlePage`). GREEN.
5. RED: `prune(state:now:)` — drop archive messages with `created < now - 13d`;
   drop `sessions` entries absent from the current `/session` list and older
   than 14 days. GREEN.
6. `OpenCodeSyncStore` (enum, next to `OpenCodeSnapshotStore`): `fileURL` =
   container + `opencode-cursor.json`; `load()`/`save()` via `AtomicFile`.
   GREEN. (Compiled into the widget extension too — no AppKit/Foundation-only
   deps, never called there.)

**Verification:** full `DeckSharedTests` suite green; existing
`RemoteOpenCodeAggregatorTests` untouched and still passing.

**Dependencies:** none.

## Phase 2 — dual-shape message decode (TDD)

**Goal:** `/session/{id}/message` decodes under both the envelope shape the
loader was built against (`[{info, parts}]`) and the flat shape current
servers serve (`[{...info, parts}]`) — without which the incremental path is
dead on modern servers (PRD §3).

**Files touched:**

- `native/Shared/RemoteOpenCodeSync.swift` (decode function)
- `native/SharedTests/RemoteOpenCodeSyncTests.swift` (fixtures)

**Steps:**

1. RED: fixture JSON for both shapes (envelope + flat, same message fields,
   `parts` present but ignored) → both decode to the same
   `RemoteOpenCodeAggregator.RemoteMessage` values.
2. `RemoteOpenCodeSync.decodeMessages(Data) throws -> [RemoteMessage]`: try
   `[RemoteMessageEnvelope]` first (the working path — no behavior change),
   fall back to a tolerant flat decoder (`decodeIfPresent` on every optional
   field, `parts` skipped). GREEN.
3. Move the envelope type into `RemoteOpenCodeSync` (it is transport-shape,
   not transport) and make the loader's message GET decode through it.

**Verification:** decode tests green; loader still compiles.

**Dependencies:** Phase 1 (the function lives in `RemoteOpenCodeSync`).

## Phase 3 — loader paging loop

**Goal:** `RemoteOpenCodeLoader.load` takes an optional previous state, runs
the per-session paging loop, and returns the new state; with `nil` state in,
behavior is byte-identical to today (full resync, no state out).

**Files touched:**

- `native/Shared/RemoteOpenCodeLoader.swift`
- `native/DeckAgent/main.swift` (call site compiles: pass `nil`, ignore out)

**Steps:**

1. New signature: `load(serverURL:token:state:) async throws ->
   (OpenCodeSnapshot, RemoteOpenCodeSyncState?)`.
2. Session-usage mode (any session has `cost`/`tokens`): unchanged — 1
   request, aggregate from sessions, **state passes through untouched** (the
   sidecar survives mode flips).
3. Message mode: `GET /session` → `plan` → for each planned session, the thin
   loop: fetch `limit=100` (+ `before` from `X-Next-Cursor` while
   `needMore`), feed to `merge`, stop on capability fallbacks. Errors throw
   `RemoteError` as today; the old state is never mutated in memory on error
   (persistence is the agent's job, Phase 4).
4. Aggregate over archive + new messages with the **existing**
   `RemoteOpenCodeAggregator.aggregate(sessions:messages:now:)`; prune; return
   `(snapshot, newState)`.
5. Update the agent call site to the new signature passing `nil` (full-resync
   behavior — exactly today's), so this phase ends with the app behaving
   identically and the state plumbing compiling.

**Verification:** suite green; `xcodebuild build -scheme DeckApp` green; agent
run manually still writes `opencode.json` (local mode — the incremental path
is dormant on this machine, verified by reading the live `settings.json`).

**Dependencies:** Phases 1–2.

## Phase 4 — agent wiring: sidecar persistence

**Goal:** the agent carries the cursor across ticks: load before the fetch,
persist (atomically, only when changed) after a successful tick.

**Files touched:**

- `native/DeckAgent/main.swift` (lines ~61–102)
- `native/Shared/RemoteOpenCodeSync.swift` (store, from Phase 1)

**Steps:**

1. Agent: `let state = OpenCodeSyncStore.load()` before the remote fetch;
   pass it to `load`.
2. On success: `OpenCodeSyncStore.save(newState)` **only when
   `newState != state`** (idle ticks write nothing); on failure: nothing —
   the old file stays, next tick's overlapping merge is idempotent (PRD §3).
3. The `opencode.json` unchanged-skip check (`main.swift:94`) is untouched —
   the sidecar never participates in snapshot equality.
4. Local mode: neither read nor write the sidecar (mode decision is
   `openBoxUsesRemoteServer`, untouched).

**Verification:** suite green; DeckApp build green; manual agent run: no
`opencode-cursor.json` appears in local mode (dormant-path honesty check —
the live incremental run needs a server URL, which no account has; the plan
accepts this and relies on Phase 1's unit coverage for the loop logic).

**Dependencies:** Phase 3.
