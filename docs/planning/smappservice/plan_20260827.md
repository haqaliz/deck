# SMAppService — implementation plan

Plan for `docs/planning/smappservice/prd.md` (approved 2026-08-27).
Repo: `native/` xcodegen project. New source files require
`xcodegen generate --spec native/project.yml` before building (silent-no-compile
trap, CLAUDE.md). All builds go into `native/build.noindex`; run
`scripts/lsclean.sh` after every Release build.

## Phase 1 — Pure policy cores + tests (TDD)

**Goal:** the two decision tables this feature needs, unit-pinned before any
I/O code consumes them.

**Files touched:**
- `native/Shared/AgentReconcilePolicy.swift` (new)
- `native/Shared/ProcessRefreshPolicy.swift` (new)
- `native/SharedTests/AgentReconcilePolicyTests.swift` (new)
- `native/SharedTests/ProcessRefreshPolicyTests.swift` (new)
- `native/project.yml` — nothing (Shared + SharedTests are already target sources; xcodegen picks up new files at regenerate)

**Steps:**
1. `ProcessRefreshPolicy.shouldSample(lastSampleAt: Date?, configuredInterval: Int, now: Date) -> Bool`:
   `nil` lastSampleAt → true (first run); `now.timeIntervalSince(lastSampleAt) >= Double(configuredInterval)` → true; else false.
2. `AgentRegistrationState` (neutral enum: `notFound`, `notRegistered`, `enabled`, `requiresApproval`) + `AgentReconcilePolicy.resolve(intent: Bool, state: AgentRegistrationState) -> [AgentAction]` with `AgentAction ∈ {register, unregister, adoptIntent(Bool)}`. The policy governs **launch-time reconciliation only** (mirror reality both ways); imperative register/unregister are the toggle handler's direct actions, never policy outputs:
   - (true, .enabled) / (true, .requiresApproval) → [] (already on / OS owns the prompt)
   - (true, .notFound) → [register] (fresh install; plist is in the bundle, register is ours to try)
   - (true, .notRegistered) → [adoptIntent(false)] (user disabled in System Settings; no fight — PRD §Failure behavior)
   - (false, .enabled) → [adoptIntent(true)] (user re-enabled in System Settings; mirror it)
   - (false, .notRegistered) / (false, .notFound) / (false, .requiresApproval) → []
3. Tests: throttle table (nil, exact boundary, one second under, 5s interval, 60s interval, future-dated lastSampleAt); reconcile table (all 8 combos).

**Verification:** `xcodegen generate --spec native/project.yml` then
`xcodebuild -project native/Deck.xcodeproj -scheme DeckSharedTests -derivedDataPath native/build.noindex test` — all new tests green; existing suite still green (agentAtLogin decode tests must keep passing — the settings key stays).

**Dependencies:** none.

**Dependencies:** none (can land with Phase 1).

## Phase 3 — DeckAgent: env role, throttle, always-write

**Goal:** the fast agent selects itself via `DECK_AGENT_ROLE` and honors the
configured interval even though its launchd tick is fixed at 5s.

**Files touched:**
- `native/DeckAgent/main.swift`

**Steps:**
1. Role selection: `let isFast = ProcessInfo.processInfo.environment["DECK_AGENT_ROLE"] == "processes" || CommandLine.arguments.contains("--processes")` — both paths select fast mode (PRD choice 2).
2. `sampleProcesses()`: load `DeckSettings.load().livebox.processRefreshInterval`; gate the sample on
   `ProcessRefreshPolicy.shouldSample(lastSampleAt: ProcessSnapshotStore.load()?.writtenAt, configuredInterval: interval, now: Date())`; when skipped, log `agentLog.info("skipped processes snapshot (throttled)")` and exit.
3. **Always-write:** remove the unchanged-skip equality check — every sampled snapshot is saved (fresh `writtenAt` every sample; PRD choice 4). Keep the log line distinguishing written vs throttled.
4. `--processes` manual runs keep working (arg path unchanged).

**Verification:**
- `xcodegen generate` (Shared unchanged, but harmless) + Release build.
- Run the built binary directly: `DECK_AGENT_ROLE=processes native/build.noindex/.../DeckAgent` twice with `processRefreshInterval` 60 in `settings.json` → second run logs `throttled` and does not rewrite `processes.json`.
- `DeckAgent --processes` still samples.
- Note: running the dev-built agent writes the dev machine's real container — expected; the end-to-end pass (Phase 5) reinstalls the app anyway.

**Dependencies:** Phase 1 (policy exists).

## Phase 4 — DeckApp: AgentService, reconcile, legacy cleanup

**Goal:** registration moves to `SMAppService`; the toggle mirrors reality;
legacy plists are retired with a one-release cleanup.

**Files touched:**
- `native/DeckApp/AgentService.swift` (new — app-only; thin I/O wrapper over `SMAppService`)
- `native/DeckApp/DeckApp.swift` — replace the plumbing, retarget the call sites, update General-tab strings

**Steps:**
1. `AgentService`: two `SMAppService.agent(plistName:)` instances
   (`"com.deck.agent"`, `"com.deck.agent.processes"`); `registerAll()` /
   `unregisterAll()` (first error stops, logged); `statuses() -> (main:
   AgentRegistrationState, processes: AgentRegistrationState)` mapping
   `SMAppService.Status` onto the Shared enum; both agents share one policy
   decision (they register/unregister as a pair).
2. Replace `installAgentIfNeeded` / `installAgent` / `plistValue` /
   `currentStartInterval` / `currentLogPath` / `runLaunchctl` with:
   - `legacyCleanup()`: `launchctl bootout gui/<uid>/<label>` for both labels
     (ignore failures) + delete both `~/Library/LaunchAgents/*.plist` files —
     runs **before** any registration this release only (label collision,
     PRD §Migration).
   - `reconcileAgents()`: `legacyCleanup()`; for the pair, `AgentReconcilePolicy.resolve`
     on (settings.agentAtLogin, status); apply actions: `register` →
     `AgentService.registerAll()`, `adoptIntent(b)` → `settings.agentAtLogin = b`
     (+ save when changed).
   - `removeAgents()`: `AgentService.unregisterAll()` + `legacyCleanup()` —
     used by the Uninstall button and by `eraseDeckData()` (unchanged call
     sites).
3. Call sites (`DeckApp.swift`):
   - `onAppear` (line ~154): `installAgentIfNeeded()` → `reconcileAgents()` —
     the toggle is now authoritative (fixes the relaunch-reinstalls quirk).
   - `onChange(of: settings)` (line ~185-189): **drop** `applyAgent()` —
     registration only reacts to the toggle, not to every settings change
     (PRD choice 5).
   - `onChange(of: settings.agentAtLogin)` (line ~190-192): `applyAgent()` →
     toggle-off → `removeAgents()`; toggle-on → `legacyCleanup()` +
     `AgentService.registerAll()`.
   - Keep creating `~/Library/Logs/Deck` (0700) at launch (PRD choice 3 — the
     documented layout stays true).
4. General tab strings: toggle caption points at System Settings → Login
   Items; Uninstall caption drops "deletes their LaunchAgent files" as the
   only mechanism ("unregisters the background agents"; the legacy file
   deletion becomes invisible cleanup). Registration failure surfaces as a
   short caption under the toggle (a `@State` string set by reconcile,
   cleared on success).

**Verification:**
- Release build + install to `/Applications` (replace **only** the bundle).
- First launch: `launchctl print gui/$(id -u)/com.deck.agent` and
  `.processes` show loaded; System Settings → General → Login Items lists both
  agents under "Allow in the Background"; `log show --last 2m --predicate
  'subsystem == "com.deck.agent"'` shows ticks.
- Toggle off → `launchctl print` fails for both; relaunch → still gone (new
  behavior); toggle on → back.
- Legacy: pre-seed `~/Library/LaunchAgents/com.deck.agent.plist` +
  `launchctl bootstrap` it, launch Deck → job replaced by the SMAppService
  registration, file deleted.
- Uninstall button → both unregistered, legacy files absent.
- `scripts/lsclean.sh` after the Release build.

**Dependencies:** Phase 2 (plists must be in the bundle for registration).
