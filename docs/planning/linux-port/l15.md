# L15 — Accessory batteries and named accounts

Closes the two functional gaps left after the widget and Flatpak work.

## BatBox accessories

- Devices with `scope=Device` or a `hid-*`/`hidpp_*` power-supply name are
  treated as accessories instead of system batteries.
- Name comes from `model_name` or `manufacturer`; percentage comes from
  `capacity`; the status is shown as the detail.
- Accessories use the same low-battery colour thresholds and a configurable
  row count.
- Fixture tests cover a HID mouse alongside a system battery and AC supply.

## Named credential accounts

- The old Azure-only account list is now a generic `accounts` list:
  `id`, `provider`, `label`, `organization`, `project`, `server_url`.
- Existing `azureAccounts` files migrate through a serde alias; the provider
  defaults to `azure`.
- Credentials now has a generic Accounts section with provider, label,
  organization/project, server/base URL and token fields.
- Widget selectors:
  - Tasks and PR: Azure account
  - Ship and PR: GitHub account
  - Logs: Elastic account (server URL overrides the base URL)
  - Metrics: Grafana account (server URL overrides the base URL)
  - Open: opencode account (server URL overrides the local/server URL)
- Daemon fetches and remote search use the selected account’s token id and
  target/server URL. Empty selection still uses the legacy provider token and
  the existing widget fields.

## Tests

- 127 core + 3 daemon + 3 GUI + 3 platform tests, fmt and clippy green.
- Old Azure account JSON migration test.
- BatBox HID accessory fixture test.

## Known gaps

- No physical Bluetooth accessory was available beyond the sysfs fixture.
- Named accounts now have their own Verify button; GitHub Enterprise still
  uses api.github.com.
- GitHub Enterprise server URLs are stored but the GitHub client still uses
  api.github.com.
