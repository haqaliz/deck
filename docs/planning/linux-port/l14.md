# L14 — Flatpak

A self-contained Flatpak bundle for desktop Linux.

## Manifest

`flatpak/io.github.haqaliz.deck.yml` targets `org.gnome.Platform//49` and
builds:

- `gtk4-layer-shell` 1.0.4
- `wl-clipboard` 2.2.1
- `curl` 8.11.1
- `git` 2.47.1
- Deck itself from `linux/`

The runtime supplies GTK4 and the Wayland/X11 stack. The extra modules keep
remote fetching, GitBox and ClipBox working inside the sandbox.

## Sandbox

- Network, Wayland, fallback X11, IPC and DRI.
- Home-directory access because GitBox scans configured repositories and
  OpenBox reads the local opencode database.
- StatusNotifierWatcher and Secret Service D-Bus names.
- Autostart and shortcut installers detect Flatpak and use
  `flatpak run io.github.haqaliz.deck`.
- `deckd` is available as `/app/bin/deckd`:

```bash
flatpak run --command=deckd io.github.haqaliz.deck --interval 60
```

## CI

`.github/workflows/linux-flatpak.yml` installs the GNOME 49 SDK and Rust
extension, builds with `flatpak-builder`, bundles
`deck_<version>_x86_64.flatpak`, uploads it as a workflow artifact and, on a
`linux-v*` tag, attaches it to the GitHub release with the other assets.

## Known gaps

- The manifest was syntax-checked with `flatpak-builder --show-deps`, but the
  Docker environment on this machine cannot create bubblewrap namespaces, so a
  full local Flatpak build was not possible. The CI job is the build authority.
- Tray depends on the host StatusNotifierWatcher.
- The sandbox needs `--filesystem=home` for GitBox/OpenBox, which is broader
  than ideal.
- `deckd` must be started separately; Flatpak cannot install a host systemd
  user service.
