# L6 Pi packaging and v1 smoke — verification

**Date:** 2026-11-20.
**Target:** Pi 4B (4GB), Pi OS Trixie, labwc 0.9.2, GTK 4.18.6.
**Artifact:** `deck_0.1.0_arm64.deb`, 3.6 MB, release build.

## Verified

- `VERSION=0.1.0 bash packaging/build-deb.sh` builds the three binaries, the
  desktop entry, the hicolor icon, the systemd user unit, README and Debian
  copyright into one package.
- `sudo dpkg -i deck_0.1.0_arm64.deb` installs cleanly; dependency resolution
  is from Pi OS Trixie. `deck --version` reports `0.1.0`.
- The installed `/usr/bin/deck-gui` runs under labwc, creates the
  LiveBox/NetBox/DevBox layer surfaces and answers the socket; search and
  settings work from the installed binaries.
  Screenshots: `evidence/l6-installed.png`, `evidence/l6-search.png`.
- `deckd --once` from `/usr/bin` writes the hello snapshot and status on a
  fresh XDG home.
- `sudo dpkg -r deck` removes the binaries and desktop/icon files while
  keeping `~/.config/deck` and `~/.local/share/deck`. Reinstalling restores
  the app.
- `deck --remove-shortcut` removes the marked labwc block and leaves the other
  bindings intact.
- The Settings General tab shows the no-keyring warning when `secret-tool` is
  absent; the package recommends `libsecret-tools`.
- The autostart toggle writes `~/.config/autostart/deck.desktop` pointing at
  the installed `/usr/bin/deck-gui`.

## Not tested / deferred

- Pi 5: no hardware. The package is `arm64` and should behave the same, but
  this is not claimed as tested.
- Secret Service: the Pi has no `secret-tool`/keyring, so the 0600 fallback is
  the active path. A desktop keyring round-trip is still L8/desktop work.
- The `.deb` is built but not yet published; L8 bundles it with the AppImage in
  the final release.
- No Flatpak (owner decision).
