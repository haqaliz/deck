# L11 — Settings cards, multi-account Azure, and environment checks

Third post-v1 pass: the remaining group-1/group-2 feature work plus the
platform checks that can run without a second physical desktop or a Pi 5.

## Settings

- **Section cards.** Every widget pane now draws each section in its own
  rounded card (macOS grouped-form style) instead of one card for the whole
  pane. The sidebar still uses the 190 px macOS layout. Evidence:
  [`l11-settings-livebox-cards.png`](evidence/l11-settings-livebox-cards.png).
- **Azure accounts.** Credentials can hold any number of Azure DevOps accounts
  (label, organization, project, token). Tasks and Pull requests choose an
  account from a picker; "Default" keeps the old single `azure` token and the
  Tasks organization/project fields. Removing an account deletes its token.
- `deck --check-credentials` prints the store kind and which credential ids
  are present, without printing tokens.

## Search

- **Remote log search.** A `log …` query runs a full-text Elasticsearch query
  against the configured LogBox index, maps the hits through the local scorer
  and opens the message in Kibana Discover. The same 60-second cache and
  per-source 429 backoff as work items and PRs apply.
- The **Market picker** now searches Yahoo Finance as well as CoinGecko, so
  stocks and ETFs can be added alongside coins.
- Remote search, cache and 429 handling now cover work items, PRs and logs;
  Metrics remains snapshot-only.

## Platform checks

These ran in Debian Trixie arm64 containers, using the release `.deb`:

- **Sway headless (wlroots).** Layer-shell widgets render on the bottom layer,
  the search panel opens on the overlay layer, and the tray degrades cleanly
  without a StatusNotifierWatcher. Evidence:
  [`l11-sway-widgets.png`](evidence/l11-sway-widgets.png),
  [`l11-sway-search.png`](evidence/l11-sway-search.png).
- **X11 + Openbox.** Widgets receive
  `_NET_WM_WINDOW_TYPE_DESKTOP`, `_NET_WM_STATE_BELOW`,
  `_NET_WM_STATE_SKIP_TASKBAR` and `_NET_WM_STATE_SKIP_PAGER`; the search card
  becomes opaque on non-composited X11 so the desktop does not show through.
  Evidence:
  [`l11-x11-widgets.png`](evidence/l11-x11-widgets.png),
  [`l11-x11-search.png`](evidence/l11-x11-search.png),
  [`l11-x11-window-hints.txt`](evidence/l11-x11-window-hints.txt).
- **Secret Service.** With `gnome-keyring` and `secret-tool` under a D-Bus
  session, the store reports `secret-service`, stores a GitHub token and reads
  it back through `deck --check-credentials`. Evidence:
  [`l11-keyring.txt`](evidence/l11-keyring.txt).

## Verification

- 118 core + 3 daemon + 3 GUI + 3 platform tests, fmt and clippy green.

## Still platform-blocked

- **KDE Plasma / GNOME Wayland**: no desktop machine. KDE shortcut code is
  unit-tested, not exercised against KWallet/KGlobalAccel.
- **Pi 5 and a fresh Pi OS image**: no hardware.
- **Live GitHub/Azure/Elastic/Grafana/opencode**: no accounts or server; the
  remote code is fixture/unit tested.
- **Multi-monitor**: Xvfb does not expose multiple GDK monitors; the automatic
  column-to-next-monitor path remains unverified.
- **macOS vibrancy blur**: GTK layer surfaces have no compositor blur protocol
  binding. The search card keeps its translucent fill.
