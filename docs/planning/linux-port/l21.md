# L21 — apt repository and a unique package name

Groundwork for `apt install` and the later official Debian/Ubuntu package.

## Why the package changed name

Debian already ships a package called **`deck`** (Kong's configuration CLI),
which owns `/usr/bin/deck`. Installing our old package under the same name
replaced it, and a later apt upgrade could replace our files again. Our package
is now **`deck-desktop`** and our CLI is **`deckctl`**, so both packages can
coexist. `deck-gui` and `deckd` were already unique.

## Signed apt repository

- `scripts/build-apt-repo.sh` downloads the newest `linux-v*` arm64 `.deb`,
  writes `dists/stable/main/binary-arm64/Packages`, `Release`, `InRelease` and
  `Release.gpg`, and copies the public key to `apt/key.asc`.
- The Pages workflow builds it on every site deploy and on `release: published`.
- Users add the key and source once, then run `sudo apt install deck-desktop`.
- The apt repository is ARM64 only for now; x86_64 remains AppImage/Flatpak.

## Official Debian/Ubuntu later

`deck-desktop` is now free of the package and file-name conflicts that would
have blocked a Debian ITP or Ubuntu review. Official inclusion still needs a
source package, Rust dependency packaging or vendoring, and a sponsor.

## Verification

- `scripts/build-apt-repo.sh` tested on the Pi with a local `.deb`; `gpg
  --verify` accepts the generated `InRelease`.
