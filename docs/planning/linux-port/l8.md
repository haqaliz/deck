# L8 hardening and v0.1.0 release — verification

**Date:** 2026-11-20.
**Target:** Pi 4B / Trixie / labwc; x86_64 AppImage built in Debian Trixie CI.

## Hardening

- **Crash handling**: the GUI and daemon install panic hooks that write
  `last-error.log` / `deckd-last-error.log` under `$XDG_CACHE_HOME/deck`.
  Settings → General shows the first line of the GUI's last crash. The helper
  is unit-tested.
- **Offline/timeout/429**: every fetch already keeps the last good snapshot.
  HTTP 429 now maps to the `rateLimited` outcome, with the face copy “Rate
  limited — showing the last data”. The contract schema includes the value.
- **Config migration**: a settings file with no `schema_version` now reads as
  version 1 instead of 0; corrupt files are still moved aside and replaced by
  defaults. Both paths are tested.
- **Security**: tokens are passed to `curl` on stdin (never argv), header
  values cannot inject config lines, snapshots/settings/status never carry a
  token, and every remote URL used by an action must be `http(s)` with a host.
  No fetch writes to a remote service.
- **Performance**: release build, default cadence. 60 s: 0.53% CPU / 119 MB
  RSS. 30 min: 0.57% CPU, RSS 115260 → 115956 kB. Details in
  [`l8-perf.txt`](l8-perf.txt).
- `cargo fmt`, `cargo clippy --workspace --all-targets -- -D warnings` and
  `cargo test --workspace` are green (102 core + 3 daemon tests).

## v0.1.1 patch

The first post-release fix makes widget and search windows movable: header
drags update layer margins (or the normal-window handle), save `positions` in
settings and restore them on the next start. The `Linux deb` workflow builds
the arm64 package on GitHub's arm64 runner; the AppImage workflow was re-run.
Artifacts: `deck_0.1.1_arm64.deb` and `deck_0.1.1_x86_64.AppImage`.


## v0.1.2 patch

The movable-window fix needed a second part on labwc: PCManFM's desktop window
covers bottom-layer surfaces for input, so Deck now installs a marked labwc
`windowRule` (`ToggleAlwaysOnBottom` for pcmanfm) before creating widgets. The
drag gesture is attached at the window level and limited to the header band,
so a header drag works even though a label does not receive the press directly.
Verified on the Pi with a virtual uinput mouse: LiveBox moved and its position
survived a restart; the search panel moved too. Artifacts:
`deck_0.1.2_arm64.deb` and `deck_0.1.2_x86_64.AppImage`.
