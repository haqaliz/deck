# L7 desktop backends and AppImage — verification

**Date:** 2026-11-20.
**Target:** Pi 4B / Trixie / labwc for the X11 smoke; Debian Trixie x86_64 CI
for the AppImage.

## Verified

- **Surface override**: General → Widget surface offers Auto-detect, Layer
  shell, X11 desktop and Dashboard. The choice is applied at startup; Layer
  shell remains the default where available.
- **X11 backend**: with `surface_mode: "x11"`, `WAYLAND_DISPLAY` unset and
  `GDK_BACKEND=x11`, the GUI runs through Xwayland. `xprop` shows every widget
  window carrying `_NET_WM_WINDOW_TYPE_DESKTOP` and
  `_NET_WM_STATE_BELOW, _NET_WM_STATE_SKIP_TASKBAR,
  _NET_WM_STATE_SKIP_PAGER`, and the window is marked non-focusable.
  Screenshot: `evidence/l7-x11.png`.
- **Dashboard fallback**: the same normal-window path is used for GNOME
  Wayland; no layer-shell call is made. This is the documented fallback, not a
  claim that GNOME gets desktop widgets.
- **Movable windows**: widget headers and the search header are drag handles.
  On layer surfaces they update the margins and save the position in
  `settings.json`; on normal X11/GNOME windows they use a client-side
  `WindowHandle`. Verified on the Pi with a virtual uinput mouse: LiveBox moved
  to and restored from a saved position, and the search panel moved. Saved
  positions are also shown in headless sway
  (`evidence/movable-widgets.png`, `evidence/movable-search.png`).
- **labwc input**: PCManFM's desktop window sits above bottom-layer surfaces
  and blocks pointer input. Deck installs a marked labwc `windowRule` that puts
  it on the always-on-bottom layer; with it, the widgets receive drags.
- **Multi-monitor flow**: the three-column flow moves a full column to the
  next monitor and resets, so a multi-monitor desktop fills before stacking.
  Widgets and the search panel can also be dragged by their title/header; the
  position is saved in settings and restored on the next start, overriding the
  flow.
- **Shortcuts**: `deck --install-shortcut` now chooses by desktop:
  - GNOME: writes `custom-keybindings` plus a `deck` keybinding
    (`<Super>space`) through `gsettings`, preserving existing entries. The
    list merge is unit-tested; no GNOME machine was available.
  - labwc: the existing marked `W-Space` block installer.
  - KDE, Sway, Hyprland, generic X11: prints the correct command binding
    instead of editing a config it does not own.
- **AppImage**: `packaging/build-appimage.sh` stages the three binaries,
  desktop file and icon, bundles GTK4/gtk4-layer-shell with `linuxdeploy` and
  the GTK plugin, and writes `deck_0.1.0_x86_64.AppImage` with a SHA256. The
  `Linux AppImage` workflow runs it inside Debian Trixie on GitHub Actions
  and uploads the artifact.

## Not tested / deferred

- KDE Plasma, GNOME Wayland, Hyprland/Sway and XFCE/i3 were not available as
  machines. Their backends are the shared layer-shell/normal-window paths, but
  the matrix is not claimed as tested.
- The X11 hints are set correctly, but labwc's Xwayland integration still tiles
  the windows and lists them in its panel. A native X11 WM may honor the
  desktop type; this Pi run cannot prove it. X11 placement is left to the WM.
- PCManFM's desktop rule is specific to labwc; other desktops use their own
  bottom/desktop handling and were not available to test.
- Multi-monitor behavior has no second display to exercise.
- The AppImage has not been launched on a clean Ubuntu/Fedora desktop. It
  contains GTK4 and the layer-shell library, but FUSE/runtime checks remain a
  release smoke item.
- KDE KGlobalAccel/portal shortcut writing is not implemented; the command
  snippet is the fallback.
