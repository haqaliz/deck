# Plan — azure-multi-org

**Date:** 2026-10-19 · **Branch:** `feat/azure-multi-org/aliz`
**PRD:** `docs/planning/azure-multi-org/prd.md` (approved) · **Understanding:** `understanding.md`

Bind the `.taskbox` and `.prboxAzure` slots to **up to 4 Azure accounts** and
merge their results. Each account is unchanged (one org, its projects, its own
PAT). The task is mostly a **data-model + merge** task; the widget faces do not
change.

## Ground rules for every phase

- **xcodegen first for any new file.** A new `.swift` file is silently not
  compiled until `xcodegen generate --spec native/project.yml`; the suite still
  reports success. Run it after adding or removing a file.
- **Build/test commands:**
  ```bash
  xcodegen generate --spec native/project.yml
  xcodebuild test -project native/Deck.xcodeproj -scheme DeckSharedTests \
    -derivedDataPath native/build.noindex CODE_SIGNING_ALLOWED=NO
  xcodebuild -project native/Deck.xcodeproj -scheme DeckApp -configuration Release \
    -derivedDataPath native/build.noindex -allowProvisioningUpdates \
    -allowProvisioningDeviceRegistration build
  ```
- **TDD:** every pure rule is RED → GREEN in `DeckSharedTests` in the same phase
  it is introduced. Tests ship with the code, never after.
- **Green at the end of every phase**: the suite passes and the Release build
  succeeds. Commit per phase.
- **Never touch `native/DeckWidgets/`.** The faces are unchanged; the two greps
  stay clean:
  `grep -rn "\.enabled\|serverURL" native/DeckWidgets/` and
  `grep -rn "HostCoinSearchLoader\|HostStockSearchLoader\|HostGitHubPRLoader.search\|HostAzureDevOpsLoader.search\|HostGitCommitSearch\|HostEventSearch" native/DeckAgent native/DeckWidgets`.
- **Live work needs Deck quit** (`pgrep -lf "MacOS/Deck$"`), settings edited
  never by hand while it runs.

## Deviations from this plan (recorded during implementation)

1. **Rows carry `organization` unconditionally**, populated by the parser from
   the target — not stamped by the merge. So a *single-account* snapshot gains
   the additive `organization` field on Azure rows and the org-qualified Azure
   PR id (`azureDevOps:{org}/{project}/{repo}#{n}`). The **face** is unchanged
   (the label only qualifies when the rows span more than one org). Phase 5's
   "byte-identical" bar is therefore read as *identical apart from those additive
   fields*.
2. **`PRFormatting.deduped`'s key gained the `project` too**, not just the org.
   The key was `(provider, repo, number)`, which already collapsed two projects'
   same-named repos with the same PR number — a latent multi-project bug this
   fixes incidentally.
3. **The task merge sorts globally** (newest-first, tiebreak organization then
   id) rather than round-robin interleaving. A global sort is total and
   deterministic and matches the single-account order; the PRD's "interleave"
   wording was about determinism, not a fair-share policy.
4. **`resolvedCredentials` excludes ids in `unavailable`** — a real behaviour fix
   the tests caught: without it, a bound account whose keychain read failed was
   still fetched when a token happened to be in memory.
5. **The live single-org agent run (Phase 5) was not performed.** It needs the
   installed `/Applications/Deck.app` replaced with an unsigned dev build and the
   user's live snapshots rewritten; that is invasive and is handed back as a
   manual check rather than run here.

## Recorded follow-ups (not built here)
- **The live two-org run** — needs a second Azure organization + PAT. Unit tests
  are the whole surface on this machine.
- **Per-account row caps or per-account sprint chips** — deliberately one face.
- **A second TaskBox provider** (Jira/Linear) and **Entra/AAD auth** — separate
  work; the PRD's non-goals.

## Risk register

| Risk | Mitigation |
|---|---|
| `.fetch` list change ripples to ~26 sites | Phase 2 is mechanical, single-element lists keep single-slot tests meaning-identical |
| Hand-written `CodingKeys` forgetting a field | Phase 1's round-trip test covers every field |
| A bound account silently dropped | Phase 4's note names every non-contributor; Phase 2 pins mixed `unavailable` |
| Merge drift between agent and host | Phase 4's merge is one pure `Shared/` function; Phase 5 mirrors call sites only |
| PRBox dropped row across orgs | Phase 3's `Set(ids).count == ids.count` test |
