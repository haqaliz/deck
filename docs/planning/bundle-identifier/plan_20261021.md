# Plan — bundle-identifier flip (#77)

The runbook (`flip-runbook.md`, in this directory) is the step-by-step plan and
was written for exactly this change; this file only records what differs.

## What differs from the runbook

1. **Sequencing.** The flip no longer waits for notarization — M9 is deferred by
   the owner (2026-10-21). With no users, one re-grant now is cheaper than
   holding the item open for an indefinite period.
2. **No version bump here.** `CFBundleShortVersionString` stays at 1.57; the
   release commit bumps it and tags, as every release does. Bumping in the flip
   commit would publish a version that does not exist.
3. **Installed-copy gate is not run in this change.** Installing the renamed
   build re-parents BTM records and forces the owner to re-add all fourteen
   widgets and re-grant TCC. That is the release step, not the merge step; the
   roadmap item stays unchecked until it passes.

## Phases

1. Constants: `DeckBundle.appID` / `agentLabel`, `scripts/lib/ids.sh`.
2. Build: `project.yml` prefix, three identifiers, DeckAgent's explicit
   `PRODUCT_BUNDLE_IDENTIFIER`, the tests' identifier, the embed step.
3. Plists: `git mv` both to the new names; re-add the old pair for one release
   plus `AgentService.unregisterLegacy()`, guarded so it is a no-op before the
   rename.
4. Docs: README, Homebrew cask (both containers on zap), issue template,
   CLAUDE.md, script comments.
5. Verify: clean Release build — `codesign` identifiers, the four plists, the
   `grep` gate; unit suite.
