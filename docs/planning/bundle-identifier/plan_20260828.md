# Implementation plan — bundle identifier rename

**Slug:** `bundle-identifier` · **Date:** 2026-08-28
**From:** `docs/planning/bundle-identifier/prd.md` (approved, incl. self-critique)

## Note on verification commands

The `deck-plan` skill's template predates this repo's move to xcodegen — there
is no `Package.swift`, so `swift build` / `swift test` / `swift run --debug-flip`
do not exist here. The real equivalents, matching `.github/workflows/deck.yml`:

```bash
xcodegen generate --spec native/project.yml            # after ANY new source file
xcodebuild test -project native/Deck.xcodeproj -scheme DeckSharedTests \
  -derivedDataPath native/build.noindex CODE_SIGNING_ALLOWED=NO
xcodebuild -project native/Deck.xcodeproj -scheme DeckApp -configuration Release \
  -derivedDataPath native/build.noindex -allowProvisioningUpdates \
  -allowProvisioningDeviceRegistration build
scripts/lsclean.sh                                     # after every release build
```

**xcodegen enumerates files at generation time**, so a new test file that is not
followed by `xcodegen generate` is silently not compiled and the suite still
reports success (CLAUDE.md). Every phase that adds a file regenerates first.

## Shape of the work

Nine phases in three groups:

- **Phases 1–3 — probe.** Answer O1/O2 and R2/R3 on a real renamed build before
  writing the migration. One-way on this machine (R4); done first because the
  answers change phases 4–6.
- **Phases 4–7 — dormant implementation.** Source of truth, migration, notice,
  agent wiring. Ships invisibly in the next release; ids stay `com.deck.*`.
- **Phases 8–9 — the flip.** A single prepared commit, held for the
  notarization release, plus the docs/distribution pass.

Phases 1–7 land on this branch. Phases 8–9 are written up as a runbook and
**not merged in flipped form** — per the approved sequencing.

## Phase 1 — Pre-probe: capture the current state

**Goal:** record what "healthy" looks like, so the probe's effect is legible.

**Files touched:** `docs/planning/bundle-identifier/probe.md` (new).

**Steps**

1. `pgrep -lf "MacOS/Deck$"` — confirm Deck is **not** running. A running Deck
   overwrites both `settings.json` and the snapshots with its in-memory copy
   (CLAUDE.md), which would make every later observation untrustworthy.
2. Record: `ls -la ~/Library/Containers/com.deck.app.widgets/`,
   `stat -f '%Sm %N' ~/Library/Containers/com.deck.app.widgets/Data/Library/Application\ Support/Deck/*.json`,
   `pluginkit -m -i com.deck.app.widgets`, `launchctl list | grep com.deck`,
   `sfltool dumpbtm | grep -A5 -i deck`, and
   `codesign -dv /Applications/Deck.app/Contents/MacOS/DeckAgent 2>&1 | grep Identifier=`.
3. Back up `settings.json` to the scratchpad — it holds the five token
   *references* and every colour; the probe must not be able to cost it.

**Verification:** `probe.md` contains the six baseline outputs.
**Dependencies:** none.

## Phase 2 — Probe build: one renamed Deck, the real new id

**Goal:** answer O1 (does containermanagerd adopt a hand-made container?) and
R2 (what does a renamed agent sign as?) on a real build.

**Files touched:** none committed — a scratch edit to `native/project.yml`,
reverted at the end of the phase.

**Steps**

1. Remove Deck's widgets from the desktop first (CLAUDE.md: uninstall order).
2. Edit `project.yml` to the real target ids (`io.github.haqaliz.deck`,
   `.widgets`, `.agent`, `.agent.processes`), set DeckAgent's
   `PRODUCT_BUNDLE_IDENTIFIER` explicitly (R2), rename the two LaunchAgent
   plists and their `Label`s, and bump to a probe version.
   **One id only** — R4: each distinct id leaves a permanently undeletable
   container, so the artefact left behind must be the one the product will use.
3. `xcodegen generate` → Release build → `scripts/lsclean.sh`.
4. `codesign -dv` all three binaries; record `Identifier=` for each. Confirms
   whether the `__info_plist` section still wins for the agent.
5. Install to `/Applications` (replacing), launch, add **one** widget.
6. Observe, in order: does `~/Library/Containers/io.github.haqaliz.deck.widgets/`
   exist before the extension first runs? Does it have a
   `.com.apple.containermanagerd.metadata.plist`? Does the widget render?

**Verification:** the widget renders at all three sizes from the new container,
**or** it does not and `probe.md` records the chronod line
(`log show --predicate 'process == "chronod"'`) that says why. Both outcomes are
findings; a blank widget here is the O1 answer, not a failure of the phase.

**Dependencies:** Phase 1.

## Phase 3 — Probe: registrations, and the old agent's fate

**Goal:** answer O2 and R3 — what happens to the old BTM record and the old job.

**Steps**

1. With the renamed Deck installed over the old path, `sfltool dumpbtm` and
   `launchctl list | grep -i deck`: is the old `com.deck.agent` record still
   present, still `[enabled, allowed]`, and is its job running?
2. If it is running, `ps` its executable path and confirm R3's prediction: the
   old label is executing the **new** `DeckAgent` binary via `BundleProgram`.
3. Check whether the new binary wrote snapshots into the *new* container from
   default settings (the R3 damage), by `stat` mtimes against Phase 1's.
4. Attempt `SMAppService` unregister of the old plist name from the renamed
   app; record whether it succeeds, throws, or silently no-ops. Fall back to
   `launchctl bootout gui/$(id -u)/com.deck.agent` and re-check `dumpbtm`.
5. Restore: reinstall the real (unrenamed) Deck from a clean Release build,
   restore `settings.json` from the Phase 1 backup, re-add the widgets, and
   confirm the original container is serving again.

**Verification:** `probe.md` answers O1, O2 and R3 with commands and outputs,
and the machine is back on `com.deck.*` with settings intact.
**Dependencies:** Phase 2.

**Commit:** `docs(bundle-identifier): probe — container provisioning, signing identity, old-agent fate`

## Phase 4 — `DeckBundle`: the identity constants, with a drift test (TDD)

**Goal:** one place naming the current and legacy ids, pinned against the build.

**Files touched:** `native/Shared/DeckBundle.swift` (new),
`native/SharedTests/DeckBundleTests.swift` (new).

**Steps (RED → GREEN)**

1. **RED:** write `DeckBundleTests` asserting (a) `DeckBundle.widgetsID ==
   DeckBundle.appID + ".widgets"` — true in both the old and new schemes, so it
   survives the flip; (b) the legacy constants are exactly
   `com.deck.app` / `com.deck.app.widgets` / `com.deck.agent` /
   `com.deck.agent.processes` and are **never** equal to the current ones after
   the flip; (c) the drift guard from R1 — read the app `Info.plist` from the
   test bundle's build products and assert `CFBundleIdentifier` equals
   `DeckBundle.appID`. Run; it fails to compile.
2. **GREEN:** add `DeckBundle` with `appID`, `widgetsID`, `agentLabel`,
   `fastAgentLabel`, `logSubsystem`, and a `legacy` enum holding the four old
   values with a comment marking them permanent (they name a container that
   exists on users' disks forever).
3. `xcodegen generate` (two new files) then run the suite.

**Verification:** `xcodebuild test -scheme DeckSharedTests` — suite passes and
`Executed [1-9][0-9]* test` (CI's own guard against a silently empty target).
**Dependencies:** Phase 3 (the probe may rename a constant).

## Phase 5 — Route every Swift call site through `DeckBundle`

**Goal:** no Swift literal names an identifier except `DeckBundle.legacy`.

**Files touched:** `native/Shared/DeckSettings.swift:181`,
`native/DeckApp/AgentService.swift:35-38`, `native/DeckApp/DeckApp.swift:491`,
`native/DeckAgent/main.swift:25`.

**Steps**

1. `DeckSettings.containerDirectory` builds its path from
   `DeckBundle.widgetsID`. The sandboxed branch is untouched — inside the
   extension `homeDirectoryForCurrentUser` already *is* the container.
2. `AgentService` derives both plist names (`"\(label).plist"`) and labels from
   `DeckBundle`.
3. `legacyCleanup()` iterates `DeckBundle.legacy` labels — it is *already* a
   legacy sweep, so it keeps naming the old ids by definition.
4. `DeckAgent`'s `Logger(subsystem:)` takes `DeckBundle.logSubsystem`.
5. `grep -rn '"com\.deck' native/ --include=*.swift` → only `DeckBundle`.

**Verification:** grep is clean; `xcodebuild test` green; Release build green;
`scripts/lsclean.sh`. Ids are still `com.deck.*`, so the built app must behave
identically — re-add one widget and confirm it renders.
**Dependencies:** Phase 4.

## Phase 6 — The migration, as pure policy first (TDD)

**Goal:** decide-then-do, with the decision unit-tested and the I/O thin.

**Files touched:** `native/Shared/ContainerMigration.swift` (new),
`native/SharedTests/ContainerMigrationTests.swift` (new).

**Steps (RED → GREEN)**

1. **RED:** `ContainerMigrationPolicy.decide(oldExists:oldSettingsExists:
   newSettingsExists:) -> Decision` with `.copy` / `.skip(reason:)`, covering
   the PRD's four states: no old container → skip (fresh install); old
   container but no `settings.json` → skip; new `settings.json` present → skip
   (**never overwrite**); otherwise → copy. Assert `.skip` reasons are
   distinguishable — the repo's standing rule that "absent" and "failed" must
   never collapse (`SecretRead`, `FetchOutcome`).
2. **GREEN:** implement the policy (pure, no `FileManager`).
3. Add `ContainerMigration.run()`: resolves the two paths from `DeckBundle`,
   asks the policy, and on `.copy` creates the destination directory and copies
   **`settings.json` only** (PRD scope B), preserving 0600. Idempotent.
   **Never** deletes or moves anything in the old container (the SIP trap).
4. Return a result the caller can render: `.migrated`, `.skipped(reason)`,
   `.failed(Error)`.

**Verification:** suite green with the four policy cases plus a round-trip test
driving `run()` against two temp directories (not the real container).
**Dependencies:** Phase 4.

## Phase 7 — Wire the migration into both entry points, and the notice

**Goal:** the migration runs whoever starts first (R3), and the user is told
their widgets need re-adding.

**Files touched:** `native/DeckAgent/main.swift`, `native/DeckApp/DeckApp.swift`,
`native/Shared/DeckSettings.swift` (`didShowRenameNotice`),
`native/SharedTests/DeckSettingsTests.swift`.

**Steps**

1. Call `ContainerMigration.run()` at the top of `DeckAgent.main`, **before**
   `DeckSettings.load()` — R3: after the flip the old BTM record launches the
   new binary under the old label, so the agent can genuinely be first.
2. Call it in the app at launch, before settings load and before
   `reconcileAgents()`.
3. Add `didShowRenameNotice: Bool = false` to `DeckSettings` with tolerant
   decode (the established pattern) and a regression test that an older
   `settings.json` without the key still decodes. **A4:** it is written to the
   *new* container, so it cannot loop.
4. General tab: when the last migration was `.migrated` and
   `!didShowRenameNotice`, show a dismissible notice — "Deck's identifier
   changed. Remove and re-add your widgets from the Widget Center." On
   `.failed`, say instead that settings could not be carried over, and name the
   old file's path.
5. Both notices sit alongside the existing `agentNotice` in General, reusing
   its presentation rather than inventing one.

**Verification:** suite green; Release build; `scripts/lsclean.sh`. Manual: with
ids still `com.deck.*` the migration must decide `.skip` (old and new resolve to
the same path) and **no notice appears** — the dormant state must be invisible,
which is A1's requirement and the main risk of shipping it early.
**Dependencies:** Phases 5, 6.

**Commit boundary:** phases 4–7 merge as the dormant implementation.

## Phase 8 — The flip, prepared but held

**Goal:** one reviewable commit that the notarization release cherry-picks.

**Files touched:** `native/project.yml`, `native/Shared/DeckBundle.swift`,
`native/DeckApp/LaunchAgents/*.plist` (renamed),
`native/{DeckApp,DeckWidgets,DeckAgent}/Info.plist` (regenerated).

**Steps**

1. `DeckBundle` current ids → `io.github.haqaliz.deck*`.
2. `project.yml`: three `PRODUCT_BUNDLE_IDENTIFIER`s, DeckAgent's
   `CFBundleIdentifier` **and** an explicit `PRODUCT_BUNDLE_IDENTIFIER` (R2,
   killing the synthesised `com.deck.DeckAgent`), `bundleIdPrefix`,
   `com.deck.sharedtests`, and the two plist filenames in the copy step.
3. `git mv` the two LaunchAgent plists; update their `Label`s.
4. Bump `CFBundleShortVersionString` / `CFBundleVersion` on all three targets
   (A2 — cheap, and the failure it prevents is silent).
5. `xcodegen generate` and commit the regenerated `Info.plist`s (A3 — they are
   tracked; without them the agent keeps the old identity).
6. Written to `docs/planning/bundle-identifier/flip-runbook.md`, **not merged
   in flipped form** on this branch.

**Verification (at flip time, on the installed copy):**
`codesign -dv` on all three binaries reports the new identifiers (R2);
`pluginkit -m -i io.github.haqaliz.deck.widgets`; both agents in Login Items
under new labels; old labels gone from `launchctl list`; `settings.json` present
in the new container with the user's colours; all fourteen widgets re-add and
render at three sizes; `grep -rn "com\.deck" native/ scripts/ homebrew/ README.md`
returns only `DeckBundle.legacy` and the documented legacy sweep.
**Dependencies:** Phase 7 + the probe's answers.

## Risk register

| Risk | Phase | Mitigation |
|---|---|---|
| Probe leaves an undeletable container | 2 | One id, and it is the real one (R4) |
| Hand-made container poisons provisioning | 2 | The probe's whole purpose; `container-repair.sh` is the recovery |
| Old BTM record cannot be unregistered | 3 | Measured, not assumed; `launchctl bootout` is the fallback |
| Dormant migration fires early and eats settings | 7 | Policy never overwrites an existing `settings.json`; verified `.skip` while ids are unchanged |
| xcodegen silently omits a new test file | 4, 6 | `xcodegen generate` in the phase; CI asserts a non-zero test count |
| Deck running during the probe corrupts observations | 1 | `pgrep -lf "MacOS/Deck$"` gate first |
