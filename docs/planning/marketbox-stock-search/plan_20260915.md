## Phase 1 — `StockSearchHit` + `StockSearchParser` + live fixture

**Goal.** Search hits parse out of a captured Yahoo payload, with the noise
filter the interview chose.

**Files.** `native/Shared/StockSearch.swift` (new — the `CoinSearch.swift`
mirror), `native/SharedTests/Fixtures/yahoo_search_apple.json` (new),
`native/SharedTests/StockSearchTests.swift` (new).

**Steps.**
1. Capture the live `q=apple&quotesCount=8&newsCount=0&listsCount=0` payload
   (app-like UA — probe-measured safe) into `Fixtures/yahoo_search_apple.json`.
2. **RED** — `StockSearchTests`:
   - the fixture parses to 8 hits, first is `AAPL`/`Apple Inc.` with
     `exchange: "NMS"`, `type: "Equity"`;
   - **the filter**: `SAAPL=F` and `XAAPL=F` (FUTURE) are dropped; `AAPX`
     (ETF) and `APLE` (EQUITY, unrelated company) are kept — the interview's
     "filter noise, label the rest";
   - server order preserved (no re-sort — the `CoinSearchParser` precedent);
   - `longname` preferred, `shortname` fallback (a hit with only `shortname`);
   - an entry with no `symbol` is dropped; `{"quotes":[]}` → `[]`; garbage →
     `nil` (the `CoinSearchParser` contract);
   - a hit converts to a `MarketTicker` with `symbol == stockSymbol` (raw
     Yahoo symbol, e.g. `^GSPC`) and `kind == .stock`.
3. **GREEN** — `StockSearchHit` (`symbol`, `name`, `exchange`, `type`) and
   `StockSearchParser` in `StockSearch.swift`: reads only `quotes`, keeps
   `quoteType ∈ {EQUITY, INDEX, ETF}` (the PRD §3 filter), else drops.
4. `xcodegen generate` (two new files) + suite.

**Verification.** The suite. Plus a one-off check that the fixture file is the
real captured payload (byte size ~2.5 KB, contains `SAAPL=F`).

**Depends on.** Nothing.

## Phase 2 — `HostStockSearchLoader`

**Goal.** The host-app-only search loader, shaped like `HostCoinSearchLoader`
and pinned to the probe's two load-bearing rules.

**Files.** `native/Shared/StockSearch.swift`, `native/SharedTests/StockSearchTests.swift`.

**Steps.**
1. **RED** — loader tests:
   - `url(for: "purple pepe")` is percent-encoded and carries
     `quotesCount=8&newsCount=0&listsCount=0` (constants pinned);
   - `a&b=c` cannot inject a parameter (`URLComponents`, the CoinGecko rule);
   - `classify(429) == .rateLimited`, `200 == .ok`, else `.serverError(code)`;
   - **the request sets no `User-Agent`** — `request.value(forHTTPHeaderField:
     "User-Agent") == nil`; the probe's load-bearing finding is that a browser
     UA earns a host-wide 8-minute ban while `URLSession`'s default sails
     through, so this is a test, not a comment.
2. **GREEN** — `HostStockSearchLoader` mirroring `HostCoinSearchLoader`
   (`URLComponents`, `timeoutInterval = 10`, transport → `.offline`,
   429 → `.rateLimited`, parse failure → `.badResponse`), reusing
   `CoinSearchFailure` + `CoinSearchOutcome` as-is. **No browser UA.**
3. Suite green (no new files, no xcodegen needed — unless a helper type was
   added, then regenerate).

**Verification.** The suite.

**Depends on.** P1.

## Phase 3 — `AddTickerSheet` searches both sources

**Goal.** One search field, grouped results; curated sections stay as the
offline empty state.

**Files.** `native/DeckApp/DeckApp.swift` (`AddTickerSheet`, ~line 2585).

**Steps.**
1. Split the sheet's state per source: `coinHits`/`stockHits`, two caches,
   two `lastRequest` stamps. The existing `hits`/`cache`/`lastRequest` become
   the coin half — the coin UX and constants are untouched.
2. `search()` runs both searches concurrently (`async let`), each guarded by
   `guard !Task.isCancelled` **before** assigning its own slice, so a slow
   source can never clobber a fast one (the `.task(id:)` cancellation trap).
   Each source keeps its own 2s floor (`CoinSearchPolicy.shouldSearch` with
   its own `lastRequest`), one shared debounce, one shared query key.
3. Results render grouped: `Section("Coins")` (existing row, `#rank`) and
   `Section("Stocks & ETFs")` — a stock row shows `exchange` in the leading
   slot (52pt, existing geometry) and `type` as the secondary text. A section
   with zero hits is omitted; both empty → the no-results message becomes
   `No coins or stocks match that.`.
4. Empty/`<2` query → the three curated sections exactly as today (the
   catalogue is the offline empty state — the brief's requirement). Search
   field placeholder becomes `Search coins & stocks`.
5. `Status` gains nothing new — `.busy`/`.offline`/`.failed` wording reused;
   a Yahoo 429 degrades this sheet only (the PRD's amber; the next keystroke
   is the retry, never a timer).

**Verification.** Debug build, then open the built app
(`native/build.noindex/Build/Products/Debug/Deck.app` — no LaunchServices
pollution from `.noindex`, quit it afterwards) and check the sheet:
- type `apple` → `Coins` empty, `Stocks & ETFs` shows AAPL, AAPX, APLE — no
  `SAAPL=F`; exchange + type visible;
- type `sp500` → the S&P 500 index row (`^GSPC`); pick it → appears in the
  ticker list, then prices on the next tick;
- clear the field → the curated Popular / Fiat & Gold / Stocks & Indices
  sections;
- pick a second `AAPL` → the out-loud duplicate refusal.

**Depends on.** P2.

## Honest scope notes

- The sheet's visuals can't be unit-tested (SwiftUI) — phase 3's manual check
  is the proof, per the coin-lookup precedent.
- The search's 429 ceiling with the app UA was **not found** (15 requests in
  8s all 200); the policy shape is kept because the measured worst case (the
  browser-UA ban) is host-wide and minutes-long — the loader is collateral.
- `scripts/demo-data.sh` needs no change: it sanitizes snapshots, and this
  work touches no snapshot shape.
